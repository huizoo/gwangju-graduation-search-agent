# 조사 기록 초기화

이 작업은 **학교 목록을 그대로 두고 시즌·일정·시간 찾기 결과·수기 입력·근거·조사 이력을 비웁니다.** 학교 ID, 학교 프로필과 직접 고친 학교 정보, 명부 출처·연결, `.env`와 설정은 유지합니다. 이전 조사와 수기는 현재 화면에서 사라지지만 전체 백업에 보존됩니다.

1. 앱 화면의 **프로그램 종료**를 누릅니다. 브라우저 창만 닫으면 서버가 남아 있을 수 있습니다.
2. 프로젝트 폴더에서 실행합니다.

   ```sh
   .venv/bin/python scripts/reset_research_data.py --confirm-reset
   ```

3. 출력의 `status`가 `completed`인지 확인하고 `start.command`를 다시 실행합니다.
4. 학교 목록이 있으면 새 시즌의 날짜 범위를 선택해 조사합니다. 목록이 비어 있으면 먼저 학교 목록을 불러옵니다.

초기화 직후 DB에는 시즌이 없습니다. 앱을 다시 실행하면 현재 설정의 기본 기간으로 **조사 기록이 없는 새 시즌**을 자동으로 만듭니다. 이는 이전 시즌 ID나 일정을 복구하는 동작이 아닙니다. 원하는 기간이 다르면 **새 시즌 조사**를 선택하세요.

현재 설정의 모드별 데이터 폴더만 대상으로 합니다. API나 모델을 호출하지 않습니다. 실행 중인 앱의 잠금을 얻지 못하면 중단하며 앱을 강제 종료하지 않습니다.

`data/live/backups/research-reset-날짜-고유값/`에 변경 전 전체 DB와 검증 영수증이 생깁니다. 기존 `exports/`의 일정표는 같은 백업 폴더로 옮겨 오래된 결과가 현재 일정표처럼 보이지 않게 합니다. 원문·근거는 전체 DB 백업에 포함됩니다. 기존 백업·개발 검증 보관 파일과 프로젝트 밖으로 내려받은 HTML은 그대로 둡니다. 별도로 내려받은 HTML은 이전 자료이므로 필요에 따라 직접 정리하세요.

백업은 SQLite 무결성·외래키와 테이블 내용 대조를 통과해야 합니다. 초기화 중 파일 이동이나 DB 검증에 실패하면 현재 DB의 삭제 거래와 파일 이동을 되돌립니다. 지원하지 않는 DB 구조나 심볼릭 링크는 자동 처리하지 않습니다. 백업 이름은 고유하며 기존 백업을 덮어쓰지 않습니다.

복구가 필요하면 앱을 종료하고 영수증의 백업 경로를 기준으로 복구해야 합니다. DB 백업만 덮어쓰면 과거 HTML 파일 경로와 맞지 않을 수 있으므로, 이 문서의 초기화 명령을 복구 명령으로 사용하지 마세요. 수기 내용이 포함된 백업과 영수증은 Git에 추가하거나 공유하지 않습니다.

초기화는 조사 기록을 비우는 기능입니다. 외부 사이트의 접속·자료 형식 문제를 해결하는 기능은 아닙니다. 격리 DB의 백업·복원·명부 보존·실행 중 차단 검사는 `tests/test_reset_research_data.py`에 있습니다.
