# 일정표 파일명 변경과 기존 HTML 정리

2026-10-21. 사용자 요청에 따라 프로젝트의 기존 일정표 HTML 9개를 삭제하고 이후 파일명을 `광주 졸업식 일정표 (2025.12.01~2026.03.31).html` 형식으로 통일했다.

## 적용 범위

- 자동 저장, 일정표 열기 응답, 파일 내려받기 모두 시즌의 시작일·종료일로 구성한 같은 한국어 파일명을 사용한다.
- 최신 파일은 `data/live/exports/`에 저장한다. 불변 버전은 `exports/versions/`의 고유 폴더 아래에 같은 이름으로 보관한다.
- 기존 `output/`의 HTML 4개와 `data/live/exports/`의 HTML 5개를 삭제했다. 삭제 후 사용자 산출물은 다시 생성하지 않았다. 다음 앱 실행부터 저장된 시즌을 새 이름으로 자동 생성한다.
- 실제 앱이 종료된 상태에서 인스턴스 잠금을 확보하고 내보내기 메타데이터만 재생성 대기로 바꿨다. 내보내기 외 모든 DB 테이블의 전후 해시가 같고 외래키 검사도 통과했다. 조사·수기·근거·설정·백업·개발 검증 기록과 인계 원본은 보존했다.
- 삭제 파일의 경로·크기·해시는 [정리 기록](../runtime/filename-update/cleanup.json)에 있다. 다른 폴더로 내려받은 복사본은 정리 대상이 아니다.

## 검증

- 저장·응답·파일명·자동 갱신·실패 복구 관련 pytest 28개 통과. 일반 기간과 윤년 날짜에서 정확한 이름, UTF-8 다운로드 헤더, 자동 저장과 응답 바이트 일치, 불변 버전 경로를 확인했다.
- 사용자 화면 관련 pytest 17개 통과. 서버 파일명을 사용하며 파일명이 누락되면 잘못된 이름으로 다운로드하지 않는다.
- 사용자 DB와 분리한 합성 자료로 실제 브라우저 검사 8개 통과. 실제 다운로드 이름과 저장 바이트, 일정표 열기, 서버 종료 후 동일 HTML 바이트의 20행 페이지·검색·날짜 결합을 확인했다. [브라우저 결과](../runtime/korean-filename-v5/browser-20261021-152319/result.json)
- 전용 브라우저 CLI는 `file://` 탐색을 차단하므로 파일 더블 클릭 동작은 이번 검사에서 확인하지 못했다. 서버 종료 후 검사는 다운로드한 동일 바이트를 허용된 `data:` URL로 열었다. 이를 `file://` 성공으로 계산하지 않았고 최초 차단 기록도 보존했다.
- 파일명 변경 검증에서 외부 API·모델 호출이나 실제 일정 재수집은 수행하지 않았다.
