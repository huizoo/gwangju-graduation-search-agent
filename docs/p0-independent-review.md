# P0 독립 구현 대조 검토

검토일: 2026-10-20. 기준은 `reference/handoff/04_codex_handoff.txt`, `06_acceptance.md`, `02_technical_design.md`, `contracts/README.md`의 4.0 사양이다. 이 문서는 구현 중간의 독립 검토 결과이며 최종 실연동 성과 집계가 아니다.

핵심 저장·수기·게시·작업·출력 경로와 주요 실패 반례는 구현되어 있다. 그러나 **모든 유형의 최신 전체 명부 확보, 모든 유형의 실제 일정 정확성, 구버전 DB 이관, 사용자 PC 검증까지 완료한 것으로 해석해서는 안 된다.** 코드와 임시 DB 검사, 다른 담당자가 남긴 실제 자료원·브라우저 증빙을 구분했다. 이번 검토는 실제 사용 DB·실행 중 프로세스·키를 읽거나 변경하지 않았다.

## 독립 재현으로 확인하고 수정된 항목

아래 항목은 발견 당시 실패 조건을 재현했고 현재 코드와 회귀 검사에 반영되어 있다. 원본 인계 파일은 변경하지 않았다.

1. **HTML 교체 후 DB 오류:** 이전 파일을 먼저 덮어쓰던 경로를 불변 새 파일과 DB 포인터 갱신으로 바꿨다. 임시 DB trigger로 UPDATE를 실패시켜 이전 파일 바이트 보존을 검사한다.
2. **결과 저장 실패 시 사용량 rollback:** 시간·미확인 예약 정산을 최종 결과 저장과 분리했다. 잘못된 첫 기관 결과는 실패로 남기고 다음 기관은 계속하며 사용량은 유지한다.
3. **운영 Host의 `testserver` 허용:** 실제 허용 목록에서 제거했다. 테스트도 loopback base URL을 사용한다.
4. **실행 중 전체 활성시간 초과:** 기관/구간 시간 외에 전체 잔여시간을 실행 기한에 포함하고 동시 기관의 선예약을 반영한다. 예약은 실제 비용 정산까지 다른 기관이 사용할 수 없다.
5. **화면과 다른 조사 대상 필터:** 원본 기관 열만 보던 필터를 수기 보정된 기관 프로필로 맞췄다.
6. **복수 행사 중 미확인 누락:** 한 기관에 판매 가능한 행사가 하나 있어도 다른 미해결 행사가 있으면 `missing_only`에 남긴다.
7. **다른 시즌의 과거 원문 재확인:** 현재 시즌의 관측·활성 수기 확인에서 참조하는 source_key만 골라 최신 버전을 다시 읽는다. 무관한 과거 시즌 오류를 현재 조사에 섞지 않는다.
8. **토큰 예약을 실제 사용량으로 정산하지 않음:** 확인된 사용량은 예약 차액을 돌려주고 초과량은 더한다. 0은 제공자가 명시한 실제 값일 때 허용된다. usage가 없는 응답은 0이나 예약분의 실제 계측값으로 바꾸지 않고 `charged_unknown`, `actual_json=null`, 잔여 `reserved_tokens`로 보존한다.
9. **보조 시즌 선택 API의 잘못된 입력 500:** null·정수·배열 형태의 ID를 임시 앱에서 재현했다. root가 구조·UUID 검사를 추가했고 현재 구조화된 422 응답 검사에 통과한다.
10. **운영 규칙 버전 변경 후 검사 오탐:** `tests/test_storage.py`와 `tests/test_publication.py`의 두 운영 활성화 부분은 `REGISTERED_RULES`의 현재 버전을 사용한다. 인계 참조 사례 전용 1.0.0 fixture는 의도적으로 유지한다.

활성시간의 의미는 **실제로 수행한 각 기관 실행시간의 초 단위 올림 합**이다. 구간 기한은 별도의 wall clock이다. 동시 실행 중에는 남은 기한 상한을 예약하고 정상 종료에서 실제 측정값으로 정산한다. crash로 실제 비용을 확인하지 못하면 예약분을 보수적으로 유지하며 재개 때 다시 더하지 않는다. asyncio 취소 전달·정리 시간과 초 단위 올림 때문에 측정된 최종 비용이 한도를 조금 넘을 수 있다. 이 경우 실제 값을 낮춰 보고하지 않고 이후 실행·재개를 제한한다.

## 이번 검사의 실행 증거

모두 가상 자료와 임시 DB를 사용했으며 외부 네트워크 성공이나 실제 일정 정확성을 측정하지 않는다.

```sh
.venv/bin/python -m pytest tests/test_storage.py tests/test_publication.py -q
# 15 passed in 0.62s

.venv/bin/python -m pytest tests/test_domain.py tests/test_manual.py tests/test_config.py tests/test_export.py tests/test_jobs_api.py tests/test_jobs_review.py -q
# 41 passed, 1 skipped in 2.27s

.venv/bin/python -m pytest tests/test_jobs_api.py::test_api_cursor_and_invalid_queries tests/test_jobs_review.py::test_known_token_usage_refunds_only_unused_reservation -q
# 2 passed in 0.39s — 마지막 두 수정 후 재실행
```

마지막 2건은 앞 검사에 포함되는 사례를 수정 후 다시 실행한 것이므로 별도 기능 2건으로 합산하지 않는다. skip은 `tests/test_jobs_review.py::test_occupied_port_fallback_requires_local_socket_permission` 하나다. 이 검사 환경의 localhost socket bind 권한 제한 때문에 실제 포트 점유를 만들 수 없었다. 포트 대체 구현 성공으로 간주하지 않으며, 잠금 파일의 중복 실행 방지는 별도 검사에 통과했다.

## 실제 증빙과 완료 판단의 구분

- `docs/evidence/spec-baseline.json`의 schema 96·example 35·publication 55·configuration 49는 사양 기준선이다. 실제 자료원 인증·일정 확보를 증명하지 않는다.
- `docs/evidence/browser-validation.json`은 전용 브라우저에서 실제 화면 입력, HTML 저장, 서버 종료 뒤 오프라인 파일 열기, 필터, XSS 비실행, 외부 자원 요청 0건을 확인한 증빙이다. 명시된 `actual_browser_with_demo_data`처럼 가상 전화 확인값을 썼으므로 실제 기관 일정의 정답 증거가 아니다.
- `docs/PROGRESS.md`에는 NEIS 학교 명부 335개와 학교 대표 조사 8곳의 1차 결과가 기록되어 있다. 당시 특수학교 과정별 행사 식별 문제로 재검증 중이라고 명시되어 있으므로 해당 중간 수치로 최종 정확성·판매 준비 건수를 확정하지 않는다.
- `docs/registry-coverage.md`와 `docs/evidence/non-school-registry.json`은 공식 비학교 명부 확보 증거다. 유치원 명부 256행은 관내 공식 명부 행수와 일치하나 원문 자료 기준일과 개별 운영상태가 미상이다. 대학 11·전문대학 7은 별도 캠퍼스 포괄 여부가 미검증이고 어린이집 250행은 일부 자료다. **9유형×5구의 최신 전체 목록 확보 완료로 합산할 수 없다.**
- 비학교 대표 10곳의 입력 파일은 정답 날짜·일정 URL이 없는 조사 입력을 준비했다는 증거다. 그것만으로 실제 10개 기관의 조사나 일정 정확성을 검증한 것으로 계산하지 않는다. 본 독립 검토는 해당 파일을 실제 사용 DB에 적재하거나 조사하지 않았다.

## 남은 인계 항목

1. 구버전 DB를 지원해야 한다면 실제 이전 스키마 fixture와 이관 요구를 확보하고, 사전 백업·기록 보존·증명 없는 자동값 보류·구정책 HTML 격리 검사를 포함한 migration을 구현한다.
2. 어린이집 전체 명부와 대학의 지역 캠퍼스 범위를 공식 자료로 더 대조한다. 기관 유형별 범위·기준일·미확보와 전체성 불명확을 유지한다. 파일 import의 형식 통과만으로 공식 홈페이지 관계를 승인하지 않는다.
3. 실제 앱에 연결된 자료원을 이용한 대표 기관 결과를 확정한다. 정답 날짜·URL 없는 탐색과 seeded 검사를 분리하고, 원문 hash·읽기 범위·사람이 대조한 날짜/시간 기대값을 남긴다. 실제 현재 날짜·시간 허용 기관수와 추가 전화 확인 필요 수를 각각 보고한다.
4. 실제 launcher에서 중복 실행·포트 점유·멈춤/취소 후 강제 재시작·꺼져 있던 시간 미과금·late response 거절을 검증한다. 임시 상태 복구 검사를 프로세스 실검증으로 대신하지 않는다.
5. 실제 사용할 PC와 어머니의 기록으로 입력→재조사→새로고침→재시작→HTML 보관을 확인한다. Windows 실행파일은 P2이며 이번 P0 개발 완료에 포함하지 않는다.

이 문서 이후 root가 추가한 실연동·프로세스 증빙은 최종 진행 기록과 완료 보고에서 별도로 참조한다. 여기의 중간 수치와 미검증 항목은 최종 결과를 덮어쓰는 근거로 사용하지 않는다.

## 최종 검토

2026-10-20 최종 대조는 인계 README·`04_codex_handoff.txt`·P0 검증 기준과 당시 최신 코드·검사를 읽어 수행했다. 앞 절의 중간 상태 중 실제 프로세스 검증, 아래 NEIS 재확인과 A04 변경 공지 항목은 이 절의 결과로 갱신한다. 전체 검사 수와 실제 기관별 최종 성과는 별도의 [최종 검증 기록](VALIDATION.md)을 사용한다.

### 핵심 결함 발견과 해소

추가로 발견한 핵심 결함은 **NEIS의 실제 재조회 실패가 저장된 NEIS 근거의 현재 사용 허용에 반영되지 않는 경로**였다. 실제 `NeisProvider.calendar`는 실패를 `coverage.calendar.status=provider_error`로 전달하고 문서 배열은 비운다. 기존 저장 경로는 이 조회 범위 상태를 읽지 않았으므로, 과거 날짜는 유지해야 하지만 현재 사용은 보류해야 하는 A12를 위반했다. 임시 DB에서 NEIS 날짜를 채택한 뒤 같은 기관·시즌의 실패 결과를 저장했을 때 `current_date_allowed=true`, 재확인 `not_attempted`가 유지되는 것을 재현했다.

root는 `app/storage.py:_apply_calendar_recheck`와 `save_research`, `app/research.py:initial_collect`를 수정했다. 실제 조회 시각을 checkpoint마다 유지하고, 실패 또는 완전한 조회에서 해당 행사 행이 사라진 경우 그 기관·시즌의 NEIS 지원 문서에만 실패를 반영한다. 과거 확인값과 확인시점은 보존하고 현재 사용만 보류한다. 미발견을 취소·폐교로 확정하지 않으며, 키 미설정·보조 검색 실패·미시도는 이 분기에 넣지 않는다.

독립 작성한 `tests/test_neis_recheck.py`는 실제 NEIS Adapter와 HTTP Gateway의 **격리 HTTP 응답**을 서비스 저장과 Publication까지 연결한다. 다음 8건이 최신 수정 후 통과했다.

- 실제 API 재조회 실패 시 일반 날짜·확인시점 보존 및 현재 사용 보류.
- 실패 후 동일한 행을 성공적으로 다시 읽었을 때 정상 회복.
- 키 미설정과 보조 검색 실패가 정상 NEIS 근거에 전파되지 않음.
- 전체 응답에서 일부 행사 행만 빠진 경우 그 행사만 보류.
- 성공한 전체 응답이 자료 없음일 때 과거값을 현재 재확인값으로 취급하지 않음.
- 같은 기관의 다른 시즌 근거에 실패를 전파하지 않음.
- 같은 행사 날짜 변경을 새 행사로 숨기지 않고 충돌로 보존.

```sh
.venv/bin/python -m pytest tests/test_neis_recheck.py -q
# 8 passed in 0.33s
```

위 목록의 키 미설정·보조 검색은 각각 독립 매개변수 사례다. 이 검사는 실제 외부 API 장애를 발생시킨 시험이나 실제 일정 정답 검증이 아니다. 실패 전파 정책의 회귀 증거이며, 기준을 완화하거나 실제값을 가상값으로 바꿔 통과시킨 것이 아니다.

### 후속 대조에서 발견한 A04 누락과 보완

첫 최종 검토 뒤에 **명시적 변경 공지의 검증된 대체 관계를 저장·적용하는 연결이 없다는 기능 누락**을 추가로 확인했다. 당시 구현은 두 날짜를 충돌로 보존하므로 임의 변경을 막았지만, A04의 “검증된 대체 관계는 이력 남기고 갱신”을 수행하지 못했다. 이 상태를 지원하지 않는 문법의 한계로만 분류하고 A04 완료로 보고할 수 없다는 판단을 root에 전달했다. 앞선 “추가 blocker 미발견” 판단은 이 후속 발견으로 수정한다.

현재 `app/rules.py`의 `academic_calendar_row@1.0.0`은 학년도·학부/대학원·행사 회차가 명시되고 `(변경전) YYYY.M.D(요일) → (변경후) YYYY.M.D(요일)` 행이 붙은 좁은 학사력 문법을 지원한다. 날짜의 유효성·시즌 범위와 원문을 검사하며 시각은 만들지 않는다. `supersession_edges`는 공식성·값 검증을 통과한 같은 기관·시즌·행사·회차·대상의 관측끼리만 이전값과 새값을 연결하고 순환 관계를 제외한다. 단순히 문서가 더 늦다는 이유로 기존값을 대체하지 않는다.

`app/storage.py:_reassess`는 검증된 관계의 이전 관측을 **해당 필드의 현재 자동 평가에서만 제외**하고 `audit_log`에 원문 문서·관측·규칙 버전을 중복 없이 기록한다. 원래 문서와 관측은 삭제하거나 기각하지 않는다. 다른 필드가 여전히 사용하는 관측은 채택 상태를 유지할 수 있다. 다음 평가에서도 현재 원문으로 관계를 다시 검사하므로, 변경 관측을 기각한 뒤 과거 감사 이력만으로 계속 대체하지 않는다. 수기 지정은 유지하며 이전 날짜에 묶인 시작 시각을 새 날짜에 붙이지 않는다.

검증 증거는 다음 두 종류로 구분한다.

- [변경 공지 규칙 증거](evidence/calendar-change-rule.json)의 `tests/test_calendar_change.py` **25건**은 실제 캡처 사례 7건과 별도 합성 문법 사례 18건이다. 서강대의 과거 2025학년도 원문에서 2026-02-23 → 2026-02-20을 추출했고 시작 시각은 null로 남겼다. 원래 `authority=unverified`와 공식 관계 증명 부재를 유지한 채 ValueCheck 거절·Publication 보류를 확인했다. 다른 표 문법, 학년도·대상·회차 누락, 기간 밖 날짜와 게시 시각을 다룬 반례도 포함한다.
- `tests/test_change_storage.py` **8건**은 임시 SQLite와 별도 합성 공식 원문을 사용한 저장·게시 연결 검사다. 연속된 두 변경 공지의 날짜 갱신, 관측·감사 이력 보존, 반복 평가 중복 방지, 관계없는 공지의 충돌 유지, 수기 날짜·시각 보호, 변경 관측 기각 후 재평가, 순환 관계, 다른 회차·대상의 행사 분리를 확인했다. 이 8건은 관련 저장·게시·수기·NEIS 회귀 검사와 함께 통과했으며 전체 검사 수에 별도로 더하지 않는다.

따라서 **A04의 좁은 검증 규칙과 저장 연결은 구현·회귀 검증되어 있다.** 다만 실제 캡처는 광주 밖 과거 자료이고 운영 DB에 적재하지 않았다. 실제 공식 채널 관계가 확인된 두 원문을 수집하여 현재 광주 일정이 자동 대체되는 전체 경로를 검증한 결과는 아니다. `academic_calendar_row`라는 규칙 이름도 모든 학사력 표나 모든 변경 문법을 지원한다는 뜻이 아니다.

### 문서화하고 남겨야 할 한계

- 구버전 DB 이관은 미구현이다. 시작 시 기존 DB가 없었던 신규 4.0 프로젝트이므로 이번 신규 사용의 blocker는 아니지만, 이전 DB를 제공받는 즉시 별도 이관 작업이 필요하다. 자동 복원 UI도 없다.
- 모든 유형×5구의 최신 전체 명부 확보는 별도 미완료 항목이다. 일반 파일의 계약 검사와 서버가 검토한 공식 관계를 구분하며, 부분 명부를 전체 완료로 보고하지 않는다.
- 현재 시즌의 실제 시작 시각이 공개되지 않거나 확인되지 않은 기관은 판매 준비 목록에 들어가지 않는다. 이 상태는 미공개 정보를 추측해서 해결할 수 없으며 전화·문서 직접 확인이 남는다. 과거 시즌의 정상 날짜+시간 양성을 올해 자동 발견 성과로 계산하지 않는다.
- 변경 공지는 위의 명시적 학사력 날짜 변경 문법만 자동 대체한다. 시간·장소 변경, 다른 표·문장 형식, 공식 관계가 확인되지 않은 원문은 추가 규칙과 실제 양성·반례 검증이 필요하다. 광주의 실제 공식 변경 공지 전체 경로는 미검증이다.
- 현재 기관별 일반 원문 재확인은 저장한 관련 source 중 우선 최대 3개를 읽고, 전체 탐색도 문서·검색·시간 예산을 따른다(`app/research.py:initial_collect`, `read`). 한 번의 recheck가 모든 저장 원문을 전수 재검증했다는 의미는 아니다. 실제로 시도하지 않은 경로를 성공이나 실패로 새로 표시하지 않는다.
- HTML은 생성 당시 결과다. 열어보는 것만으로 재확인되거나 갱신되지 않는다. 인터넷 없이 열리는 기능과 최신 일정 보장은 별개다.
- 브라우저 실행이 필요한 사이트·이미지/OCR·HWP·모든 PDF 표 해석·외부 tracing·Windows 실행파일·예약 운영은 현재 지원 범위 밖이다. 인계에서 P0 필수 경로로 먼저 요구하지 않은 확장 기능을 이번 완료 조건에 끼워 넣지 않는다.
- 실제 어머니의 PC와 사용 경험은 개발 PC의 자동·브라우저·프로세스 증거와 구분한다. 필요한 키·선택 모델·환경 준비는 최종 실행 안내에 남겨야 한다.

최종 보고는 P0 기능, 개별 자료원 실연동, 실제 일정 확인, 전체 명부 확보를 각각 구분해야 한다. 남은 한계가 있다는 이유로 확인한 근거를 숨기지 않고, 검사 통과만으로 미확보 사실을 완료로 표현하지 않는다.
