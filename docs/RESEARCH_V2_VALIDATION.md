## 실제 브라우저·독립 HTML

`scripts/verify_ui_v2.py`와 `runtime/improvements-20261021/browser-115549/result.json`에서 **20개 검사 모두 통과**했다. `browser-verification`의 전용 Chromium 세션을 사용했고 사용자 브라우저를 연결하거나 종료하지 않았다.

- 실제 자료 사본: 대상 339개, 공식 홈페이지 337개, 건국초 2027-01-06·188명과 공란 시각, 다섯 열을 확인했다.
- 앱에서 합성 전화 확인 문장을 입력해 **기존 행사 UUID**에 10:00을 보완했다. 인원·학교 주소는 유지했다. 이 10:00은 기능 검사 입력이며 실제 일정 성과나 배포 HTML에 포함하지 않는다.
- 행의 시간 찾기 요청은 정확한 학교·시즌·행사에 연결했다. 검색·구 필터가 적용된 상태에서 일정찾기를 눌러 전체 339개가 작업 대상이 됨을 확인했다. 브라우저 작업 실행기는 외부 호출 없는 격리 실행기이며 이 부분을 실제 자료 수집으로 계산하지 않는다.
- 별도 사본의 합성 45개 기관으로 세 필터의 AND 조건, 26건의 20/6 페이지 이동, 조건 변경 시 첫 페이지, 빈 결과, 복수 행사일 각각의 일치, 날짜 색의 일관성을 검사했다.
- 앱과 HTML 모두 인쇄 모드에서 필터된 26개 행을 **2페이지 PDF**에 전부 출력했다. 버튼·입력창·페이지 조작은 숨기고 시간 찾기 칸은 비웠다. 날짜 그룹 경계선도 확인했다.
- 390px 화면에서 가로 넘침 없이 읽을 수 있었다. 데스크톱·모바일·인쇄 스크린샷을 직접 확인했다.
- 검증 서버 두 개를 종료한 뒤 **같은 HTML 바이트**를 data URL로 열어 검색·필터·페이지·인쇄와 외부 리소스 요청 0건을 확인했다. 자동화 도구가 `file://`를 차단하므로 OS에서 파일을 더블 클릭하는 동작은 이번 자동화로 검증하지 않았다.
- 전용 helper 종료 상태 `FINISHED`, 정리 방식 `exact-close`, 잔여 프로세스 0과 자체 서버 종료를 확인했다.

저장 예제 [graduation-schedule-2026.html](../output/graduation-schedule-2026.html)은 실제 자료와 최종 모델 작업 사본의 근거를 새 검증 사본에서 다시 검증해 합친 결과다. 339개 대상과 건국초 날짜·188명, 광주대학교 날짜를 포함한다. 합성 학교나 합성 전화 확인값은 들어 있지 않다. 원본 사용자 DB에는 검증 데이터를 쓰지 않았다. 통합 기록은 `runtime/improvements-20261021/final-result/20261021T032108853636Z/result.json`, 재현 스크립트는 `scripts/build_verified_result_v2.py`다.

## 한계와 사용자 준비

- 전체 명부 339개는 조사 대상의 수다. 모든 학교의 현재 날짜·인원·시간을 확보한 수가 아니다. 이번 검증은 실제 정상 사례와 실패 방어를 확인하며 전체 학교 전수 실조사를 대신하지 않는다.
- 작은 로컬 모델은 원문에 없는 값을 제안하거나 찾을 수 있는 자료를 놓칠 수 있다. 독립 검증은 명확하게 지원하는 관계만 승인하며 모든 자연어 의미 오류나 발견률을 보장하지 않는다.
- 실제 모델 검증은 선택된 Ollama만 수행했다. OpenAI는 계약·합성 회귀를 검사했으며 실제 API로 실행하지 않았다. 광주대학교 날짜 게시에는 성공했지만 해당 작업의 인원 조사까지 완료하지 못했다.
- 공개 자료가 없거나 읽기에 실패한 경우 값을 추정하지 않는다. 이미지·HWP/OCR, 로그인·접근 차단 자료는 자동 수집하지 못할 수 있다.
- 시간 탐색은 현재 날짜와 단일 행사가 확인된 행에서 실행한다. 대학 인원은 같은 대표 행사와 연결되지 않으면 공란이다.
- 기존 설정과 키는 보존했다. 사용자에게서 추가받은 `SCHOOLINFO_API_KEY`의 실제 호출을 확인했다. `.env` 변경은 앱 재시작 후 적용된다.
- 구조 확장 전에 자동 백업한다. 이전 조사 계약의 중단 작업은 이력으로 남기고 새 조사로 시작한다. 비밀값·DB·개인 기록·런타임 증빙은 Git에 넣지 않는다.
- 저장 HTML은 저장 시점의 사본이다. 앱에서 새 조사·직접 기록을 한 뒤 다시 저장해야 갱신된다.
- 브라우저의 인쇄 미디어와 PDF를 확인했다. OS 파일 더블 클릭과 실제 종이 출력은 직접 검증하지 않았다.
