# 일정표 출력 규칙

이 문서는 화면과 HTML에 어떤 값을 제공할 수 있는지 정한다. 내부 근거·게시 검증을 통과한 필드만 사용한다. `/api/results?season_id=…`와 저장 HTML은 `app/web/results.py`의 같은 현재 허용 결과를 사용한다.

## 사용자 시즌과 자료 학년도

- 사용자 시즌은 **찾을 졸업식의 실제 날짜 범위**다. 시작일·종료일을 모두 포함하며, 실행 기간이나 표의 하루 날짜 필터와 다르다.
- 새 시즌은 시작일·종료일만 받는다. 기간으로 이름과 내보내기 이름을 구성하고, 같은 기간을 다시 요청하면 기존 시즌 ID를 사용한다.
- 종료일은 시작일보다 빠를 수 없다. 시작일에 달력상 6개월을 더하고 말일을 보정한 날짜부터 종료일로 선택할 수 없다. 예를 들어 2023-08-31의 마지막 허용 종료일은 2024-02-28이며 2024-02-29는 허용하지 않는다. 프론트엔드와 백엔드가 같은 규칙을 검사한다.
- 기존 시즌 갱신은 같은 ID·기간·기록을 유지한다. 기간을 바꾸려면 새 시즌으로 조사한다. 실행 중이거나 멈춘 작업의 고정 기간을 수정하지 않는다.
- 사용자 시즌과 자료의 학년도는 별개다. 초·중·고의 NEIS는 실제 날짜 범위로 조회해 각 원문 학년도를 보존하고, 인원은 확인된 행사 학년도의 6학년 또는 3학년 자료를 조회해 연결한다. 3월 경계 이후로 연기됐다는 이유로 원문 학년도를 다른 값으로 바꾸지 않는다. 대학의 학년도·전기/후기·행사 회차는 원문 문맥으로 확인하며 날짜만으로 정하지 않는다.
- 겹치는 시즌에서 동일한 실제 행사를 다시 표시할 수 있지만 행사·수기 기록을 시즌마다 복제하지 않는다. 서로 다른 학년도·회차·전기/후기의 실제 행사는 구분하고 같은 행사의 날짜 충돌은 별도 행사로 숨기지 않는다.

## 범위와 값

- 대상은 공식 목록에 등록된 광주 초등학교·중학교·고등학교·대학교·전문대학이다. 기본 날짜·인원 조사와 표의 표시 필터는 별개다. 구·학교명·하루 날짜·현재 페이지가 기본 전체 조사 범위를 바꾸지 않는다.
- 날짜·시간은 내부 Publication의 `current_allowed`를 만족하는 값만 제공한다. 과거 `general_visible`이나 `sales_ready`는 사용자 표시 권한이 아니다.
- 복수일 행사는 현재 허용 날짜와 선택 시즌의 포함 범위가 겹치는 날짜만 `dates`에 제공한다. `date`는 이 교집합의 첫 날짜다. 범위 밖 날짜를 표시하거나 그 날짜에만 연결된 시간을 범위 안 날짜로 옮기지 않는다.
- 인원은 해당 행사 학년도의 초등 6학년 또는 중고등 3학년 재학생 수, 대학의 해당 대표 본식 졸업자 수다. 근거를 다시 검사하고 유효한 서로 다른 값이 충돌하면 공란으로 둔다. 확인된 0명은 0으로 표시한다.
- 정상 날짜는 시간·인원이 보류돼도 유지한다. 날짜가 바뀌면 이전 날짜에 연결한 시간을 자동으로 옮기지 않는다.
- 현재 확인된 취소·미실시는 학교명 옆에 짧게 표시하고 정상 일정처럼 날짜·시간을 제공하지 않는다. 연기로 개최 일정이 불확실하면 기존 날짜·시간을 보류한다.
- 학교·캠퍼스의 대표 행사가 실제로 다르면 별도 행을 유지한다. 같은 대표 행사의 학부·대학원 대상 표기만으로 행을 나누지 않는다.
- 주소는 공식 명부에서 확인한 학교·캠퍼스 주소다. 장소 메모를 주소로 대체하지 않으며 확인 근거가 없는 프로필 수정 주소는 제공하지 않는다.
- 학교명 링크는 **확인된 공식 홈페이지만** 사용한다. 공지 원문이나 API·XML·JSON 주소를 대신 연결하지 않는다. 홈페이지가 없으면 일반 텍스트다.
- 원문 근거·정책·확인시점·인원 기준·수정 이력은 내부 DB에 남긴다. 사용자 결과에 사적 메모나 검증 상세를 싣지 않는다.

## API와 행 구조

`/api/results`는 `presentation_version: "3.0"`, `season_id`, `request_job_id`, `active_job_id`, `rows`를 반환한다. `active_job_id`는 다른 시즌의 작업도 포함한 현재 활성 작업 ID이며, 동시 실행 제한을 화면에 반영하는 데 사용한다.

| 행 필드 | 의미 |
| --- | --- |
| `institution_id`, `event_ids` | 정확한 학교·행사 연결. 시간 조사는 단일 현재 행사 UUID가 필요하다 |
| `name`, `event_label` | 학교명과 실제 구분이 필요한 행사 설명 |
| `date` | 현재 시즌 범위에서 허용한 첫 행사일. 미확인 `null` |
| `dates` | 같은 본식의 현재 허용 날짜와 시즌 범위의 교집합. 공란일 때 빈 배열 |
| `start_time` | 현재 표시 날짜에 연결된 실제 본식 시작 시각. 미확인 `null` |
| `graduation_count` | 현재 허용 정수 인원. 미확인 `null` |
| `address`, `district` | 확인한 학교 주소와 표시용 구 |
| `url` | 공식 홈페이지 또는 `null` |
| `status` | 현재 확인한 취소·미실시 또는 `null` |
| `time_search` | 해당 시즌·단일 행사에 대한 최신 시간 조사 상태 또는 `null` |

`time_search`는 `job_id`, `status`, `outcome`, `paused_reason`, `revision`, `created_at`, `feedback`을 포함한다. `feedback`은 미발견(`not_found`), 자료 접근·읽기 실패(`source_unavailable`), 서비스 오류(`service_error`), 미완료(`incomplete`) 또는 `null`이다. 마지막 저장 실행의 구조화된 오류를 사용하며, 오래된 실패를 성공한 재조사에 덧씌우지 않는다. 최근 작업 목록의 페이지에 없는 과거 작업도 결과 투영에서 복원한다. 현재 활성 작업이 최근 100건 밖에 있으면 앱은 `/api/status`의 ID로 해당 작업을 따로 읽는다.

표의 열 순서는 **날짜 | 학교명 | 시간 | 졸업인원수 | 장소**다. 값이 없으면 `미확인` 문구 대신 해당 칸을 비운다. 앱의 시간 조사 조작·안내만 해당 시간 칸에 표시한다.

## 앱의 시간 조사 상태

- 시간 찾기는 표시 중인 시즌 ID·학교 ID·단일 대상 행사 ID에 연결한다. 행사나 날짜를 먼저 확인해야 하면 조사 요청을 보내지 않는다.
- 요청을 보내는 동안은 해당 칸에 `요청 중…`을 표시한다. 서버가 작업을 수락한 뒤에는 HTTP 요청 완료 여부가 아니라 저장된 작업 상태로 `찾기 준비 중…`, `찾는 중…` 등을 표시한다.
- 중간 저장으로 API의 `start_time`이 생겨도 작업이 `queued`, `running`, `pausing`, `cancelling`, `paused`이면 행의 조사 상태를 우선 표시한다. 실제 작업이 완료되고 현재 허용 시간이 있으면 그 시간으로 교체한다. 종료된 실패·취소 작업은 이후에 직접 확인한 현재 허용 시간을 가리지 않는다.
- 미발견은 `이번 조사에서 시간을 찾지 못했어요.`로 알린다. 자료 접근 실패는 `일부 자료를 읽지 못했어요.`, 서비스 오류는 `조사 중 오류가 났어요.`, 미완료는 `찾기를 마치지 못했어요.`로 구분한다. 이를 시간이 공개되지 않았다는 뜻으로 단정하지 않는다. 실패·일시정지·취소·요청 실패도 같은 칸에서 짧게 알린다. 재개 가능한 일시정지는 이어서 찾기, 설정 변경 등으로 재개할 수 없는 작업은 새 조사로 연결한다.
- 해당 행의 중복 요청을 막고 동시 실행 제한을 지킨다. 다른 학교는 버튼만 비활성화하며 조사 중 표시를 붙이지 않는다.
- 폴링·표 갱신·페이지 이동·브라우저 새로고침 후에도 같은 시즌·행사의 상태를 복원한다. 상태가 변하지 않은 버튼은 다시 만들지 않아 폴링으로 키보드 포커스를 잃지 않게 한다.
- 사용 가능한 버튼은 일반·주요 버튼별 hover와 클릭 색을 제공한다. 키보드 포커스와 비활성 상태를 구별한다.

## 필터·페이지·날짜 색상

학교명 검색, 구 선택, 하루 날짜 선택을 독립 입력으로 제공하고 세 조건을 AND로 적용한다. 날짜는 `dates` 중 하나라도 선택일과 같으면 일치한다. 조건을 바꾸거나 전체 보기를 누르면 첫 페이지로 이동한다. 날짜·시간순으로 정렬하고 날짜 공란을 마지막에 둔다. 필터 결과를 화면에서 20행씩 표시한다.

날짜 문자열 해시를 색상에 사용하지 않는다. **날짜순으로 정렬된 현재 필터 전체 결과**에서 날짜 그룹이 바뀔 때마다 차분한 여섯 색 중 다음 색을 사용한다. 색을 먼저 배정한 뒤 페이지를 나누므로 같은 날짜가 페이지 경계에 걸려도 같은 색이며 바로 다음 날짜 그룹은 다른 색이다. 필터가 바뀌면 색이 다시 배정될 수 있다. 복수 날짜 행은 현재 표시하는 첫 행사일로 그룹을 정하고 날짜 공란은 별도 흰색으로 둔다. 앱과 새 저장 HTML은 같은 스크립트를 사용한다.

## 인쇄와 독립 HTML

인쇄는 **현재 필터를 통과한 전체 행**을 대상으로 한다. 페이지 때문에 숨긴 행은 인쇄 때 다시 보이고, 필터에서 제외한 행은 인쇄하지 않는다. 표 외 제목·검색창·버튼·페이지 조작을 숨긴다. 날짜 그룹의 흑백 경계선은 유지한다.

앱의 시간 찾기 버튼과 진행·결과 안내 전체를 인쇄에서 숨기고 해당 칸을 공란으로 둔다. 중간 시간이 저장됐더라도 화면에 조사 상태가 표시되는 동안에는 인쇄 칸도 공란이다. 정상적으로 표시한 확인 시간은 인쇄한다.

저장 HTML은 저장 시점에 현재 허용된 일정 값만 포함한다. 서버에 연결하는 조사·재개·직접 입력 기능과 작업 상태 UI를 넣지 않는다. 필요한 CSS·JS를 내장해 프로그램과 인터넷 없이 검색·필터·페이지 이동·인쇄를 수행한다. 학교 홈페이지 링크를 열 때만 인터넷이 필요하다.

파일명은 `광주 졸업식 일정표 (YYYY.MM.DD~YYYY.MM.DD).html`이며 시즌의 시작일·종료일을 포함한다. 앱이 실행 중이면 DB 변경을 감지해 `data/live/exports/`의 해당 파일을 자동 갱신한다. 불변 버전은 `exports/versions/r{revision}-{고유값}/` 아래에 같은 파일명으로 보존한다. 자동 저장·HTTP 응답·`ExportResult.filename`은 서버의 공통 함수로 이름을 구성하며, 내려받기 화면은 이 값을 그대로 사용한다. 다른 곳에 내려받은 복사본과 이미 열어 둔 HTML 화면은 저절로 갱신되지 않는다.

## 내보내기 버전

`<meta name="schedule-presentation" content="3.0">` 표식으로 현재 파일을 식별한다. 이전 HTML 파일은 보존하지만 현재 결과 URL에서 그대로 재사용하지 않는다. 불신 텍스트와 URL 속성을 이스케이프하고 CSP 해시로 내장 코드만 실행한다.

## 개발 검증과 사용자 조사 분리

GIST 고정 URL 개발 검증의 시즌·관측·원문·판정·이력은 전체 DB 백업과 별도 원본 보관 후 운영 테이블에서 분리한다. 정확한 과거 식별자와 원문 출처를 대조한 기록만 처리한다. 같은 행사에 일반 조사나 수기가 섞였으면 독립 기록을 보존하고 검증 근거만 분리해 재평가한다. 일반 시즌 생성·겹친 기간·HTML·조사 실적에 검증값을 재사용하지 않는다. 이후 일반 조사에서 다시 수집한 근거는 공통 검증을 거쳐 표시할 수 있다. 신규 개발 검증은 사용자 DB를 사용하지 않는다.

## 간단한 앱 안내와 자동 파일 저장

- 앱 시작·학교 목록 갱신은 시즌을 생성하지 않는다. `/api/bootstrap`은 시즌이 없으면 `seasons: []`, `selected_season_id: null`을 반환하며 앱은 새 조사 기간 입력을 보여 준다. 사용자가 기간을 선택해 조사를 시작해야 시즌을 만든다.
- `/api/status.eligible_institution_count`는 시즌 선택 없이도 명부의 조사 대상 학교 수를 제공한다. `/api/results.eligible_institution_count`는 선택한 시즌의 조사 대상 학교 수이며 두 값 모두 화면 필터와 무관하다. 시즌이 없는 화면은 status로 명부 준비 여부를 확인한다. 대상 수가 0이면 학교 목록 불러오기 안내와 버튼을 표시하고 시즌 조사 버튼을 비활성화한다. 명부 갱신 뒤 폴링으로 준비 상태를 갱신한다.
- 서버도 명부 없는 일정 조사 요청을 `roster_required`(422), 해당 시즌·조건의 대상 학교가 없는 요청을 `no_eligible_schools`(422)로 거절하며 작업을 만들지 않는다. 명부 조회 작업은 학교 목록이 없어도 시작할 수 있다. 명부 확보를 졸업식 조사 완료로 표시하지 않는다.
- `research_summary`의 `state`, `message`는 현재 명부 전체에 대한 일반 날짜·인원 조사 이력을 요약한다. 선택 학교·시간·명부 조회를 전체 조사 완료로 세지 않는다. 작업 완료와 모든 일정 확인을 구분한다. HTML에는 이 관리 안내를 넣지 않는다.
- `/api/status?season_id=…`와 `/api/results`의 `html_save`는 자동 파일 저장 상태(`pending`, `current`, `failed`)와 실패 안내를 제공한다. 기록 저장과 HTML 생성 실패를 구분한다. 마지막 정상 파일과 사용자 DB를 보존하고 재시도한다.
- 새로 보기와 중복 기간 안내를 제거하고 내용 revision 변경을 폴링해 다른 창의 저장도 반영한다. 일정표 열기·파일 내려받기는 현재 파일의 생성을 확인한 뒤 제공한다.
- 접힌 관리에는 기록 백업과 학교 목록 갱신을 둔다. 프로그램 종료는 조사를 일시정지하고 HTML 저장을 마무리한다. `/api/app/shutdown`은 `accepted`, `paused_active_job`을 반환한다. HTML 저장 실패 시 503을 반환하고 앱을 유지한다. 입력창에만 남은 문장을 확인된 사실로 자동 저장하지 않는다.
- `reset-research.command`는 백업 후 시즌·기간·현재 선택과 모든 조사·직접 기록을 비우고 학교 명부·설정을 보존한다. 재시작만으로 시즌이나 일정표를 복원하지 않는다. 명령줄에서 명시한 `--keep-seasons`는 기간·선택만 유지하며 조사·직접 기록은 동일하게 비운다.
