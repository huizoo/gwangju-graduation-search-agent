# 2026-10-20 사용자 요청에 따른 개선

원본 `reference/handoff`는 보존한다. 이번 요청이 이전 화면·HTML 요구보다 우선한다.

## 구현 단위

1. 실제 저장 경로의 행사·기관·시각 관계, 별도 공지의 취소, 자료원 간 행사 연결, 조사 재개 경합을 회귀 검사하고 수정한다.
2. 현재 허용 필드와 조사 대상 기관으로 구성한 단일 결과 계약을 만든다. 학교 주소·공식 읽기 페이지·미확인·취소 표시를 적용하고 독립 HTML의 검색·날짜·20개 페이지를 구현한다.
3. 원문과 대화 이력을 보존하는 자연어 기록을 구현한다. 확인 진술과 조사 요청·추측을 구분하고 기존 행사를 보완한다. 앱은 조사·기록·결과 중심으로 정리한다.
4. 격리 DB에서 정상·반례 및 실제 브라우저를 검사한다. 실제 저장 원문과 현재 결과를 재대조하고 HTML을 생성한다. 검증 범위와 한계를 기록한다.

## 보존과 검증 원칙

- 기존 SQLite·수기·근거를 지우지 않는다. 데이터 구조 확장은 변경 전 SQLite backup을 만들고 원자적으로 적용한다.
- 비밀값·기존 백엔드 선택·외부 전송 경계는 유지한다. 자연어 수기 내용은 외부 모델로 전송하지 않는다.
- 내부 이력에서 과거 확인값을 유지해도 사용자 결과는 현재 허용된 필드만 제공한다.
- 행사일이 다르다는 이유로 다른 행사로 나누지 않는다. 반대로 과정·회차·캠퍼스가 다른 행사를 날짜만으로 합치지 않는다.
- 합성 회귀 검사는 실제 서비스나 실제 일정 정확성 검사로 보고하지 않는다.

## 진행

- 적용 지침, 깨끗한 Git 상태, 현재 구현·계약, 독립 검토의 R1–R6을 확인했다.
- 첫 단위: 기존 코드에서 새 회귀 9개 모두 실패했다. 수정 후 전체 232개 통과, sandbox의 loopback 제한 검사 1개 건너뜀. 특수학교의 실제 별도 과정, 정상 본식 시각, 다른 기관·학년도·부대행사의 취소 반례도 포함한다.
- 기관·대상·캠퍼스·명시 회차로 연결하며 자료원 URL과 행사일은 행사 구분 키로 사용하지 않는다. 모호하게 여러 행사와 연결되면 새 행사를 더 만들지 않고 연결 검토로 남긴다.
- 규칙 버전을 1.2.0으로 올렸다. 기존 1.1.0 증명은 자동 승인하지 않는다. 저장 원문의 재검증과 현재 출력 재생성은 후속 단위에서 진행한다.
- 두 번째 단위: 현재 허용 필드만 제공하는 표현 계약 1.0, 4열 HTML, 독립 검색·하루/기간·20개 페이지를 구현했다. 전체 236개 통과, loopback 1개 별도 확인 예정.
- 세 번째 단위: 자연어 원문·정규값·확인 표현·후속 질문을 로컬 DB에 보존한다. 기존 행사 갱신, 부분 저장, 추측/조사 구분, 충돌 재확인과 앱 단순화를 구현했다. 기존 자료 복사본에서 백업과 중복 5쌍의 이력 보존을 확인했다.
- 실제 복사본 결과: 13기관, 17행, 날짜 10건, 시작 시각 0건, 학교 주소·공식 링크 17건. 과거의 미분리 generic 후보를 별도 행사로 더 표시하지 않는다.
- 최근 취소된 847기관 요청이 마지막 완료 13기관 요청을 가리는 문제를 발견했다. 취소 요청은 기존 결과 범위를 덮어쓰지 않고, 다른 요청이 없을 때만 사용하도록 결과 계약과 검사를 보완했다. 작업·기록은 삭제하지 않는다.
- 현재: 실제 브라우저와 최종 실제 앱 검증 진행 중.
