# 구조와 선택 이유

현재 앱은 **학교별 조사 Agent + 코드 기반 실행 관리자** 구조다. 하나의 조사 구현에 학교 종류·조사 목적·현재 행사·재사용 경로·공개 근거를 전달한다. 학교마다 별도 프로그램이나 감독용 LLM을 만들지 않는다. 사용자에게는 조사·직접 기록·일정표를 제공하고 근거와 실행 이력은 SQLite에 보관한다.

## 조사 목적과 실행 흐름

```mermaid
flowchart TD
  U[전체 일정찾기 또는 해당 행사 시간 찾기] --> J[고정 학교 큐 · 목적 · 설정 · 누적 한도]
  J --> S[공통 정형 자료 수집]
  S --> E[현재 근거 · 누락 · 충돌 평가]
  E --> R[검증한 학교 경로를 새로 읽기]
  R --> E
  E --> A[선택 모델이 다음 행동과 후보 제출]
  A --> C[행동 계약 · 목적 · 출처 · 중복 · 한도 검사]
  C --> T[MCP 도구 실행]
  T --> O[결과 관찰과 실행 기록]
  O --> E
  E --> V[충분하면 종료 · 공통 후보 검증]
  V --> D[SQLite 원문 · 관측 · 인원 · 경로 · 이력]
  N[자연어 직접 확인] --> D
  D --> P[현재 허용 필드만 일정표로 제공]
  P --> UI[앱 · 독립 HTML · 전체 필터 인쇄]
```

`date_count`는 전체 대상 학교의 날짜·인원을 조사한다. 초중고는 NEIS에 학년도를 강제하지 않고 사용자 실제 날짜 범위를 조회한다. 각 응답 행의 원문 학년도를 보존하고 확인된 행사 학년도의 학교알리미 인원을 조회한다. 날짜가 3월을 넘겨 연기된 행사도 원문 학년도와 다르다는 이유로 버리지 않는다. 누락 재확인은 실제 조회가 완전히 성공한 날짜 범위에만 적용한다. 정형 근거가 충분하면 모델을 초기화하지 않고 종료한다. 기본 조사에서는 시각 탐색 목적의 별도 검색을 허용하지 않지만 날짜를 찾던 동일 원문에 본식 시각이 있으면 함께 저장한다.

`time`은 단일 학교·시즌·현재 행사 UUID와 날짜에 고정한다. 해당 행사의 본식 시각을 찾으며 다른 행사나 변경 전 날짜의 시각을 붙이지 않는다. 작업 시작·재개·체크포인트·최종 저장에서 기간·revision·대상 행사 날짜와 설정을 대조한다. 활성 작업이 있으면 다른 작업을 동시에 생성·재개하지 않는다.

대학은 공식 학사일정·대표 행사 공지·캠퍼스 자료를 조사한다. 학위복 대여·학위증 수령이나 학과 행사를 학교 대표 본식으로 채택하지 않는다. 같은 대표 행사 안의 학부·대학원은 같은 행사로 묶고, 실제 구분되는 회차·캠퍼스는 유지한다.

## 사용자 시즌과 자료 학년도

시즌은 양끝을 포함하는 실제 행사일 범위다. 시작일에 달력상 6개월을 더한 날짜부터는 종료일로 허용하지 않는다. 말일은 도착 월의 말일로 보정한다. 같은 범위는 기존 시즌을 재사용하며, 다른 범위는 새 시즌이다. 기존 시즌의 기간은 수정하지 않는다. 프론트엔드와 Python에 같은 말일·윤년 경계 검사를 적용한다.

시즌의 과거 `academic_year`는 이력으로 보존하지만 새 시즌은 `null`이며 수집·검증의 학년도로 쓰지 않는다. 초중고의 학년도도 날짜로 확정하지 않는다. 실제 NEIS의 AY 생략 날짜 조회가 서로 다른 학년도 행을 반환하는 것을 확인했으므로, 날짜 범위 조회와 원문 학년도 검증을 분리한다. 인원은 각 행사 원문 학년도에 맞는 자료만 연결한다. 대학 학년도·전기/후기·회차는 원문에서 확인하며 날짜로 추론하지 않는다. 대학 학년도 미상이어도 날짜 근거가 충분하면 날짜는 제공하고 인원은 비운다.

기존 행사 UUID가 정본이며 `event_seasons`가 여러 시즌과 연결한다. `events.season_id`는 최초 기록 출처, 관측의 시즌은 당시 조사 조건으로 보존한다. 겹치는 시즌에서 같은 행사와 수기를 복제하지 않는다. 원문은 취득 당시 기간으로 재검증하고 표에는 선택 기간과 교차하는 날짜만 제공한다. 명시 학년도·회차·전후기가 없는 서로 다른 날짜는 같은 행사인지 다른 행사인지 단정하지 않고 연결을 보류한다. 같은 행사임이 확인된 날짜 불일치는 하나의 행사 안에서 충돌로 남는다.

## Agent와 코드의 경계

`ResearchRunner`는 확보한 원문을 평가하고, 검증된 학교 경로를 읽은 뒤 부족하거나 충돌한 필드가 남으면 선택 모델에 다음 행동을 요청한다. 모델은 `AgentDecision` 계약의 `search_web`, `fetch_document`, `stop` 행동과 원문 후보·인원 후보·선택 이유를 제출한다. 실행기는 결과 관찰과 이전 행동을 다음 결정에 다시 전달한다. 계획 문장만 저장하거나 미리 정한 검색어를 순서대로 실행하는 흐름이 아니다.

모델에 전달하는 긴 메뉴·달력 숫자 격자는 필요한 실제 연속 원문 구간으로 줄인다. 생성 응답의 짧은 근거 블록 ID를 원래 문서·분절·연속 인용에 다시 연결한 뒤 내부 `AgentDecision`으로 검사한다. 모델이 원문을 재작성해 문맥을 만들어내는 문제와 긴 UUID 복사 오류를 줄이기 위한 선택이다. 정규 날짜·시각·인원은 여전히 모델의 미승인 제안이며, 원래 제안과 탈락한 필드의 이유도 내부에 남긴다.

코드는 행동 계약, 조사 목적, 공식 URL, 중복 검색·문서 요청, 자료원 호출 수, 문서 수, 모델 호출·토큰·시간 한도를 검사한다. 호출 전 예약과 실제 사용량 정산, 중단 체크포인트를 사용한다. 잘못된 행동은 실행하지 않고 관찰 결과로 돌려주며 취소·재개 때 누적 사용량을 초기화하지 않는다. 모델 장애 시 다른 백엔드로 자동 전환하지 않는다.

`investigation_traces`에는 학교·시즌·목적·대상 행사와 선택 행동·도구 관찰·종료 이유를 기록한다. 정형 자료로 끝난 조사도 명시적인 종료 기록이 남는다. 이 기록은 사용자 기본 화면에 표시하지 않는다.

## 사실을 승인하는 방법

정형 파서는 NEIS·명시 공지·학사력에 등록한 규칙으로 후보를 만든다. 모델 후보도 같은 저장 경로를 통과한다. `grounded_notice`는 기존 파서가 같은 값을 재추출했는지 대신 실제 문맥·필드 인용과 학교·학년도·행사·날짜·시각 역할을 검사한다. 키 힌트가 없는 정상 모델 후보도 근거를 확인한 후 서버가 기존 행사와 연결한다.

기관명과 행사 주어, 본식 날짜와 시각, 문서 단위가 일치해야 한다. 식전 공연·촬영·입장·대여 시각을 본식 시작으로 사용하지 않는다. 날짜만 지원되면 시간은 보류하고 날짜를 게시한다. 취소·미실시·연기와 같은 변경은 같은 기관·학년도·행사에 연결해 이전 값의 현재 사용을 통제한다.

월별 달력은 같은 분절에서 날짜 행 직전의 연월 제목과 그 날짜 바로 다음의 본식 제목을 연결한다. 학년도와 달력 연도를 혼동하거나 같은 페이지의 다른 행사 날짜를 가져오면 거절한다. 대학의 ‘졸업식’과 ‘학위수여식’ 분류는 같은 대표 행사의 동의어로 정규화하되 회차·캠퍼스 차이는 유지한다. 이전 중복을 연결할 때 인원 관측도 함께 이동하며 원문·이력은 보존한다.

원문 해시·공식 관계·실제 인용·기간·필드별 규칙 버전은 저장과 조회에서 검사한다. 모델의 자신감이나 여러 모델의 동의를 승인 근거로 삼지 않는다. 이러한 검사는 명확한 관계를 가진 공개 문서를 처리하지만 모든 자연어 의미 오류를 제거하지는 못한다. 모호한 단위·지원하지 않는 형식은 보류하고 추가 조사 또는 직접 확인이 필요하다.

## 인원과 학교별 경로

`CountClaim`에는 원문 ID, 값, 기준 학년도, 인원 종류, 학년, 단위, 인용, 자료원 식별을 보관한다. 초등 6학년·중고등 3학년 재학생 수와 대학 대표 본식 졸업자 수를 구별한다. 학교알리미 API와 공개 표는 학교 코드·주소·구 코드·기준 학년도·표의 학년 열을 공통 검증기가 다시 확인한다. 전체 학생 수를 졸업 학년 인원으로 바꾸거나 미발견을 0명으로 만들지 않는다.

`count_observations`는 허용·기각 후보와 판정을 함께 보존한다. 조회 시 원문·재확인 상태를 다시 검사한다. 한 경로가 실패해도 독립적인 같은 값의 근거가 유효하면 유지하고, 유효한 인원이 서로 다르면 보류한다. 대학 인원은 단 하나의 현재 허용 행사에만 연결하며 날짜나 행사 관계가 맞지 않으면 사용하지 않는다.

`collection_routes`는 공식 홈페이지와 실제 활용할 수 있는 학사일정·공지 목록을 저장한다. 학교, URL, 목적, 읽기 방식, 마지막 성공·시도, 실패 이유와 원문 ID를 관리한다. 공식성·성공적인 읽기·목록의 공식 링크를 서버가 다시 검사한다. 개별 시즌 공지는 사실 원문으로 남기고 재사용 목록으로 승격하지 않는다.

`route_attempts`에는 실패도 남는다. 미발견·접근 실패·지원하지 않는 형식·다른 학년도를 구분한다. 실패한 경로의 마지막 성공 이력을 지우지 않되 현재 조사에서는 다시 읽어야 한다. 과거 경로 성공이나 검색 실패를 올해 사실 또는 미공개의 증거로 삼지 않는다.

## 직접 기록과 현재 출력

자연어 직접 기록은 외부 모델에 보내지 않고 로컬에서 날짜·시간·학교·확인 방법·실제 확인시점을 해석한다. 원문과 정규값, 질문과 답변, 변경 이력을 저장한다. 명확한 내용은 먼저 기록하고 모호하거나 기존 값과 충돌하는 필드만 질문한다. 기존 시간 보완은 같은 UUID를 갱신한다. 자동 조사는 보호된 수기 값을 임의로 덮어쓰지 않는다.

일정표는 날짜·학교명·시간·졸업인원수·학교 주소의 다섯 열이다. 현재 허용 필드만 제공하고 공란으로 부족한 정보를 표시한다. 학교 링크는 확인된 공식 홈페이지다. 검증 상태·확인시점·정책·기술 사용량은 내부에 유지한다.

앱과 저장 HTML은 같은 필터 스크립트를 사용한다. 학교명·구·하루 조건을 함께 적용하고 복수 행사일의 각 날짜를 검색할 수 있다. 필터 결과 전체를 날짜순으로 정렬하고 날짜 그룹마다 다음 색을 배정한 뒤 20행씩 나눈다. 페이지 경계에서도 같은 날짜는 같은 색이며 흑백 인쇄에는 경계선이 남는다. 인쇄는 현재 필터의 전체 행을 보여준다. HTML에는 CSS·JS를 내장하고 외부 요청 없이 조회·인쇄한다. 학교별 조사 버튼은 실행 앱에만 있다.

시간 칸은 DB 작업의 시즌·대상 행사 ID로 상태를 복원한다. 중간 저장에서 시각을 확보했더라도 작업이 실행 중이거나 일시정지면 진행·중지 표시를 유지하고, 실제 완료 후 시각으로 교체한다. 다른 행은 동시 실행 제한으로 비활성화할 수 있지만 조사 중 표시를 붙이지 않는다. 미발견은 공개 여부의 판정이 아니다. 조사 버튼·진행·결과 안내는 인쇄에서 숨긴다.

## 저장·설정·보호

SQLite WAL·외래키·짧은 거래를 사용한다. 외부 응답을 기다리는 동안 쓰기 거래를 잡지 않는다. 핵심 저장 계약 4.0 위에 `experience_schema=2`, `period_schema=1` 확장을 적용하며 기존 파일은 백업 후 변경한다. 기간 확장은 시즌 학년도를 nullable로 바꾸고 행사 학년도·전후기·시즌 연결을 추가한다. 행사 학년도는 승인 원문·명시 제목에서만 이관하며 과거 시즌 학년도나 수기 행사 날짜에서 추측하지 않는다. 지원하지 않는 버전은 파일을 보존한 채 거절한다.

새 규칙 적용 시 기존 원문을 로컬에서 다시 평가하지만 인터넷에서 새로 읽은 것으로 확인시점을 바꾸지 않는다. 사용자 조사의 과거 행사·관측·수기·원문과 자료원별 연결 이력을 보존한다. 운영 DB에 혼입된 고정 GIST 개발 검증은 정확한 UUID·출처를 대조해 전체 백업과 선별 원본 JSON으로 보관한 뒤 운영 테이블에서 분리한다. 일반 관측·수기가 섞인 행사는 유지하고 검증 근거만 분리해 재평가한다. 새 HTML을 만든 뒤 현재 파일 포인터를 갱신하고 이전 표현 파일은 그대로 보관한다.

새 원문과 정형 후보는 하나의 체크포인트로 저장한다. 조회수처럼 사실과 무관한 본문 변화로 이전 근거가 보류되더라도 같은 작업 안에서 새 근거를 검증할 수 있게 한다. 모델 해석이 필요한 경우에는 그 작업이 저장한 원문 주소 키·해시가 작업 이력에 있을 때만 검토를 이어간다. 검토 중 옛 날짜·시간을 다시 게시하지 않으며 실제 날짜 변경·취소·접근 실패·다른 작업의 원문에는 이 예외를 적용하지 않는다. 같은 값의 근거가 여러 규칙으로 지원되면 재확인에 실패하지 않은 근거를 대표로 선택하고, 서로 다른 값의 충돌은 먼저 분리한다.

여러 시즌이 같은 행사를 볼 수 있으므로 사실 변경 시 모든 시즌 HTML을 갱신 대상으로 표시한다. 앱 수명에 연결한 자동 저장 작업이 이를 확인해 기간별 최신 HTML과 불변 버전을 생성한다. 파일 생성은 별도 스레드에서 실행하고 수동 내보내기와 같은 잠금으로 직렬화한다. 파일 교체 실패·DB 잠금 초과가 자동 저장을 영구 중단시키지 않으며 마지막 정상 파일을 보존하고 재시도한다. 종료는 진행 작업을 일시정지한 뒤 파일 저장을 마무리한다. 저장 실패 시 종료 성공을 알리지 않고 다시 조사할 수 있는 앱 상태를 유지한다. 시즌 수가 적은 로컬 앱에서 복잡한 변경 전파 누락을 피하기 위한 선택이다. 기존 작업 2.0은 이력으로 보존하고 새 조건을 고정한 3.0 작업을 시작한다.

최신 파일과 다운로드 이름은 `schedule_filename()`이 시즌 날짜로 구성한 `광주 졸업식 일정표 (YYYY.MM.DD~YYYY.MM.DD).html`을 공유한다. 파일명 규칙을 브라우저에서 중복 구현하지 않는다. 불변 버전은 `exports/versions/`의 고유 폴더로 구분해 사용자에게 전달하는 파일명에 내부 revision이 붙지 않게 한다.

설정은 기존 기본값·선택 모델 profile·비어 있지 않은 환경 설정 병합을 유지한다. 선택한 Ollama/OpenAI만 필요할 때 초기화하며 사적 수기와 이미지의 외부 전송 정책을 유지한다. 학교알리미 키와 검색·NEIS 키는 비밀 설정으로 보관하고 출력·커밋하지 않는다. 학교알리미 소재 구 코드는 공식 식별 자료로 처리한다.

## 읽기 호환성과 한계

공개 GET 응답의 `P3P :` 헤더 오류만 확인된 경우, 기존 HTTPX 경로에서 한 번 더 예산을 예약해 시스템 libcurl로 읽는다. 원래 호스트와 TLS 인증서 검증·검사한 공개 IP 고정·응답 크기·시간 제한은 유지한다. 자동 리다이렉트·프록시·사용자 curl 설정을 허용하지 않으며, 이동 주소는 기존 공개 URL 검사를 다시 거친다. curl 부재나 다른 프로토콜 오류는 읽기 실패로 남는다. 읽기에 성공해도 새 도메인의 공식성이나 해당 졸업식의 시작 시각을 자동 승인하지 않는다.

본문 검증은 원문 분절에서 제목과 세부 항목의 관계를 읽는다. 본식 제목 아래의 일시와 부대 행사 제목 아래의 일시를 구분하고, 본식에 연결된 취소·미개최 표현만 해당 본식에 반영한다. 날짜가 없는 변경 공지는 학교·학년도·회차와 연결 가능한 기존 행사가 유일한 경우에만 연결한다. 여러 실제 행사를 임의로 합치지 않는다.
