# 자연어 직접 기록 계약

`POST /api/records/natural`은 원문을 외부 모델이나 검색 서비스에 보내지 않는다. 로컬 한국어 패턴 해석과 기존 기관·행사 조회를 사용한다. 해석한 문장이 사용자의 직접 확인 진술인지, 추측인지, 조사 요청인지 분리한다. 지원하지 않는 표현은 대화로 확인하며 파싱 성공을 사실의 독립 검증으로 표시하지 않는다.

## 저장과 질문

- 입력은 시즌·대화 UUID·revision에 묶인다. `natural_records`에 모든 원문, 입력시각, 정규값, 질문과 답변을 저장한다. 기존 API와 같은 토큰·출처·멱등성 검사를 적용한다.
- 명확한 날짜 등은 직접 확인 방법과 실제 확인시점이 있으면 먼저 저장한다. 오전/오후, 날짜, 대상 기관/행사, 확인 방법·시점 또는 기존 값 충돌만 짧게 묻는다.
- `방금`은 사용자가 명시한 상대 시각으로 입력시각에 해석하며 원래 표현을 함께 남긴다. 시간 없이 `어제 확인` 또는 `전화로 확인`이라고만 하면 임의의 자정이나 현재시각을 넣지 않는다.
- 생략 연도는 해당 시즌 기간 안에서 유일한 날짜일 때만 해석한다. 잘못된 날짜·시각·다른 시즌을 자동 보정하지 않는다.
- 학교의 정식 이름·초/중/고/대 축약명을 지원한다. 기관·과정·캠퍼스가 여러 후보면 질문하고 이름 부분 일치만으로 다른 기관에 연결하지 않는다.
- 기존 행사 시각 보완은 기존 UUID의 수기 필드를 갱신한다. 새 행사는 동일 기관·시즌에 연결할 행사가 없을 때만 만든다. 같은 입력 재전송은 멱등 처리하고 반복 기록도 행사 중복을 만들지 않는다.
- 수기 변경은 기존 수기 행을 삭제하지 않고 비활성화와 새 행 추가로 남긴다. 충돌 필드만 보류하고 재확인한 값·시점·근거로 해결한다. 날짜만 정상이라면 결과의 날짜는 유지한다.
- 행사장 언급은 내부 수기 장소로 저장한다. 결과 2.0의 장소 열은 확인한 학교·캠퍼스 주소다.
- 추측은 원문 메모로만 남긴다. 조사 요청은 직접 확인한 사실로 저장하거나 자동 실행하지 않고 앱의 일정찾기를 안내한다. 여러 학교의 추가 조사를 위한 신규 자연어 창이나 범용 챗봇을 제공하지 않는다.

## 기존 DB

핵심 4.0 저장 계약과 기존 `natural_records`, `event_aliases`를 유지한다. 현재 `experience_schema=2`는 별도의 인원·학교 경로·조사 실행 이력을 추가하며 자연어 수기 원본을 바꾸지 않는다. 기존 DB는 추가 전 SQLite backup을 만든다. 규칙 버전 변경도 별도 backup 후 로컬 원문만 재평가한다. 이 재평가는 원문을 인터넷에서 다시 읽은 일이 아니므로 이전 실제 확인시점을 갱신하지 않는다.

자료원별로 나뉜 기존 행사 중 같은 기관·대상·캠퍼스·회차인 기록은 원문과 관측 UUID를 보존하고 연결 이력을 남긴다. 수기 활성 필드끼리 충돌하면 자동 병합하지 않는다. 이전 행사 상세와 과거 평가 이력은 남고 새 수정은 연결된 현재 행사에서 한다.

## 지원 범위

날짜·오전/오후·24시간 시각·전화/문서 확인의 일반 표현을 지원한다. 임의의 모든 한국어 문장을 이해하는 범용 언어모델은 아니다. 복잡한 조건부 일정, 암묵적인 다른 행사 지칭, 여러 시각 또는 불명확한 확인시점은 짧은 질문으로 해소해야 한다.

현재 사용자 결과와 조사 목적은 [결과 계약 2.0](RESULT_CONTRACT.md), 실제 검증 범위는 [최신 검증 기록](RESEARCH_V2_VALIDATION.md)을 따른다.
