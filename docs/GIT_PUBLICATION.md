# Git 공개 관리

앱의 조사 결과와 사용자 기록은 로컬 자료다. 운영 DB·원문·수기·로그·HTML·백업을 저장하는 `data/`, `runtime/`, `output/`, `exports/` 등의 경로는 Git에서 제외한다. 앱을 사용해 수집할 때 Git에 자동으로 업로드하지 않는다.

## 공개하는 자료

소스 코드, 비밀값 없는 설정 예제, 문서와 검토한 고정 검사 자료를 공개한다. `assets/registry/`의 명부는 최초 학교 목록의 출처 검증에 사용하므로 무조건 삭제하지 않는다. 보안 토큰과 불필요한 게시 작성자·시설장 이름을 제거한 사본을 사용하고, 원문 취득 해시와 공개 사본의 해시는 구분한다.

`config/publication-data-manifest.json`은 명부·원문 고정 예제·화면 증빙 등의 공개 검토 목록이다. 해당 파일의 내용이 바뀌거나 새 자료가 추가되면 자동으로 승인되지 않는다. 자료를 직접 검토한 다음 정확한 SHA-256과 필요한 이유를 기록한다. 해시는 검토 이후 내용이 달라졌는지를 확인하며 개인정보 검토 자체를 대신하지 않는다.

이 목록을 도입하기 전의 과거 파일도 현재 검토한 파일과 일치해야 한다. 차이가 있는 과거 사본은 `historical_files`에 별도로 검토한 정확한 해시와 이유를 남긴다. 과거 이력 전체를 검사에서 제외하지 않는다. 검토 목록을 포함하는 커밋은 해당 시점의 목록으로 검사하며, 과거 사본 등록은 현재 파일 승인을 대신하지 않는다.

검사 문자열 예제는 실제 키를 사용하지 않는다. 화면 증빙에 합성 학교명이 있어도 이름·전화번호·수기·설정 화면이 함께 노출되지 않았는지 확인한다.

## 로컬 차단과 GitHub 검사

최초 개발 환경마다 다음 명령으로 저장소의 hook을 활성화한다. Git은 저장소를 복제할 때 이 로컬 설정을 복제하지 않는다.

```sh
git config --local core.hooksPath .githooks
python3 scripts/check_publication_safety.py --tracked
```

- `pre-commit`: 스테이징한 실제 Git 내용을 검사한다. 금지 경로, 비밀값 패턴, 현재 로컬 `.env`의 키와 일치하는 값, 개인 홈 경로, 숨겨진 HTML 토큰, 미검토 자료를 차단한다.
- `commit-msg`: 제목에 한국어가 없는 커밋과 메시지의 비밀값을 거절한다. 영어 기술명과 한국어 설명을 함께 쓰는 제목은 허용한다.
- `pre-push`: 전송할 최신 파일과 새 커밋 이력·메시지를 검사한다. 키나 미검토 자료를 넣었다가 나중에 삭제한 중간 커밋도 검사한다.
- GitHub Actions: 전체 이력을 가져와 최신 파일과 이력을 다시 검사한다. 이 검사는 **푸시된 뒤** 실행되므로 업로드 전 차단을 대신하지 않는다.

검사는 값 자체를 출력하지 않고 파일·행·유형을 알린다. 대용량 미검사 파일, 심볼릭 링크와 하위 저장소도 자동 승인하지 않는다. 모든 개인정보·파일 형식을 완전히 탐지하지는 못하며, hook은 다른 환경에서 빠지거나 우회될 수 있다. GitHub의 Push Protection은 지원하는 비밀값 유형의 추가 방어 수단이다.

- 당시 원격 `main`은 `5b0516a`였으며 브랜치는 하나, 태그는 없었다.

- 교육청 HTML의 숨김 CSRF 토큰, 불필요한 공개 인명 2건과 개인 홈 경로를 정제했다. 학교명·주소·행사 근거의 의미는 유지한다.

- `reference/handoff/`는 개인 경로만 제거한 배포 사본이다. 원래 명세와 취득 원본 해시를 유지하며, 사본 해시와 설명을 맞춘다.
- 영어 제목 35개와 본문 2개를 번역하고 기존 한국어 제목 5개는 유지한다. 변경안은 [메시지 목록](KOREAN_COMMIT_MESSAGES.md)에 있다.
- 별도 로컬 사본에서 모든 커밋의 정제 대상 값과 과거 `output/` 산출물을 제거하고 메시지를 바꾼 이력을 준비한다. 작성자·커미터와 날짜를 보존하며, 마지막 파일 트리가 검토한 현재 트리와 같은지 검사한다.

준비 결과와 기존→새 커밋 ID 대응은 `runtime/git-publication-cleanup/`에 보관한다. 이력 정리로 과거 파일 내용이 바뀌므로 과거 시점에 기록한 원문·패키지 해시는 당시 취득 기록이며, 정제된 과거 사본의 무결성 보증으로 사용하지 않는다. 현재 버전의 사본 해시와 검사는 함께 갱신한다.

검증은 전체 회귀 검사, 인계 명세 검사 4종과 사본 해시 대조, 실제 임시 Git 저장소의 hook 거절·성공, 공개 예정 사본의 파일·전체 이력 검사를 사용한다. 운영 DB와 분리하며 API 재수집이나 브라우저 화면의 새 검증을 의미하지 않는다. sandbox에서 실제 localhost 포트 검사는 건너뛰므로 별도 실행 확인 범위로 남긴다.

## 원격 반영

일반 삭제 커밋은 이미 올라간 자료를 과거 이력에서 없애지 못한다. 이력을 재작성하면 메시지를 바꾸는 것만으로도 커밋 ID가 바뀐다. 준비·검증과 원격 반영은 별개이며, 사용자 승인 전에는 기존 공개 이력과 실제 작업 브랜치를 교체하지 않는다.

승인 후에는 방금 확인한 원격 `main` ID를 정확히 지정한 `--force-with-lease`로 해당 브랜치만 교체한다. 다른 사람이 원격을 바꿨으면 중단한다. 다른 복제본은 이전 이력을 다시 올리지 않도록 새로 복제하거나 별도로 정리해야 한다. 로컬 운영 데이터와 비밀 설정은 새 복제 전에 별도로 보존한다.

강제 푸시는 다른 사람의 복제본·fork나 GitHub의 캐시·PR 참조를 삭제하지 않는다. 실제 인증키가 노출된 경우 키 폐기·재발급이 우선이며, 필요한 경우 GitHub의 민감 자료 삭제 절차를 따른다. 이번 점검에서는 실제 API 키 노출을 발견하지 못했다.

공식 설명: [GitHub의 민감 자료 삭제](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository), [Push Protection](https://docs.github.com/en/code-security/concepts/secret-security/push-protection).

## 원격 반영 결과

2026-10-21 사용자 승인 후, 원격 `main`이 검증 당시 `5b0516a` 그대로인지 확인하고 정확한 기대 ID를 지정한 `--force-with-lease`로 정제 이력 `cd1ac07`을 반영했다. 원격에서 다시 받아 최신 파일 276개와 이력의 경로·blob 조합 520개를 검사했으며 탐지는 0건이었다. 공개 원격 참조는 `main` 하나이고 새 이력을 가리킨다.

기존 영어 제목 35개와 본문 2개를 한국어로 바꾸고 작성자·커미터·날짜를 보존했다. 정제본의 회귀 검사는 607개 통과, sandbox의 포트 바인딩 제한으로 1개를 건너뛰었다. 작업 폴더도 같은 이력으로 동기화했으며 파일 내용·사용자 DB·수기·비밀 설정은 변경하지 않았다. 정제 전 이력 백업은 로컬 Git 제외 경로에만 보관한다.

GitHub API는 HTTP 403을 반환해 Actions 실행 결과와 예전 커밋 직접 링크의 잔존 여부를 확인하지 못했다. 브랜치 이력 정리 완료를 GitHub 캐시·PR 참조·외부 복제본의 삭제 완료로 확대하지 않는다. 상세 반영 결과는 `runtime/git-publication-cleanup/remote-completion.json`에 기록한다.
