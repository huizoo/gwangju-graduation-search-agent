# 학교 목록 준비와 최초 조사 흐름

2026-10-21. 학교 목록이 없으면 목록을 불러오도록 안내하고, 준비된 목록으로 사용자가 선택한 시즌을 조사한다. 기존 운영 DB 초기화는 이번 변경에 포함하지 않았다.

## 동작과 수정 이유

- 첫 화면은 선택한 시즌의 실제 조사 대상 학교 수를 `/api/results.eligible_institution_count`로 받는다. 학교명·구·날짜 필터나 일정 확인 여부로 목록 준비 상태를 추정하지 않는다.
- 조사 대상이 0개이면 **학교 목록 불러오기**를 표시하고 시즌 조사 버튼을 비활성화한다. 서버도 해당 요청을 거절하므로 버튼 상태와 무관하게 빈 작업이 완료로 저장되지 않는다.
- 명부 조회는 별도 작업으로 실행한다. 응답을 기다릴 때부터 두 위치의 목록 버튼을 함께 잠그고, 작업 상태를 폴링해 실패 시 재시도와 성공 시 시즌 조사를 허용한다.
- 브라우저 검증에서 기존 목록 갱신 요청에 시즌 조사 전용 필드가 포함되어 API가 422로 거절하는 문제를 발견했다. 두 버튼이 공유하는 요청 함수에서 작업 종류별 계약으로 구성하도록 수정했다.
- 목록 확보는 졸업식 조사 완료와 구분해 안내한다. 목록이 준비되면 새 시즌을 지정하거나 저장된 시즌을 선택해 조사한다.
- **파일 내려받기**는 현재 결과의 독립 HTML 복사본을 받는다. 프로그램 없이 조회·검색·인쇄할 수 있으며, 이후 조사 결과가 바뀌면 다시 내려받아야 한다.

## 검증 결과

- 최종 전체 pytest: **565 passed, 1 skipped**. 건너뛴 기존 검사는 sandbox의 localhost socket bind 제한에 따른 점유 포트 우회 검사다. 실제 화면 검사는 별도 허용된 전용 서버에서 수행했다.
- 명부 없음·유치원만 있음·선택 조건 0개·유효 학교 있음·과거 작업 이력 존재를 구분했다. 빈 명부 요청은 422이고 작업과 기관 큐를 남기지 않는다. 명부 자체 조회는 허용한다.
- 실제 `app.js`의 요청 함수를 실행하고 `JobCreate` 계약으로 검증해 목록 요청의 잘못된 필드 재발을 검사한다.
- 합성 자료를 사용하는 실제 브라우저 검사 **15개 통과**: 초기 안내, 불러오는 중 중복 차단, 새로고침 복원, 실패·재시도, 명부 정상 적재, 필터 빈 결과와 조사 범위 분리, 선택 기간과 실행기의 조건 일치, 좁은 화면, 실제 다운로드 이름·자동 저장과 바이트 일치.
- 서버 종료 후 다운로드한 동일 HTML 바이트를 `data:` URL로 열어 외부 리소스 의존이 없음을 확인했다. 전용 도구의 기존 `file://` 제한 때문에 이번에는 파일 더블 클릭 검사를 시도하지 않았다.
- [최초 실패 기록](../runtime/first-use-v6/browser-20261021-154423/result.json)과 [수정 후 최종 결과](../runtime/first-use-v6/browser-20261021-154704/result.json)를 함께 보존한다. 두 전용 브라우저 lease는 `FINISHED / exact-close / finalResidualCount=0`이며 검사 소유 서버도 종료했다.
- 명부 응답과 일정 실행기는 합성 자료를 사용했다. 이번 검사를 실제 API·모델·학교 일정 수집 성과로 계산하지 않는다. 사용자 DB·수기·설정·기존 백업은 변경하지 않았다.
