# 조사 수집기와 사실 검증 경계

아래는 2026-10-20의 역사 기록이다. 현재 학교별 Agent 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 실제 실행 결과는 [2026-10-21 검증 기록](RESEARCH_V2_VALIDATION.md)을 따른다.

2026-10-20 구현·검증 기록. 원본 설계와 계약은 `reference/handoff`에 보존했다. 이 문서는 구현의 범위, 실제 자료에서 발견한 사양 보완, 다음 개발자가 재현할 수 있는 검증 근거를 설명한다.

## 실행 경로

`ResearchRunner.run(institution, season, identifiers=...)`는 기관과 조사 기간만 받아 LangGraph를 실행한다. 정답 날짜나 행사 URL을 필수 입력으로 요구하지 않는다.

1. 학교이면 NEIS `SchoolSchedule` 전체 기간을 읽는다. 기존 저장 근거와 공식 목록에 연결된 홈페이지도 읽는다.
2. 등록된 정형 규칙으로 후보를 추출한다. 공개 원문이 읽혔고 공식성이 연결된 경우에만 선택 모델을 필요에 따라 호출한다.
3. 정확한 날짜와 실제 시작 시각이 부족하면 새 검색어와 발견한 공식 링크로 추가 조사한다.
4. 기관별 검색·본문·재계획 한도 또는 충분한 근거에 도달하면 종료한다.

NEIS, 검색, 본문 읽기는 실제 MCP 클라이언트의 `call_tool` → MCP 서버 → 수집기를 통과한다. `policy://graduation/verification` 리소스도 세션에서 읽는다. MCP의 메모리 전송은 앱 내부의 실제 프로토콜 호출 경계이며 독립된 원격 MCP 서비스를 배포한 것은 아니다. 예산·중단 예외가 MCP의 일반 오류 문자열로 바뀌지 않도록 원래 예외를 실행기로 되돌린다.

완료한 문서와 후보는 다음 외부 호출 전 `meter.checkpoint(...)`로 저장한다. 중단 시 이미 얻은 근거를 잃지 않기 위한 처리다. 조사 결과는 저장 계층에 전달하며 수집기나 모델이 게시 상태를 직접 정하지 않는다.

## 자료원별 구현

| 경로 | 동작 | 실패·한계 처리 |
|---|---|---|
| NEIS 학교 목록 | 실제 KEY 인증, F10 범위, `list_total_count`와 페이지 누적 대조 | 키 없으면 `configuration_required`; 샘플 키 대체 없음; 중복·누락 페이지 거절 |
| NEIS 학사 일정 | 기관 복합 코드, 학년도, 기간 시작·끝으로 전 페이지 수집 | 자료 없음과 인증·요청 실패를 구분; 날짜와 시간을 추측하지 않음 |
| Tavily 검색 | Bearer 인증, 일반 공개 검색, 결과 수·공식 도메인 필터 | 검색 요약은 URL 발견용이며 날짜·시간 근거로 저장하지 않음 |
| HTML | 공개 응답·본문·인용 구간과 원문 해시 보존 | HTTP 200의 삭제/오류 공지, 빈 본문, 잘못된 형식도 실패로 구분 |
| PDF | 텍스트 PDF의 제한된 페이지·문자 추출 | 이미지 PDF는 미지원. OCR, 시각 추측, 표의 연도 추론을 하지 않음 |
| 모델 | 선택된 Ollama 또는 OpenAI만 지연 초기화 | 백엔드 자동 전환 없음. 공개 원문 외부 전송 기본 금지. 사적 메모·연락 기록·비밀값 미전송 |
| 공식 파일 | JSON/UTF-8 CSV 정규화, 원본 파일 해시, 종류·5개 구·캠퍼스·중복 검사 | 형식 검증은 발행자의 공식성 증명이 아님. 모든 종류의 자동 목록 API는 아직 없음 |

HTTP 수집기는 DNS의 모든 주소가 공개 주소인지 검사한 뒤 연결할 IP를 고정한다. TLS의 서버 이름과 Host는 원래 도메인으로 유지한다. 리다이렉트와 빈 HTML의 짧은 정적 meta refresh도 같은 검사를 다시 거친다. 크기·시간·재시도·호스트 간격·HTTP 예산을 적용하고 TLS 검증을 끄지 않는다. JavaScript 실행이나 사용자 브라우저 연결은 하지 않는다.

원래 홈페이지가 다른 도메인으로 이동하거나 최종 응답이 HTTP인 경우 읽기 성공과 공식 근거 승인을 분리한다. 자동으로 새 도메인을 공식 채널에 추가하지 않는다. 기존 근거 재조회는 시도한 문서에 한해 성공/실패 시각을 기록한다. 같은 출처의 취소·연기 문구는 `event_blockers`로 전달해 과거 정상값을 조용히 재사용하지 않게 한다.

## 자동 승인 규칙

실제 원문과 반례를 검토한 버전은 `neis_ceremony_row@1.1.0`, `explicit_notice@1.1.0`, `academic_calendar_row@1.0.0`이다. 규칙별 증거의 수준과 한계는 [규칙 목록](../config/rule-catalog.json)에 구분한다. 설정 허용목록은 ID와 버전을 함께 고정한다. 등록 규칙이 있다는 것만으로 후보를 승인하지 않는다. 저장 경계에서 기관·문서·행사·시즌 연결, 실제 원문 인용, 정규값, 출처 해시, 공식 채널, 시작 시각 역할을 다시 검사한다.

`neis_ceremony_row`는 허용된 졸업 행사명, 실제 유효 날짜, 대상 학년도와 기간, 요청한 학교 코드를 모두 확인한다. NEIS에 시각이 없으면 시각은 비워 둔다. `explicit_notice`는 기관·학년도·행사일이 같은 문장에 있고 실제 시작을 명시하는 형식 또는 제목과 `[행사개요]` 안의 일시·장소가 연결된 제한된 형식을 지원한다. 입장·가운 수령·학교 운영 시각을 시작 시각으로 바꾸지 않는다. 지원하지 않는 표현은 미확인으로 남긴다.

모델에는 전체 저장 계약 대신 값과 실제 원문 인용을 제안하는 작은 중간 스키마를 준다. 서버가 인용의 정확한 연속 문자열을 대조하고 계약 `Candidate`로 옮긴다. 행사 정체성이나 승인 증명은 모델에게 생성시키지 않는다. 모델 후보의 `event_key_hint`는 `null`이며 일반 후보는 참고 상태다. 모델이 맞는 JSON을 반환해도 그것은 일정의 사실 증명이나 판매 게시 승인이 아니다.

`academic_calendar_row`는 학사력 변경 공지의 학년도·학부/대학원·회차와 `(변경전) YYYY.M.D → (변경후) YYYY.M.D`를 함께 확인한다. 같은 행사의 이전 관측이 명시된 이전 날짜와 일치할 때만 날짜 근거를 대체한다. 이전 관측과 대체 감사 이력은 보존하고 수기는 덮어쓰지 않는다. 새 문서라는 이유만으로 선택하지 않으며, 순환하거나 서로 맞지 않는 변경은 충돌로 남긴다. 지원하지 않는 표·날짜 생략·시간 변경은 자동 적용하지 않는다.

이 규칙의 실제 파서 양성은 광주 밖 서강대의 과거 2025학년도 공지이며 날짜 변경 `2026-02-23 → 2026-02-20`만 확인했다. 공식 채널에 적재하지 않은 캡처의 `authority=unverified`는 유지하고, 이를 운영 일정으로 게시하지 않았다. 저장·게시의 대체 관계와 수기 보호는 별도 합성 원문으로 검사했다. 광주 실제 변경 사례의 종단 성공으로 합산하지 않는다.

## 실제 자료로 보완한 사양

### 광주 주소와 학교 종류

2026-10-20 인증 NEIS F10 학교 목록 335행의 주소는 `광주광역시` 대신 `전남광주통합특별시`였고 교육청명은 `전남광주통합특별시교육청(광주)`였다. 이 실제 응답을 근거로 두 지역명 표기를 같은 광주 5개 구에만 허용한다. 경기도 광주시와 전남의 다른 시군은 거절한다. 법령상 행정구역 변경 여부를 별도로 판정하는 기능은 아니다.

종류는 초등 158, 중등 92, 고등 71, 특수 6, 기타 8행이다. 기타에는 방송통신·외국인·고등기술·각종학교가 포함된다. 기존 종류 가정을 그대로 적용하면 정상 공식 행이 누락되므로 `other_school`에 명시적으로 매핑했다.

### 특수학교의 복수 행사

광주선광학교 실제 응답에 유치원·초등·중등·고등·전공과의 졸업식이 별도 행으로 있었다. 모든 행에 동일한 `main/졸업 대상 학생`을 붙이는 초기 구현은 서로 다른 대상 행사를 충돌로 합쳤다.

1.1.0은 과정, 주야간, 대상 학년 Y 플래그, 행사명을 행사 단위로 사용한다. 날짜는 행사키에 넣지 않아 날짜 변경을 새로운 행사로 숨기지 않는다. 같은 기간 API URL도 행사마다 별도 `source_key`를 부여하여 서로 다른 과정이 문서의 새 버전으로 오인되지 않게 했다. 실제 5행은 5개 행사로 구분되며 이전의 대상 불명 후보를 재승인하지 않는다. 운영 DB에 남은 이전 버전의 대상 불명 기록은 감사 이력으로 보존한다.

### 공식 홈페이지 이전과 오류 공지

첨단고 홈페이지는 원래 `cheomdan.gen.hs.kr`에서 `cheomdan.jge.hs.kr`로 이동하고 다시 meta refresh로 HTTP 본문을 제공했다. 빈 본문을 실제 읽기 실패와 구분해 원인을 기록하고 정적 이동을 지원했다. 최종 HTTP이며 공식 채널도 다른 호스트이므로 판매 근거로 자동 승인하지 않는다.

인계 자료의 GIST `no=220364`는 HTTP 200이지만 “필수값이 존재하지 않습니다” 오류 페이지였다. 실제 공식 목록에서 `no=220361`을 발견했다. 오류 문구를 유효 공지로 취급하지 않게 검사하고 실제 공지로만 과거 시즌 검증을 수행했다.

NEIS 목록 집합 SHA-256은 `395d7ead986d4e466f864faf5cefe842714c94e7508c39e319f6a448e1ed49a5`다. GIST 읽기 문서 SHA-256은 `0780f2042ce8aced53f86d08e35be6ea12caa0a3aa7f31629a4d5af02641a622`다. 원문은 실행 당시의 스냅샷이며 이후 일정 변경까지 보증하지 않는다.

수집기 단위·경계 검사는 인증 실패, 누락 페이지, 잘못된 기관, 사설 주소/리다이렉트/meta refresh, 빈 PDF, 초과 크기, 예산 중단 전달, 허위 인용, 월 정밀도, 입장 시간, 다른 시즌, 특수학교 대상 혼합을 포함한다. 중간 검사 81건의 기록은 `checks/research-results.json`에 보존하며 최종 전체 검사 수는 [검증 기록](VALIDATION.md)을 따른다. 격리 응답과 합성 예문은 실제 일정 정확성의 대체 증거로 계산하지 않는다.

최종 검토에서는 NEIS 재조회가 실패했지만 문서가 비어 있다는 이유로 이전 날짜의 현재 허용이 유지되던 경로를 수정했다. 실제 실패 또는 완전 조회에서 기존 행사 행이 빠진 경우, 해당 기관·시즌·NEIS 근거만 재확인 실패로 표시한다. 과거 날짜와 확인시점을 보존하며 정상 같은 행을 다시 읽으면 복구한다. 키 미설정·미시도·보조 검색 실패와 다른 시즌에는 전파하지 않는다. 8개의 독립 저장·게시 회귀 검사를 추가했다.

## 재현과 남은 범위

저장 설정과 `.env`를 사용하며 비밀값을 인자로 넘기지 않는다.

```bash
.venv/bin/python -m pytest tests/test_providers.py tests/test_research.py tests/test_rules.py tests/test_registry.py -q
.venv/bin/python checks/check_live_providers.py registry
.venv/bin/python checks/check_live_providers.py registry_pages
.venv/bin/python checks/check_live_providers.py calendar
.venv/bin/python checks/check_live_providers.py search_reader
.venv/bin/python checks/check_live_providers.py seeded_documents
.venv/bin/python checks/check_live_providers.py model
```

실제 호출에는 NEIS/Tavily 키, 인터넷, 선택한 로컬 Ollama 서버와 설치된 모델이 필요하다. OpenAI 선택 경로는 구현되어 있지만 이 작업에서 실제 호출하지 않았다. 원격 모델을 쓰려면 선택 백엔드의 키와 공개 문서 외부 전송 설정이 필요하다. 키가 없거나 연결이 안 되면 해당 작업의 실패·준비 사항을 반환하며 가상 결과를 채우지 않는다.

학교 외 모든 기관의 자동 전체 목록, 브라우저가 필요한 사이트, 이미지·HWP 첨부, OCR, 모든 공지 문법과 PDF 표 추론은 수집기 구현의 미지원 범위다. 공식 파일 적재나 사용자 직접 확인으로 이어갈 수 있지만 그 검증을 자동 완료로 표시하지 않는다. 현재 시즌에 실제 시작 시각이 없으면 날짜만 남기고 판매용 확정 일정으로 내보내지 않는다.
