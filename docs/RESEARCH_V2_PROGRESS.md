# 2026-10-21 조사 Agent 개선 기록

> 이 문서는 이전 2.0 진행 이력입니다. 현재 결정과 작업 상태는 [기간 3.0 진행 기록](PERIOD_V3_PROGRESS.md)을 따릅니다.

## 우선순위와 범위 변경

이번 사용자 요청이 이전 화면·조사 요구보다 우선한다. 조사·조회 대상은 광주 초등학교·중학교·고등학교·대학교·전문대학이다. 어머니의 졸업식 조사 목적에 맞춰 기존의 유치원·어린이집·특수학교·기타 유형을 기본 대상에서 제외한다. 기존 기관·행사·수기·근거는 삭제하지 않는다. 이 변경 사유는 이 기록에만 남긴다.

이전 결과 1.0의 네 열, 하루/기간 선택, 공지 우선 링크, 조사 요청별 좁은 기본 범위는 결과 2.0으로 대체한다. 원본 `reference/`와 이전 검증 증빙은 보존한다.

## 구현 단계

1. 날짜·인원 `date_count`와 단일 행사 `time` 목적, 5열 결과, 복수 실제 행사일 계약.
2. 정형 수집·학교 경로·한 학교를 입력으로 받는 실제 모델 의사결정 반복.
3. 모델 후보의 행사 연결과 독립 원문 관계 검증, 공통 저장·게시.
4. 전체 공식 학교 목록, 작업·재개, 앱·HTML·필터 결과 전체 인쇄.
5. 정상·반례, 실제 선택 모델·자료원·전용 브라우저 검증과 문서 정합성.

## 출발 상태와 판단

- 적용되는 별도 파일 AGENTS.md는 명시한 상위 경로와 프로젝트에서 발견되지 않았다. 사용자의 Global Working Agreements를 적용한다.
- Git 출발점은 `403d3bf`, 작업 트리는 깨끗했다. `.env`, 사용자 DB, 실행 중인 기존 앱을 변경하지 않는다.
- 기존 조사 계획 노드는 고정 검색어를 실행했다. 모델은 추출만 수행했고, 모델 후보의 행사 키가 null로 강제되어 최종 게시 경로가 막혀 있었다.
- 새 Agent는 관찰 결과마다 다음 행동 하나를 구조화해 제안한다. 실행 관리자는 목적·대상·도구·중복·한도·취소를 검사한다. 정형 날짜와 인원이 충분하면 모델 없이 끝낸다.
- 학교알리미 학년별 재학생 수 API에는 별도 키가 필요하다. 사용자에게 안내한 뒤 키 추가 완료 응답을 받았다. 올해 발급 키는 시군구 파라미터가 필수이므로 학교 소재 구를 전달한다. 별도로 공식 공개 공시 경로에서도 건국초 2026학년도 6학년 188명을 확인했다.
- 범위가 독립적인 자료원·Agent 반복·화면 작업을 나누고 핵심 계약·저장·검증은 통합 관리한다.

## 구현·검증 결과

- 1단계 계약·설정 검사 14개 통과. 조사 목적·단일 행사 시간 조사·정렬된 복수 행사일·대상 학교 범위를 확정했다.
- 2·3단계 공식 명부·학년별 인원·원문 관계 검증·지속 저장 관련 165개 검사 통과. 원래 파서가 재추출하지 못하는 모델 후보도 공식 학교·학년도·행사·필드 인용 관계가 맞으면 게시한다. 월별 학사일정은 같은 원문 분절의 직전 연월 제목과 바로 뒤 행사 행을 연결하며 다른 달·연도·인접 행을 빌려오지 않는다.
- 실제 명부 갱신: NEIS 대상 321개와 공식 고등교육 명부 18개, 합계 339개. 학교알리미의 현재 공식 시도 코드 12와 구별 `sggCode`를 사용한다. 사용자 키로 건국초 해당 학년도 6학년 188명을 확인했다.
- 날짜를 미리 주지 않은 실제 건국초 실행에서 2027-01-06과 188명을 저장·API·HTML·재시작까지 확인했다. HTTP 3회, 검색·모델 0회이며 시간 목적의 별도 검색은 없었다. 이는 정형 수집 검증이고 모델 Agent 성공으로 계산하지 않는다.
- `experience_schema=2`는 백업 후 인원 관측·학교 경로·경로 시도·Agent 기록 테이블을 추가한다. 격리한 실제 DB 복사본에서 기존 원문 159개의 텍스트·해시, 원본 DB 전체 테이블 체크섬과 `.env` 불변을 검사했다. 원본에는 수기 데이터가 없었으므로 수기 보호는 별도의 합성 회귀로 검사한다.
- 실제 qwen3:8b 실행에서 무효 action, 반복 검색, 원문에 없는 날짜·인원 제안이 발생했으며 그대로 실패 기록을 보존했다. 형식이나 근거가 잘못된 결과는 게시하지 않는다.
- 모델 응답은 실제 근거 블록 ID와 요청 기간의 연월 형식을 사용한다. 날짜 정답을 주입하지 않고 모델이 원문에서 일자를 읽는다. 공통 저장 검증은 블록을 실제 문서·분절·연속 인용으로 복원한 뒤 학교·행사·학년도·필드 역할을 다시 검사한다. 긴 UUID와 원문 재작성에 따른 작은 모델의 오류를 줄이는 대신 독립 관계 검사를 유지한다.
- 대학의 대표 졸업식/학위수여식 명칭은 같은 행사로 연결한다. 캠퍼스·회차가 다르면 분리한다. 행사 식별 마이그레이션 3은 별칭을 합칠 때 인원 근거의 행사 ID도 함께 옮기며 수기 충돌은 보존한다.
- 최종 실제 JobManager 실행에서 광주대학교 **2027-02-19**를 모델 후보 → 원문 관계 검증 → 체크포인트 → SQLite → API → HTML에 새로 게시했다. 이전 실제 탐색의 공식 경로를 재확인해 사용했다. 모델 2회·HTTP 5회·10,212토큰 이후 기존 예산에서 중단됐고 인원은 공란이다. 날짜 게시 성공과 전체 조사 미완료를 구분하며 원래 `passed=false`를 보존한다.
- 통제된 관찰(경로 실패·과거 자료·다른 행사·충돌)에 대한 실제 모델 행동 검사 4개를 통과했다. 앞 세 상황은 같은 현재 학년도 일정 검색, 충돌은 행사 식별 검색을 선택했다. 실제 현장에서 네 상황을 모두 해결했다는 주장은 하지 않는다.
- 앱·독립 HTML 브라우저 20개와 최종 실제 자료 HTML 4개 검사를 통과했다. 20행 페이지·세 조건 AND·다중 일자·전체 필터 결과 인쇄·기존 행사에 자연어 시간 보완·전체 대상 작업을 확인했다. 서버 종료 뒤 동일 HTML 바이트로 오프라인 동작을 검사했고 전용 브라우저 잔여 프로세스는 0이다.
- 최종 회귀 **399개 통과**. 실제 자료·모델·브라우저·합성 회귀의 범위와 남은 한계는 [검증 기록](RESEARCH_V2_VALIDATION.md)에 구분했다. 사용자 DB·수기·설정·원본 참고 자료를 보존하고 검증 자료는 별도 사본에 저장했다.
