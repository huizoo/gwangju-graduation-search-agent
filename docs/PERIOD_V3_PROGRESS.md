## 영향과 결정

기존의 `season.academic_year`는 NEIS, 인원 조회, 모델 입력, 원문 검증과 게시에 같은 값으로 사용됐다. `events.season_id`를 행사 식별에 포함해 겹치는 시즌에 동일 행사와 수기를 복제할 위험도 있었다.

사용자 시즌을 불변의 포함 날짜 범위로 바꾸고, 학년도는 별도의 행사 사실로 분리했다. 기존 `events` UUID를 정본으로 사용하고 `event_seasons`로 여러 시즌에 연결한다. `events.season_id`는 최초 기록 출처, `observations.season_id`는 원문을 취득한 조사 기간으로 보존한다. 새 정본 테이블로 모든 수기·원문 외래키를 옮기는 방식보다 이관 범위가 작다.

- 새 기간은 자동 이름·기간 파일명을 받는다. 같은 범위를 다시 생성하면 기존 시즌 ID를 반환한다. 기간 수정은 금지하고 새 시즌으로 처리한다.
- 시작일에 달력상 6개월을 더할 때 말일을 보정한다. 그 날짜 자체부터 종료일로 금지한다. Python과 실제 JavaScript에 같은 경계 벡터를 적용한다.
- 초·중·고는 NEIS에 AY를 지정하지 않고 실제 날짜 범위를 조회하며 각 행의 원문 AY를 보존한다. 확인된 행사 학년도로 인원을 조회한다. 처음 구현한 3월 경계 분할은 졸업식 연기 때 자료 학년도를 놓칠 수 있어 수정했다. 실제 API에서 AY 생략으로 2025·2026학년도 행을 함께 받는 것을 확인했다. 날짜·학년도 분리가 더 정확하고 조회도 단순하다.
- 대학은 명시 학년도·전기/후기·회차를 원문 관계로 확인한다. 날짜만으로 대학 학년도를 정하지 않는다. 학년도 미상 날짜도 원문 검증을 통과하면 제공하지만 인원은 연결하지 않는다.
- 학년도·전후기·회차가 모두 없는 후보의 날짜가 달라지면 같은 행사로 확정하거나 별도 행사로 생성하지 않고 미연결 관측으로 남긴다. 학년도가 확인된 같은 행사의 다른 날짜는 기존처럼 충돌이다.
- 근거는 원래 취득 기간으로 재검증하고 결과는 선택한 시즌과 교집합인 날짜만 제공한다. 수기는 복사하지 않는다. 행사 변경 때 모든 저장 HTML을 갱신 대상으로 표시한다. 로컬 앱의 적은 시즌 수에서 복잡한 전파 누락을 피하는 선택이다.
- 작업은 기간·revision·대상 행사 날짜를 고정한다. 시작·재개·체크포인트·최종 저장에서 현재 조건과 다시 대조한다. 기존 2.0 작업은 기록으로 보존하고 새 3.0 작업을 시작한다.
- 저장 구조 `period_schema=1`을 백업 후 설치한다. 기존 시즌 학년도는 역사 값으로 보존하고 새 시즌은 `null`이다. 행사 학년도는 승인 근거·명시 제목으로만 이관한다. 수기 행사일만으로 학년도를 확정하지 않는다.

## 화면

행별 시간 조사는 시즌·대상 행사 UUID와 DB 작업 상태로 복원한다. 요청 전송 중과 접수 후 실제 조사 상태를 구분하고, 다른 학교의 비활성 버튼을 조사 중으로 표시하지 않는다. 중간 체크포인트가 시간을 확보해도 실행 중 또는 일시정지라면 진행·중지 표시를 유지하고 완료 후 시간으로 교체한다. 인쇄에서는 조사 안내 전체를 숨긴다.

필터 결과 전체를 날짜순으로 묶어 6색을 순환하고 나서 20행씩 나눈다. 같은 날짜가 페이지를 걸쳐도 같은 색이며 필터를 바꾸면 색을 다시 배정한다. 인쇄의 흑백 그룹 경계선은 유지한다.
