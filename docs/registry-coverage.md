# 비학교 기관 공식 목록 확보와 적재 검토

아래는 2026-10-20의 역사 기록이다. 현재 대상 명부와 조회 결과는 [2026-10-21 검증 기록](RESEARCH_V2_VALIDATION.md)을 따른다.

2026-10-20에 공개 공식 사이트에서 원문을 취득했다. 이 문서는 기관 명부의 확보 범위를 설명하며 졸업식 일정 확인 결과가 아니다. API 키·계정·권한을 새로 준비하지 않았다. 확보 단계 이후 서버 검증과 실제 앱 import를 완료했으며, 최종 적재 상태는 아래 구현 결과와 [실제 앱 증빙](evidence/live-validation.json)에 기록한다.

## 유치원 명부 검증

교육청 화면의 전체 수 256과 엑셀 출력의 데이터 행 256이 일치한다. 공식 유치원 공시 코드도 256개로 모두 고유하다.

| 구 | 공식 화면 | 다운로드 행 |
| --- | ---: | ---: |
| 동구 | 17 | 17 |
| 서구 | 46 | 46 |
| 남구 | 38 | 38 |
| 북구 | 80 | 80 |
| 광산구 | 75 | 75 |
| 합계 | 256 | 256 |

파일은 확장자가 XLS인 HTML 표다. ZIP XLSX로 잘못 읽지 않고 실제 표를 파싱했다. 홈페이지는 기관명 링크에서 직접 추출했으며 169개는 연결 주소가 있고 87개는 원문에 없다. 기관명·주소·전화·유치원 공시 코드와 홈페이지만 사용했다. 병설유치원은 초등학교와 합치지 않는다.

공식 명부에 포함되었다는 사실로 `active`를 설정하지 않는다. 정규 데이터의 운영상태는 모두 `unknown`이며 폐원·휴원 확인은 별도 자료가 필요하다. 이 명부의 완전성은 “공식 관내 유치원 목록에 나온 256개를 빠짐없이 받았다”는 의미다. 현재 운영 중인 모든 기관의 현실적 완전성이나 해당 시즌 졸업식 개최를 보장하지 않는다.

유치원알리미 요약의 본문 텍스트에는 통학차량 설명·숨겨진 상태 문구가 섞일 수 있다. `미운영`, `이전` 같은 단어만으로 기관 폐원 여부를 판정하지 않았다.

## 대학·캠퍼스 구분

대학 자료의 행별 자료 기준일은 모두 **2026-03-18**, 기준연도는 2025다. 2026-10-20 취득일을 기준일로 대체하지 않았다. 초기 표준 페이지에는 499개의 전국 미리보기 행만 보였으므로 이를 광주 전체 목록으로 해석하지 않았다. 이후 페이지의 실제 검색 필드 `CTPV_NM=광주광역시`를 사용해 광주 79행을 확보했다.

대학구분명 `대학`은 `university`, `전문대학`은 `junior_college`로 대응한다. 한국폴리텍 V 대학 광주캠퍼스는 학교구분명이 기능대학이지만 대학구분명은 전문대학으로 명시되어 있으므로 원문 대학구분을 적용했다. 알 수 없는 분류를 조용히 다른 유형으로 바꾸지 않았다.

대학원 61행은 학교 이름 뒤 “대학원” 문자열을 임의로 잘라 합치는 대신, 원문 **대학구분명**이 대학원인 행을 기관 생성 대상에서 제외했다. 제외 행과 이유는 `university-excluded-graduate-rows.json`에 보존한다. 대학원·학과 졸업식은 해당 캠퍼스 아래 별도 행사로 연결해야 한다.

대학 18행은 모두 원문상 `본교`다. 이 사실을 광주 소재 별도 캠퍼스가 없다는 뜻으로 해석하지 않는다. 타 지역 본교의 광주 지역대학·학습관 등은 원문 광주 필터에 포함되지 않을 수 있으므로 독립 목록 대조가 남아 있다. 다른 주소나 캠퍼스는 자동 병합하지 않는다.

## 어린이집과 복지플랫폼 파일의 한계

공공데이터포털의 검색 인덱스에는 2025-08-28 파일이 보였지만, 실제 다운로드 메타데이터와 다운로드 파일은 **2026-09-21 ZIP**이었다. 현재 검증은 실제 취득 파일을 기준으로 기록한다. ZIP 안에는 CP949 CSV 두 개가 있으며, 파일명 날짜를 행별 자료 기준일로 간주하지 않았다.

어린이집 250행은 각 구가 정확히 50개다. 이것만으로 실제 서비스의 제한 방식이 50개라고 단정할 수는 없지만, 광주 전체 명부라는 근거가 없고 지역별 제한 표본의 징후가 명확하다. `coverage_complete=false`, `expected_total=null`을 유지한다.

복지플랫폼 유치원은 원본 400행 중 같은 자료원·유형·기관명·주소가 정확히 일치하는 145행만 중복 제거했다. 주소가 다르거나 이름만 비슷한 행은 합치지 않았다. 교육청 명부의 구별 수와도 일치하지 않아 두 파일의 단순 합집합을 전체 명부로 만들지 않는다.

이 CSV들은 기관명·주소만 제공하므로 전화·홈페이지·운영상태를 추정하지 않는다. 광주하나금융공동직장어린이집 한 곳은 별도 공식 공시에서 주소·전화·홈페이지를 확보했다. 운영시간은 졸업식 시작 시각으로 사용하지 않는다.

## 정규 적재와 공식 관계 신뢰 경계

권장 검토 순서는 다음과 같다.

1. `kindergarten-edoffice-registry.json`을 preview하고 중복 후보를 검토한다.
2. `universities-registry.json`을 preview한다. 기존 대학·캠퍼스와 같은 기관인지 주소까지 대조한다.
3. `childcare-welfare-partial-registry.json`과 `childcare-representative-registry.json`을 각각 검토한다.
4. 원본 명부의 최신성·운영상태 미상을 그대로 보존하고 commit 후 공식 목록 확보 화면을 확인한다.

모든 파일은 앱의 실제 `RegistryImport` JSON Schema 검사를 통과했다. 공식 기관코드가 제공되는 교육청 자료는 `pPresch` 코드를 외부키로, 어린이집 대표 공시는 `29110000084`를 사용한다. 코드가 없는 대학·복지플랫폼 파일은 **자료원 ID + 기관 유형 + 이름 + 주소**의 SHA-256을 사용한다. 행번호를 외부키로 사용하지 않아 행 재정렬만으로 중복 기관이 생기는 위험을 줄인다. 이름·주소가 실제로 변경되었으면 같은 기관인지 별도 매핑이 필요하다.

`homepage-authority-provenance.json`은 공식 관계를 검토할 수 있는 별도 근거 파일이다. 기관 외부키, 기관 이름, 공식 출처·취득 URL, 원문 SHA-256, 원문 행 번호, 기관 홈페이지를 기록한다. 일반 사용자 JSON의 `official_url` 주장만으로 공식성을 승인해서는 안 된다. root의 신뢰된 수집 경로에서 원문 해시와 행 대응을 재검증한 뒤 공식 채널을 등록하는 용도로만 사용할 수 있다. 이 관계 확인은 **기관 홈페이지의 공식성 근거**이며 졸업식 날짜·시각의 게시 승인이 아니다.

대학 표준표는 홈페이지의 호스트·경로를 제공하고 스킴을 생략했다. 정규 파일은 HTTPS를 붙였으며 실제 홈페이지 연결 성공을 주장하지 않는다. 교육청의 HTTP 원문 링크는 원래 형태를 보존했다. 리다이렉트나 도메인 이전 시 새 도메인을 자동으로 공식 출처에 추가하는 판단도 별도로 필요하다.

## 대표 기관 조사 입력

`representative-institutions-no-answer.json`에는 유형 다양성으로 선택한 10곳이 있다.

건국유치원, 빛고을유치원, 효천다솜유치원, 전남대학교, 조선대학교, 광주대학교, 동강대학교, 광주보건대학교, 조선이공대학교, 광주하나금융공동직장어린이집이다.

이 파일에는 공식 명부의 기관 식별·주소·홈페이지만 제공한다. `schedule_url`, `expected_date`, `expected_start_time`은 모두 null이다. 사전에 선택한 졸업식 정답 URL을 Agent 입력으로 제공하는 방식과 구분한다. 여기에는 졸업식 조사·정확성 검증 결과가 없다.

## 재검증

프로젝트 루트에서 다음 명령은 이미 확보한 파일만 읽으며 네트워크 요청·DB 변경을 하지 않는다.

```sh
.venv/bin/python runtime/non-school-registry/normalize_registry.py
```

확보 중의 원문과 임시 분석은 `runtime/non-school-registry/`에 보존한다. 앱 실행에 필요한 승인 명부와 대응 원문만 `assets/registry/`로 복사해 저장소에서 관리한다. `2025 유치원현황` XLSX도 다운로드했으나 기관별 명부가 아닌 집계 통계였으므로 기관 적재에 사용하지 않았다. 전국어린이집 표준데이터 링크는 현 포털에서 별도 제공자 API 안내로 연결되어, 이를 인증 없이 전체 목록을 받은 증거로 삼지 않았다.

## 최종 앱 적재 결과

`official_registry.py`는 보존한 검토 manifest, 원문 파일, 정규 행, 기관코드·주소·홈페이지 관계를 다시 대조한다. `registry_assets.py`는 이 서버 소유 자산과 요청 전체가 일치할 때에만 검토된 공식 채널을 연결한다. 일반 사용자 파일의 공식성 주장만으로 채널을 승인하지 않는다.

원본 유치원 분석의 “256행 확보 완료”는 그대로 보존한다. 다만 앱 계약에서 전체 확보를 주장하려면 자료 기준일도 필요하므로, 준비된 import 파일은 `as_of=null`, `coverage_complete=false`다. 취득일을 자료 기준일로 만들지 않는다.

실제 앱의 미리보기·commit API를 통해 유치원 256, 대학 11, 전문대학 7, 어린이집 250+1을 적재했다. NEIS 학교 335개를 합해 등록 기관은 **860개**다. 이는 광주 전체 교육기관 수가 아니다. 어린이집 전체 목록, 별도 대학 캠퍼스, 자료 기준일·운영상태 확인이 남아 있다.

어머니는 기관 관리의 **준비된 공식 명부**에서 네 파일을 선택해 같은 미리보기와 중복 검토 절차를 사용할 수 있다. 배포된 파일은 2026-10-20 취득 snapshot이며 자동으로 최신 원문을 받지 않는다. 새 파일은 별도 원문 검토 또는 일반 파일 가져오기가 필요하다.

재현 가능한 오프라인 자산 검사는 다음과 같다.

```sh
.venv/bin/python -m pytest -q tests/test_official_registry.py tests/test_registry_assets.py
```
