# 통합 개정 내용과 판단 근거

계약·게시 정책을 **4.0**으로 통합했습니다. 기존 2.1과 첨부 3.0 원본은 보존하고 별도 폴더에서 수정했습니다. 이 패키지는 기획·설계·계약과 실행 가능한 참조 검사이며 실제 앱 구현 완료본이 아닙니다.

## 1 채택한 설계와 이유

| 결정 | 반영 내용과 이유 |
| --- | --- |
| 하나의 게시 판정 | `calculate_publication` 결과를 API·화면·HTML·집계가 공유합니다. 같은 일정의 허용 조건이 출력 경로마다 달라지는 누락을 줄입니다. |
| 일반/판매/관리 조회 | 과거 유효 확인값과 현재 사용 권한을 구분합니다. 접속 실패를 사실 오류로 단정하지 않으면서 판매 준비에서는 불확실한 필드를 제한합니다. |
| 필드별 허용 | 시간만 충돌하면 날짜를 제공합니다. 행사 식별·취소의 미해결 사유는 전체에 적용합니다. 검토 필요라는 상위 플래그 하나로 모두 숨기지 않습니다. |
| 3.0 날짜·근거 표현 | DateClaim/DateValue의 day/month/unknown과 근거 배열·같은 행사 unit·읽기 범위를 유지합니다. 후보뿐 아니라 수기와 조회도 월 계획을 보존합니다. |
| 2.1 검증 연결 보강 | 공식성 출처·시점, 관측 채택/기각 상태, 규칙 ID/버전, 문서 해시와 대상 필드를 연결합니다. 형식 통과나 모델 동의를 사실 확인으로 취급하지 않습니다. |
| 수기 실제 확인시점 | 시점 미상 메모는 보존하지만 확인값으로 게시하지 않습니다. 입력시점으로 실제 확인시점을 대신하지 않습니다. 일반 메모는 선택, 충돌 재확인의 메모는 필수입니다. |
| 안정적인 충돌 시점 | 현재 fingerprint의 최초 인지시점을 별도 기록합니다. 동일 내용의 재조회 시점만 갱신해 이전 재확인을 무효화하지 않습니다. 새 충돌에는 새 재확인이 필요합니다. |
| 수기 문서 버전 | source_document_id로 확인한 원문 버전을 연결합니다. 같은 URL의 무관한 과거 오류로 새 정상 문서까지 막는 문제를 피합니다. 종이·오프라인의 사람 확인도 허용합니다. |
| 정형 처리 우선 | 등록된 API/표 매핑을 먼저 적용하고 필요한 비정형 부분에만 LLM을 사용합니다. 불필요한 호출·오류 경로·비용을 줄입니다. |
| P0 범위 | NEIS·HTML·텍스트 PDF와 핵심 저장/게시/수기/작업 복구를 우선합니다. 브라우저와 HWP는 실제 병목에 따라 추가하며 기본 비활성입니다. |
| 모델 선택 | 초기값은 Ollama이며 `LLM_BACKEND` 하나로 Ollama/OpenAI를 선택합니다. 선택한 연결만 초기화·검사하고 장애 시 다른 백엔드로 자동 전환하지 않습니다. OpenAI 키는 별도로 입력하며 기본 모델은 `gpt-6.1-sol`입니다. 이 선택은 모델 간 정확성 우위의 증거가 아닙니다. |
| 설정과 사용자 준비 | 비밀값과 선택 모델의 연결 정보만 최소 `.env.example`에 둡니다. 비밀이 아닌 전체 기본값은 `config/defaults.json`, 선택적인 환경변수 덮어쓰기 목록은 `config/env-map.json`으로 관리합니다. 기본값을 `.env`에 전부 반복하지 않습니다. |
| 취소 복구 | cancelling은 재시작해도 취소를 마무리합니다. 이미 완료한 항목과 사용량은 보존하고 늦은 응답의 작업 부활을 막습니다. |
| 측정 기준 | 현재 허용된 일자/시각을 기관별로 집계합니다. 과거 일반 조회값·월 정보·후보를 확인율에 넣지 않습니다. 발표 준비와 Before/After 비교 시스템은 범위에서 제외합니다. |
| 근거 정정·재생성 | 원본 probe 집계와 요청 코드의 출처·해시를 보존합니다. HTML/ZIP을 같은 파일 집합으로 재생성하고 내용 일치를 검사합니다. |

## 2 문장뿐 아니라 검사에 연결한 사항

기존 정상 예제를 모두 보류하지 않으면서 네 회귀 사례를 차단하는 검사를 추가했습니다. 네 사례는 미해결 행사 식별, 미해결 취소 주의, 확인시점 없는 수기 충돌 해결, 확인값과 다른 장소 출력입니다. 날짜만 있는 일정과 정당한 사람 재확인은 통과합니다.

교차 검토에서 발견한 추가 누락도 참조 규칙과 검사에 반영했습니다. 날짜가 다른 장소는 그 장소만 숨기고, 수기 문서의 실제 재확인 실패는 현재 사용에 반영하며, 운영 종료 상태의 enum을 계약과 맞췄습니다. 실제 학위수여식·졸업/수료 통합식은 허용하고 단순 수료식·unknown은 자동 승격하지 않습니다. 이미지 크기와 수기 원문 버전의 SQL 저장 매핑도 추가했습니다.

설정 병합도 실행 가능한 참조 검사로 추가했습니다. 최종 `LLM_BACKEND`를 먼저 결정해 해당 공개 문서 전송 profile을 적용한 뒤 `.env`와 프로세스 환경변수를 반영합니다. 생략·빈 값은 이전 값을 유지하고 명시한 false·0은 보존합니다. OpenAI 선택은 공개 문서의 필요한 텍스트 구간 전송을 허용하는 선택이며 키 입력만으로는 전환·허용되지 않습니다. 이미지와 사적 수기 메모는 이 선택에 포함하지 않습니다. 명시한 텍스트 전송 금지는 profile보다 우선합니다. 이 검사는 실제 앱의 설정 로더나 모델 호출이 연결됐다는 증거는 아닙니다.

최종 형식·참조 검사 수와 실행 결과는 `checks/validation-results.json`에 기록합니다. 가상 원문과 가상 규칙을 대상으로 한 사양 검사입니다. 해당 결과를 실제 사이트 전체 정확성이나 모델 일반 성능으로 확대하지 않습니다.

## 3 현재 제공하는 것과 남은 작업

| 현재 제공 | 실제 앱 구현에서 남은 일 |
| --- | --- |
| 기획·설계·JSON Schema·OpenAPI·SQLite DDL·설정·가상 예제 | FastAPI/Pydantic 구현과 실제 DB 접근·마이그레이션 |
| 가상 명시공지의 실행 가능한 게시 참조 함수·반례 검사 | NEIS/HTML/PDF 실제 추출·의미 검증 규칙과 MCP/LangGraph 연동 |
| 취소 복구·현재 허용 집계의 실행 참조 검사 | 실제 worker·영속 checkpoint·재시작·경합·예산 정산 시험 |
| 과거 개별 시험의 원본 집계·요청 설정 근거 | 날짜를 모르는 실제 기관 탐색과 정상/오류 게시의 종단 시험 |
| 이 기획 문서 HTML·ZIP 생성기와 동일성 검사 | 사용자용 실제 일정 HTML·로컬 UI와 어머니 환경의 실행 검증 |

live 활성 규칙 목록은 비어 있습니다. 현재 참조 구현의 문자열 정규화는 가상 명시공지용이며 NEIS·달력·CDN·이미지·HWP의 범용 의미 판독기를 구현한 것이 아닙니다. 각 실제 형식의 양성/음성 사례와 날짜 미상 기관 종단 시험을 통과한 규칙만 활성화해야 합니다.

원문 미공개·오기·사후 변경·사람 확인 착오는 남습니다. 보수적인 현재 사용 제한은 맞는 일정도 일시적으로 판매 목록에서 제외할 수 있습니다. 자동화만으로 모든 정보의 무오류를 보장하지 않고 원문·시점·범위·사유를 함께 제시합니다.
