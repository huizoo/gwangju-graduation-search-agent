# 기술 설계안 4.0

## 1 상태와 단일 정의

이 패키지는 구현 명세와 실행 가능한 판정·계약 참조 검사를 제공한다. FastAPI 앱, 자료원 Adapter, MCP 연결과 전체 Agent의 구현 완료를 의미하지 않는다. 실제 운영 구현은 아래 동작과 `06_acceptance.md`를 검증해야 한다.

버전 4.0의 객체·열거형은 `contracts/domain.schema.json`, API는 `contracts/openapi.json`, SQLite 구조는 `contracts/schema.sql`, 교차 객체 규칙과 출력 의미는 `contracts/README.md`를 기준으로 한다. JSON 열에 이 계약을 직렬화하며 문서마다 임의 모델을 추가하지 않는다. 비밀이 아닌 앱·실행 한도·선택 기능·tracing·신규 시즌의 전체 기본값은 `config/defaults.json`, 선택적 환경변수 덮어쓰기 이름/타입/경로는 `config/env-map.json`만 정의한다. env-map의 전체 목록은 필수 준비 목록이나 `.env.example`의 항목 수를 뜻하지 않는다.

## 2 구성과 책임

Python FastAPI 한 프로세스가 로컬 HTML/JS/CSS와 API를 제공하고 SQLite가 업무 기록을 보관한다. 단일 작업 실행기가 기관별 LangGraph를 제한된 동시성으로 실행한다. 조사와 검증은 논리적 역할이며 같은 모델 인스턴스를 사용할 수 있다. 정형 레코드가 충분하면 모델 역할을 호출하지 않는다.

| 구성 | 책임 |
| --- | --- |
| 기관 Adapter | 공식 목록의 인증·페이징·지역 필터·식별자 대조와 파일 정규화 |
| 수집 Adapter/MCP | 허용된 검색·공식 달력·공개 원문 읽기. 사실 확정이나 DB 변경 권한 없음 |
| 조사 역할 | 부족한 정보에 맞는 다음 자료원·쿼리 선택, 비정형 원문의 후보 추출 |
| 검증 역할 | 행사·시즌·시각 의미와 변경 관계에 대한 근거 있는 제안 |
| 서버 검증기 | 공식성·관측 상태·원문/값/문맥 연결을 등록 규칙으로 검사해 ValueCheck 생성 |
| 게시 판정기 | 수기 보호·필드 충돌·날짜 연결·현재 사용 조건을 반영해 Publication 생성 |
| 실행기/저장소 | 고정 큐·예산·중단/재개·감사 이력·revision과 동시 수정 보호 |
| 조회/내보내기 | 한 snapshot의 동일 Publication으로 일반/판매/관리 조회와 지표 생성 |

MCP는 도구 경계이고 Pydantic은 자료형·교차필드 불변조건을 강제한다. 모델 동의·confidence·출처 개수, HTTP 200이나 Schema 통과 자체를 사실 확인으로 사용하지 않는다. 모델에 SQL·셸·임의 파일 경로·최종 게시 승인 권한을 주지 않는다. 네트워크와 저장소는 의존성으로 주입해 fixture와 실연동을 구분한다.

기존 베이스가 제공되면 FastAPI lifespan, LangGraph 분기, MCP 클라이언트와 모델 래퍼를 재사용한다. 가상 실패·고정 지연·가상 비용·최대 시도 후 강제 통과는 운영 경로에서 제거한다. async 노드의 동기 HTTP와 불필요한 전역 잠금도 점검한다. 권장 구조는 `app/{api,domain,agent,adapters,storage,services,static,templates}`, `app/config.py`, `app/main.py`, `app/launcher.py`, `tests/{fixtures,integration}`다. 프런트는 로컬 Vue 또는 일반 JS이며 별도 빌드를 필수로 만들지 않는다.

설정은 최종 `LLM_BACKEND`를 defaults·비어 있지 않은 `.env`·비어 있지 않은 프로세스 환경변수 순서로 결정한 뒤 `defaults.json → 선택한 llm_profiles의 전송 설정 → 비어 있지 않은 .env 값 → 비어 있지 않은 프로세스 환경변수` 순서로 결합한다. profile은 공개 문서 텍스트·이미지 전송 허용값만 정하며 비밀값을 포함하지 않는다. env-map의 타입으로 변환하고 생략·빈 값은 직전 값을 유지한다. 명시한 false·0은 보존하므로 `ALLOW_EXTERNAL_DOCUMENT_TEXT=false`는 OpenAI profile의 허용보다 우선한다. `.env.example`은 여섯 준비 항목의 최소 예제이며 전체 env-map과 같은 수를 요구하지 않는다. 운영 한도나 선택 기능을 조정할 때만 해당 항목을 추가한다. 참조 구현/검사는 `checks/configuration_reference.py`와 `checks/check_configuration.py`이며 실제 앱 로더와 Adapter는 별도로 연결·검증한다.

시즌 기본값은 새 시즌 생성에만 사용한다. 기존 시즌의 학년도·기간·내보내기 키와 선택 상태는 SQLite가 관리하며 재시작 때 환경변수로 기존 시즌을 덮어쓰지 않는다. 설정 변경은 앱 재시작 후 새 작업에 적용한다. 기존 작업의 `source_config_hash`는 비밀이 아닌 실제 수집·모델 실행 설정의 정규화 해시이며 backend·model·관련 Ollama endpoint·전송 허용·게시 정책 버전·활성 규칙 ID를 포함하고 키·UI 포트·브라우저 열기 설정은 제외한다. 재개 전에 현재 설정의 해시와 대조하고 다르면 provider 초기화·호출 전에 409 `settings_changed`로 거절한다. 이전 비밀이 아닌 설정을 복원해 재개하거나 기존 기록을 유지한 채 새 작업을 만든다. 해시만으로 이전 설정을 복구할 수는 없으며 P0는 중단 작업의 모델 전환을 지원하지 않는다. 키 회전만으로는 해시가 달라지지 않는다. API 키는 환경변수와 메모리에서만 다루고 defaults.json이나 일반 설정 저장·로그·작업 snapshot·HTML에 복사하지 않는다. 키가 없는 서비스만 연결 제한으로 표시하며 앱 전체 시작이나 저장 조회·직접 입력을 막지 않는다.

## 3 데이터와 식별

| 데이터 | 보관 원칙 |
| --- | --- |
| 기관 | 내부 UUID, 자료원별 복합 코드, 주소·구·캠퍼스, 운영 상태와 근거, 사용자 정정 |
| 공식 목록 snapshot | 제공자·공식 URL·기준일·지역/유형 범위·원본 hash·완전성·수록/연결 수 |
| 시즌 | 학년도·탐색 범위·고정 export_key·시간대·지역 profile |
| 행사 | 기관/시즌에 복수 건, 불변 event_key, 유형·대상·캠퍼스/회차. 날짜는 식별키로 사용하지 않음 |
| 문서와 관측 | 내용 hash별 문서 버전, 접근/읽기 범위, 공식성 근거, 필드별 인용, 채택·보류·기각과 사유 |
| 자동 평가와 수기 | 필드별 평가 이력, ValueCheck, 활성 수기 지정, 확인 방법·실제 확인시점 |
| 작업과 실행 구간 | 고정 대상, 기관/구간/전체 한도와 누적 사용량, 호출 예약, 종료·취소 의도 |

NEIS는 교육청+학교 코드를 결합하고 다른 공급자도 실제 고유 코드를 사용한다. 대학은 캠퍼스까지 구분한다. 코드 없는 공식 파일은 자료원·유형·이름/주소로 안정적인 row key를 만들되 자료원 간 병합은 별도 대조한다. 이름만으로 병합하지 않는다.

불완전 목록은 신규 기관 보완에 사용하지만 미등재 판정에 쓰지 않는다. 완전한 목록에서 빠져도 자동 폐원·삭제하지 않고 검토 대상으로 둔다. 운영 종료는 해당 기관의 명시적 근거가 있어야 한다. closed_confirmed이고 알려진 종료일이 행사일 이전 또는 당일이면 예정 행사 게시에서 제외한다. 종료일 미상은 조사·확인 대상으로 유지하며 조용히 제외하지 않는다. 기관 연락처·이름·주소의 사용자 정정은 원본과 별도로 보호한다. 빈 응답이나 인증 실패로 기존 필드를 비우지 않는다.

DateClaim은 day/month/unknown, 알려진 DateValue는 day/month다. 후보·수기·projection 모두 이 정밀도를 유지한다. 월을 날짜로 채우거나 일 단위 값을 month로 표시하면 거절한다. 미기재 시간은 null이며 실제 자정의 시작 근거가 있을 때만 00:00이 유효하다. 학년도와 실제 연도는 원문 헤더·기간으로 연결하고 게시일이나 현재 연도로 추정하지 않는다.

입력일·사람의 실제 확인시점·수집 시도시점·성공한 원문 확인시점·재확인 시도/결과를 구분한다. 재수집 실패로 과거 문서 본문이나 확인시점을 덮어쓰지 않는다.

## 4 근거와 서버 ValueCheck

공식 API, 기관 공식 채널, 대상 기관을 명시한 공공 자료를 사용할 수 있다. `go.kr`·`ac.kr`와 이름 유사성만으로 공식성을 확정하지 않는다. 공식 목록의 홈페이지 또는 검증된 공식 링크 관계, 이를 확인한 URL과 시점을 기록한다. LLM이 공식성 DTO나 관측 채택 상태를 만들지 않는다.

문서 접근, 기대 본문·기관 확인, 후보 추출, 필드 검증과 게시를 분리한다. 각 인용은 고정 문서 hash·segment·unit에 연결한다. 떨어진 문구는 독립 Evidence 배열로 저장하고 합성하지 않는다. 정규화 후 인용의 연속 문자열 존재를 확인해도 숫자가 같은 행사·행·열을 지지하는지 별도 검사한다. 입장·학위복·하교 시간을 ceremony_start로 바꾸거나 다른 행사 시간을 섞지 않는다.

**ValueCheck는 서버가 생성하는 유일한 필드 근거 판정이다.** 등록된 rule ID와 버전, 원문 버전/hash, 관측 ID와 대상 필드의 연결, 기관·본문·시즌·행사·인용·정규값·시각 역할 검사 및 사유를 남긴다. supported라도 연결 원문이나 관측이 기각됐거나 규칙이 허용되지 않았으면 게시에 사용하지 않는다. 필수 검사를 미구현 상태에서 pass나 not_applicable로 채우지 않는다. 별도의 경쟁하는 승인 DTO를 추가하지 않는다.

정형 매핑은 NEIS의 기관/학년도/행사명/날짜처럼 의미가 검증된 레코드에서 먼저 적용한다. 비정형 문장·표의 의미를 규칙으로 확인하지 못하면 필요한 LLM 후보/검증 제안을 사용하되 서버 검사를 생략하지 않는다. 의미가 여전히 불명확하면 ambiguous로 남긴다. 한 공식 원문만으로 충분할 수 있고 여러 복제본을 다수결 근거로 사용하지 않는다.

운영 자동 규칙 허용 목록의 초기값은 비어 있다. 규칙 ID와 버전을 등록하고 같은 원문에서 정상 통과·잘못된 기관/시즌/행사/시간/인용 차단을 검사한 뒤 해당 규칙만 활성화한다. fixture의 가상 활성 규칙은 운영 검증을 대체하지 않는다. 단순히 모든 후보를 보류하는 판정도 실패다.

이미지 해석문은 원문 text가 아니다. 이미지 영역/hash는 후보 근거로 보관하되 P0 자동 게시에서는 이미지 단독을 제외한다. HWP 미리보기·부분 읽기는 범위를 표시하고 미열람 부분까지 검증했다고 하지 않는다. 충분한 텍스트나 사람의 실제 확인 없이 미리보기 단독으로 자동 게시하지 않는다.

기존 근거의 잘못된 기관·본문·합성 인용이 확인되면 관측을 기각하고 의존하는 ValueCheck와 Publication을 다시 계산한다. 원본과 정정 이력은 보존한다. 대체 유효 근거가 남으면 그 연결로 판정할 수 있다.

## 5 단일 Publication과 조회 의미

`calculate_publication(event, season, validated_context) → Publication` 하나가 확인된 값으로 최종 출력을 직접 생성한다. validated_context는 저장소·등록 규칙·검증 결과를 서버가 구성한 신뢰 경계 내부 입력이다. 클라이언트나 LLM의 `verified=true`를 신뢰하지 않는다. 요청으로 Publication이나 최종 날짜·시간·장소를 지정할 수 없다.

| 출력 | 의미 |
| --- | --- |
| `calendar_*`와 `state` | 일반 일정표에 표시 가능한 정당한 확인값과 확인 상태. 재확인 실패가 현재 사용 보류로 이어져도 유효한 과거 확인값은 남길 수 있음 |
| 필드별 permissions | 일반 표시 허용, 현재 사용 허용, 실제 확인시점, 재확인 상태와 사유 |
| `current_date_allowed` | 현재 일 단위 날짜의 사용 허용 |
| `current_time_allowed` | 현재 사용 가능한 날짜와 같은 행사·날짜에 연결된 시작 시간 사용 허용 |
| `sales_ready` | 필요한 날짜와 시작 시간이 모두 현재 사용 가능하며 행사 전체 차단 사유가 없음 |

state의 date_and_time/date_only는 일반 조회를 설명하며 판매 준비 허용과 동의어가 아니다. hold/excluded와 세부 조건은 계약 README의 정의를 따른다. 관리 화면의 effective_value/usable은 후보·수기 기록 해석용이며 최종 일정 필드로 쓰지 않는다. 월 계획은 관리 조회로 제공하되 일 단위 calendar와 판매 준비 목록에는 넣지 않는다.

차단 범위를 구분한다. 행사 식별·시즌·미해결 취소 주의는 행사 전체에 영향을 준다. 시간만 충돌하거나 시간 근거만 실패하면 날짜를 유지할 수 있다. `review_required=true`라는 이유 하나로 행사 전체를 숨기지 않는다. 장소도 확인값과 다른 문자열로 최종 출력하지 않으며, 장소 문제만으로 필수 날짜/시간을 무조건 차단하지 않는다.

실제 재확인에서 필요한 원문 근거에 접근하지 못했고 유효한 대체 근거나 사람 재확인이 없으면 해당 필드의 현재 사용을 보류한다. 과거 값·근거·실제 확인시점을 일반/관리 조회에 보존하고 실패를 눈에 띄게 표시한다. 접속 실패는 값 오류의 증거가 아니라 판매 판단을 위한 보수적 정책이다. 재확인 미수행, 보조 검색 실패, 오프라인 열람과 일부 중복 근거의 실패를 전체 필드 실패로 처리하지 않는다. 기존 근거가 무효라고 밝혀진 값은 일반 조회에도 정상 확인값으로 남기지 않는다.

P0에는 검증되지 않은 일률 TTL을 추가하지 않는다. 모든 확인은 해당 시점·자료 범위의 사실이며 최신 변경 부재를 보장하지 않는다. change_check_status와 필드별 확인·재확인 시점/상태를 함께 보인다.

## 6 수기 보호와 날짜 연결

자동 상태는 unchecked/official_confirmed/reference_only/missing/conflict다. 접근 실패와 미지원은 reason_codes와 실행 결과로 분리한다. 활성 수기 지정이 우선하되 저장 우선순위와 게시 허용을 혼동하지 않는다. clear는 빈값의 명시적 보호, release는 자동값 사용으로 복귀하는 동작이며 생략/null 메모를 삭제 명령으로 보지 않는다.

전화·문서 직접 확인값은 확인 방법과 실제 confirmed_at이 있어야 확인값으로 사용할 수 있다. 일반 신규 확인의 note는 선택이며 충돌 재확인에서만 근거 메모를 필수로 요구한다. 확인시점 미상도 저장 가능하지만 일반 일정표·판매 목록·확인율에서는 제외한다. user_recorded는 관리 메모다. 입력시점·자동 조사시점을 사람의 확인시점으로 대체하지 않는다. 월 단위 수기 확인은 월 계획으로 남긴다.

수기 문서 확인의 source_document_id는 정확한 불변 원문 버전을 가리키는 nullable 값이다. set 요청에서 생략하면 null이며 projection은 명시적으로 내려준다. 종이·오프라인 직접 확인은 null로 보관할 수 있다. URL만 남은 기존 기록은 confirmed_at 이하에 취득한 저장 버전 중 최신 버전을 선택하고 모든 과거 버전을 함께 의존 근거로 보지 않는다. 선택한 버전이 잘못된 근거로 판명되면 일반 확인값에서도 제외하되 무관한 과거 오류 버전으로 새 정상 버전의 확인을 막지 않는다. 실제 확인 이후 필요한 원문 재확인에 실패하면 일반 과거값은 보존하고 현재 사용만 보류한다. 이후의 실제 사람 재확인은 시점과 대상 근거를 남겨 다시 판정한다.

시작 시간은 같은 행사의 일 단위 bound_date에 연결한다. 현재 날짜가 month/null/충돌이거나 bound_date와 다르면 예전 시간을 보존하되 최종 시각과 현재 시간 사용을 보류한다. 날짜만 변경했다고 시간을 새 날짜에 재연결하지 않는다. UI에서 실제 재확인 후 `새 날짜에도 같은 시간임을 확인`을 선택해야 연결을 바꾼다. 날짜 한정 장소도 같은 문맥을 검사한다.

새 공식값과 수기값이 충돌하면 수기 원본을 남기고 해당 필드의 표시·사용 조건을 다시 판정한다. 공식 취소 주의는 수기 보호 때문에 숨기지 않는다. acknowledge는 알림 읽음 기록이며 해결이 아니다. 직접 재확인은 실제 방법·시점·메모와 현재 충돌 fingerprint를 필요로 한다. automatic.conflict_detected_at은 현재 fingerprint의 충돌을 처음 인지한 안정적인 시점이다. 직접 재확인시점은 이 값 이후여야 하며 단순 checked_at 갱신과 비교하지 않는다. 예전 fingerprint나 user_recorded로 해결하지 않는다. 검증된 새 근거 적용도 서버가 같은 Publication을 재계산한다. 동일 fingerprint의 정상 재확인은 conflict_detected_at과 해결 효력을 유지한다. 새로운 내용/충돌로 fingerprint가 바뀌면 최초 감지시점을 새로 기록하고 다시 확인한다.

수정 요청은 expected_revision으로 낙관적 잠금을 사용한다. 경합 시 409와 최신 revision을 반환한다. 자동 저장은 최신 수기 지정을 같은 트랜잭션에서 다시 읽고 저장·감사 이력을 함께 기록한다.

## 7 기관별 Agent와 MCP

흐름은 `load → initial_collect → assess → decide → [plan → collect → assess → decide] → resolve_and_publish → save`다.

| 단계 | 책임 |
| --- | --- |
| load | 기관/시즌·기존 근거·수기 지정·남은 예산 로드 |
| initial_collect | 공식 API와 이미 검증한 URL 우선 조회. 정형 레코드는 등록 매핑 적용 |
| assess | 본문/기관 확인 → 필요한 경우 LLM 후보 추출 → Pydantic/서버 ValueCheck |
| decide | 부족한 필드·충돌·새 경로·한도에 따라 종료 또는 추가 조사 |
| plan | 최대 3개 행동 제안, 중복 쿼리/URL 제거와 재계획 한도 적용 |
| collect | 허용된 도구로 원문/검색 실행, 문서·관측·사용량 checkpoint |
| resolve_and_publish | 현재 수기·근거·충돌로 단일 Publication 생성 |
| save | 평가·근거·판정·사용량과 정상/부분/오류/한도 결과 저장 |

정형 레코드를 조사/검증 두 모델이 매번 재해석하지 않는다. 코드가 충분·미개최·취소·유효한 다음 경로 없음·한도 도달을 판단해 종료한다. 남은 예산만을 이유로 같은 탐색을 반복하거나 한도 초과 후 강제 통과하지 않는다.

MCP Tool은 get_school_calendar, search_public_web, read_public_document이며 정식 입출력은 domain schema를 따른다. `policy://graduation/verification` Resource는 고정 규칙/버전을 시작 시 로드한다. 검색은 URL 발견 단서이고 공식성/본문 검증은 후속 단계다. 기관 CRUD와 목록 적재는 일반 Adapter/애플리케이션 코드다. 실제 호출과 trace를 남기며 장식용 endpoint로 기술 적용을 주장하지 않는다.

SDK 숨은 재시도는 끄거나 동일 계량기에 연결한다. stdio 연결 직렬화가 병목이어도 불필요한 다중 서버를 먼저 추가하지 않는다. 운영 도구는 본문과 메타정보만 반환하고 DB를 직접 갱신하지 않는다.

## 8 수집·오류와 외부 전송

P0 reader는 HTML과 텍스트 PDF다. 페이지/표의 문맥·읽은 구간과 truncation을 보존한다. 공개 URL, redirect별 주소 검사, 크기·호스트 속도 제한을 적용하고 TLS 검증을 끄지 않는다. API 인증값은 로그/화면/trace에서 제거하며 문서 내 명령은 데이터로만 취급한다.

HTTP 상태·요청/최종 URL·MIME/signature·hash·acquisition과 기대 본문/기관의 reading 결과를 따로 기록한다. 200+게시물 부재는 유효 공지가 아니고 wrong_source는 다른 기관 근거다. 미지원·부분 읽기·요청 오류·검색 결과 없음·원문 접근 실패를 합치지 않는다.

브라우저와 HWP는 대표 기관에서 병목이 확인될 때 추가하는 기본 비활성 옵션이다. 활성화 후 알려진 공개 URL을 격리된 읽기 전용 브라우저로 제한 재시도하고 HTTP 실패와 별도 관측으로 저장한다. 사용자 일반 브라우저나 로그인/비공개 채널을 사용하지 않는다. 목록 2곳 접근을 상세 탐색 완료로 확대하지 않는다. HWP 미리보기는 전체 HWP/HWPX 파서가 아니며 OCR·암호화/스캔 문서는 별도 구현 전 미지원이다.

429/일시적 5xx/전송 오류만 예산 내 재시도한다. 요청 400·인증·403·캡차·게시물 부재·미지원은 원인 해결 없이 반복하지 않는다. HTTP↔browser 무한 전환을 막고 Retry-After가 기한을 넘으면 보류한다. 도메인 필터는 선택 provider의 실제 요청 검증 후 사용한다. 기존 필터 400은 OpenAI Responses web_search 요청에서 관측했으며 Tavily 장애 증거가 아니다. 원인을 고쳐 재검증하기 전 요청 오류로 남긴다.

LLMProvider는 ollama/openai/fake를 분리하고 최종 `LLM_BACKEND`의 Adapter만 초기화·검사한다. OpenAI 선택에는 Ollama 연결이나 모델 설치가 필요하지 않으며 Ollama 선택에는 OpenAI 키가 필요하지 않다. 초기값은 ollama이고 OpenAI 기본 모델은 `gpt-6.1-sol`이다. `OPENAI_FAST_MODEL`은 선택적 재정의이며 `OPENAI_QUALITY_MODEL`이 비어 있으면 fast 모델을 재사용한다. 기존 qwen 재현값과 OpenAI 시작값의 정확성·실제 PC 처리시간은 별도 검증한다. 외부 모델 문서 해석은 제공된 probe에서 실행되지 않았으며 모델 간 우열을 현재 증거로 정하지 않는다. 키 누락·연결 오류·호출 실패 시 다른 백엔드나 demo/fake로 자동 대체하지 않는다.

기본 외부 전송값과 ollama/fake profile은 텍스트·이미지 모두 false이며 openai profile만 공개 문서 텍스트를 true로 둔다. `LLM_BACKEND=openai` 선택은 필요한 공개 원문 구간을 OpenAI로 보내는 선택이다. 키 입력만으로 선택·전송을 허용하지 않는다. 실제 전송은 profile에 `.env`·프로세스 환경변수의 `ALLOW_EXTERNAL_DOCUMENT_TEXT`/`ALLOW_EXTERNAL_IMAGES`를 결합한 최종 허용값과 실행환경 조건을 확인한다. 명시적인 false나 승인 거절이면 payload 없이 blocked를 기록한다. 이미지 기본값은 모든 profile에서 false이며 사적 전화 메모는 텍스트 허용에 포함하지 않는다. 공개 검색어와 문서 payload도 구분한다. 별도 승인 관리 UI는 P0 요구가 아니다. Ollama의 명시적 loopback endpoint는 LLM Adapter에서만 허용하고 공개 문서 reader의 내부 주소 차단을 완화하지 않는다. 사용자 지정 원격 Ollama endpoint에도 외부 전송 검사를 적용한다.

## 9 전체 큐·예산·재시작

기관 대상은 생성 시 고정해 job_items에 저장한다. 전체 조사가 화면 페이지나 관심 목록으로 잘리지 않게 한다. 후속 기관 추가는 기존 작업 분모를 바꾸지 않는다. 기관 식별·시즌·한도 snapshot과 `source_config_hash`를 고정하고 재개 때 UI 설정으로 바꾸지 않는다. 수집·모델 설정의 정확한 해시 투영은 `source_configuration_hash` 참조 함수를 따르며 비선택 모델 설정·시즌·실행 한도는 제외한다. 필요한 인증키는 실행 환경에서 읽고 snapshot에 보관하지 않는다. 같은 대상 활성 작업·idempotency 충돌과 재개 설정 불일치는 409로 안내한다. 설정 불일치는 `Error.code=settings_changed`, `details.reason_codes=[configuration_required]`이며 작업 paused_reason에 새 enum을 만들지 않는다.

기관별/실행 구간/작업 전체의 시간·검색·문서·HTTP·LLM·토큰 한도를 적용한다. 구간 소진은 paused이며 전체/기관 누적은 유지한다. job 한도 소진은 명시적 한도 상향 없이 재개하지 않는다. 사용량·예약·재계획 횟수를 재시작으로 초기화하지 않는다. 호출은 남은 기한과 예산을 원자적으로 확인·예약하고 실제 사용량으로 정산한다. 미확인 응답은 예약분을 보수적으로 남긴다. 가격 근거가 없으면 비용은 미산정이며 가상 단가를 넣지 않는다.

redirect·실패·재시도도 실제 네트워크 계량에 포함한다. 캐시 재사용은 새 호출이 아니다. 로컬 모델 동시성은 별도 한도를 적용한다. 기본 설정은 운영 성능 측정 결과가 아니며 표본 사용량으로 조정한다. 네트워크 중 SQLite 쓰기 트랜잭션을 유지하지 않는다.

멈춤은 신규 시작을 막고 진행 중 호출을 기한 내 정산·checkpoint한 뒤 paused로 전환한다. 종료/충돌로 중단된 항목은 기존 문서·사용량을 남긴 pending으로 복구한다. 재개는 기관 그래프 처음에서 저장 근거를 로드하되 누적 한도를 유지한다. done/failed 항목을 resume으로 자동 재실행하지 않는다.

**취소 의도는 영속 상태다.** cancel 수락 시 cancelling을 저장하고 신규 호출을 막는다. 미착수/미완료 항목을 cancelled로 정리하며 이미 저장된 유효 결과와 사용량은 보존한다. 늦은 응답이 도착해도 취소 작업을 running/completed로 되살리지 않는다. 재시작은 terminal 상태를 보존하고, cancelling은 정산 후 cancelled로 복구한다. 취소 의도가 없는 running/pausing은 남은 항목이 있으면 paused(interrupted), 모든 항목이 이미 처리 종결됐으면 completed다. 참조 복구 함수도 all_items_done을 받아 이 차이를 검사하고 취소를 먼저 판정한다. cancelled는 resume할 수 없고 새 의도의 조사는 새 작업이다.

done은 정해진 조사를 정상 종료했다는 뜻이며 날짜/시간 확인과 별개다. 일부 기관 실패는 격리해 나머지를 계속하고 복구 불가 시스템 실패만 job failed로 둔다. 프로세스 중단 중 불확실한 호출은 예약 시간/토큰을 보수 정산한다. 꺼져 있던 시간을 활성 시간에 더하지 않는다. SQLite WAL·foreign_keys·busy_timeout, 짧은 쓰기 직렬화, uvicorn 1 worker/reload 꺼짐을 사용한다. 브라우저 수명과 작업 task를 분리하며 P0 진행 표시는 polling이다.

## 10 API·집계·HTML

API 요청/응답은 OpenAPI 계약을 구현하고 단일 Error 객체를 사용한다. 404는 없는 ID, 409는 revision/활성 작업/idempotency 충돌, 422는 형식·업무 불변조건, 503은 필요한 설정/기능 사용 불가다. 목록은 cursor/limit과 정해진 정렬을 사용한다. 조회 목적은 같은 Publication의 표시 선택이며 별도 판정기를 두지 않는다.

확인할 목록은 기관 목록을 기준으로 행사·미연결 후보·최신 실행 결과를 left join한다. 행사 0건도 조사 전/자료 미발견으로 남긴다. 명시적 미개최는 다른 미해결 후보가 없을 때 일반 전화 확인 목록에서 제외할 수 있지만 전체 기록에는 남긴다.

모든 지표는 같은 read snapshot·content_revision·정책 버전으로 계산한다. 분모는 시즌 대상 등록 기관 수이고 0이면 비율은 null이다. 날짜 확인은 current_date_allowed, 시간 확인은 current_time_allowed를 충족한 고유 기관으로 센다. 시간은 허용된 같은 행사/날짜가 필요하다. 날짜만 허용된 기관은 날짜 분자에 포함될 수 있지만 sales_ready는 false다. 월·후보·기각 근거·과거 일반 조회값만 남은 항목은 분자에서 제외한다. 복수 행사는 기관 수를 늘리지 않는다. 취소/미개최·행사 전체 보류는 예정 확인 분자에서 제외한다. 공식/전화/문서 provenance별 수는 겹칠 수 있으므로 합산하지 않는다. 목록 불완전은 등록 기관 기준이라고 표시한다.

일반 일정표·판매 필터·HTML·지표는 동일 Publication만 소비한다. 값은 확인값에서 직접 생성해 장소까지 일치시킨다. 모델이 최종 표를 재작성하지 않는다. source 확인/기각·재확인 결과·수기 변경 등 판정에 영향을 주는 변경은 content_revision과 export 갱신 대상이다. polling과 사용량만의 변경은 올리지 않는다.

내보내기는 한 snapshot에서 렌더링해 임시 파일 후 atomic replace한다. 생성시점·revision·정책·필드 확인방법/시점·재확인 상태·공식 목록 확보 현황을 담는다. 생성 중 새 변경은 낮은 revision을 최신으로 표시하지 않고 다시 갱신한다. 실패 시 같은 정책의 마지막 정상 파일과 DB를 보존하되 파일 갱신 필요를 표시한다. 구정책/미상 정책 파일은 4.0의 현재 일정 URL로 제공하지 않는다. 사적 메모·원문 전문·키는 기본 제외한다. 불신 문자열은 escape/textContent로 렌더링하고 script 종료 문자열도 안전하게 처리한다. 허용된 자체 필터 스크립트는 동작하되 불신 입력 스크립트 실행은 금지한다. 외부 CDN·폰트·JSON fetch 없이 오프라인에서 열린다.

## 11 로컬 실행과 마이그레이션

P0는 `python -m app`이 설정/지속 데이터 준비 → 서버 기동 → readiness → 브라우저 열기를 맡는다. 키가 없어도 저장 조회·직접 입력은 시작한다. package 자산과 사용자 DB·근거 캐시·로그·백업·HTML을 분리하고 platformdirs의 지속 경로에 live/demo 하위 디렉터리를 사용한다. 임시 압축 해제 위치를 기본 DB로 쓰지 않는다.

서버는 loopback만 허용하고 실행별 토큰·Host/Origin 검사로 변경 요청을 보호한다. API 키를 화면·HTML에 주지 않는다. CORS 전체 허용과 불필요한 학생 명단 저장을 하지 않는다. tracing은 기본 꺼짐이며 활성화해도 키·사적 메모·원문 전문을 무조건 보내지 않는다. 포트 점유는 다른 loopback 포트로 처리하고, 중복 실행은 앱 식별을 확인해 기존 화면을 연다. 종료 전 checkpoint하며 취소 상태는 위 규칙을 유지한다.

기존 2.0·2.1·3.0 DB는 SQLite backup API로 백업하고 버전별 migration을 적용한다. 실제 수기값·확인시점·기각 이력·원문 hash를 보존한다. 빠진 rule 버전·공식성·원문 연결·확인시점을 만들어 채우지 않는다. 새 증명이 부족한 자동값은 reference_only로 보존 후 재검증한다. 기존 수기값도 4.0의 실제 확인시점·날짜 연결·충돌 조건을 적용한다. 마이그레이션 전후 예제를 검사하고 미상/이전 정책 export는 보관하되 새 정책으로 재생성하기 전 현재 URL을 제공하지 않는다. migration 실패 시 원본 DB를 보존한다.

Windows 실행파일은 P2다. 실제 Windows/CI에서 빌드·설치·모델 설치·처리시간·업데이트 후 데이터 보존을 검사한다. frozen MCP는 전용 실행 모드에서 프로토콜만 stdout으로 출력하고 앱 서버/브라우저를 재귀 실행하지 않는다. 개발 Mac에서 모델을 호출했다는 사실로 어머니 PC 배포 완료를 주장하지 않는다.

## 12 검증과 한계

필수 정상 사례와 네 반례를 단일 판정기에 통과시킨다. 미해결 행사 식별, 미해결 취소 주의, confirmed_at 없는 수기 충돌 해결, 확인값과 다른 장소 출력은 차단한다. 날짜+시간, 날짜만, 실제 확인시점과 현재 fingerprint를 가진 정당한 재확인은 허용한다. 시간만 충돌한 경우 날짜를 남기고 전부 보류하는 구현은 실패시킨다. 재확인 실패·대체 근거·기각 전파·취소 재시작도 검사한다.

참조 검사·Schema·SQL·OpenAPI의 정합성은 실제 웹 자료의 정확성과 다르다. 자료원 실연동, 날짜 미지정 탐색, 정상/오류 원문 종단 결과와 실제 PC는 별도 증거로 보고한다. Pydantic validator 안에서 네트워크를 호출하지 않으며 의미 검증은 서비스가 수행한다.

공개되지 않은 일정, 원문 오기, 전화 착오, 사후 변경과 탐색 밖 정정은 남는다. 현재 사용을 보수적으로 보류하면 활용 가능한 일정이 줄어드는 비용이 있다. 원문·확인시점·범위·미해결 사유로 설명하며 전체 무오류를 보장하지 않는다. 기능 완성도·기술 역할·한계의 증거를 남기되 PPT/발표와 Before/After 비교 시스템은 개발 완료 조건에 넣지 않는다.
