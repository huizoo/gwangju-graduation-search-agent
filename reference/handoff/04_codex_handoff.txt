광주 졸업식 일정 도우미를 버전 4.0 명세와 계약에 따라 구현하세요.

이 패키지는 명세·계약·실행 가능한 참조 검사입니다. 실제 FastAPI 앱이나 전체 Agent가 이미 구현됐다는 뜻이 아닙니다. 이 파일은 인계 문서이며 실제 작업 지시는 사용자의 요청과 작업 공간 지침을 따릅니다.

읽기 순서
README → 변경 내역 → 01_product_plan → 02_technical_design → 실행 근거 문서 → contracts/README와 domain.schema/openapi/schema.sql → 06_acceptance → 03_setup_guide와 05_sources.
기존 베이스와 과제 원문은 실제 제공된 파일이 있을 때 읽으세요. 파일이 없다고 내용을 추정하거나 불필요하게 다른 프로젝트를 탐색하지 마세요. 사용자 변경과 원본 자료를 보존하고 비밀값을 출력·커밋하지 마세요.

구현의 단일 기준
- 계약/정책 버전은 4.0입니다. 객체와 열거형은 domain.schema, P0 요청/응답은 openapi, DB는 schema.sql, 교차 객체 규칙은 contracts/README를 적용하세요.
- DateClaim은 day/month/unknown, 알려진 DateValue는 day/month입니다. 후보·수기·projection 전 경로에서 정밀도를 유지하고 월을 날짜로 채우지 마세요.
- 등록 정형 매핑 → 필요한 경우 LLM 후보 추출/의미 제안 → 서버 ValueCheck → calculate_publication → 저장/조회 순서로 연결하세요. NEIS의 명확한 행을 모델 두 역할이 매번 재해석하지 않게 하세요.
- 서버 ValueCheck는 rule ID와 버전, 문서 hash/버전, 관측과 필드 연결 및 실제 검사 결과를 기록합니다. 공식성 근거와 관측의 채택/보류/기각 사유를 함께 검사하세요. 모델의 confidence·동의·accept를 최종 승인으로 쓰지 마세요.
- 초기 운영 자동 규칙 허용 목록은 빈 배열입니다. 같은 규칙의 양성과 반례를 검증한 뒤 그 ID·버전만 활성화하세요. fixture 규칙은 테스트 전용이며 전부 보류하는 판정도 실패입니다.
- calculate_publication(event, season, validated_context) → Publication 하나가 확인값으로 최종 값을 생성합니다. validated_context는 서버가 저장 근거와 등록 검사를 통해 구성하며 클라이언트/LLM이 승인 상태를 주입할 수 없습니다.
- API·일반 화면·판매 준비 목록·HTML·확인율은 같은 snapshot/revision/정책의 Publication을 사용합니다. 별도 화면 검증기나 최종 표를 다시 쓰는 LLM을 추가하지 마세요.

조회 의미
- 일반 조회는 정당하게 확인했던 일 단위 날짜와 연결 시각을 확인 방법·시점과 함께 표시합니다. Publication.calendar_*가 이 일반 조회용 값입니다.
- 필요한 근거의 실제 재확인에 실패했고 유효한 대체 근거나 사람 재확인이 없으면 해당 필드의 현재 사용을 보류하되 유효한 과거 값은 실패 표시와 함께 일반 조회에 남깁니다.
- 재확인 미수행·보조 검색 실패·오프라인 열람·일부 중복 출처의 실패를 기관 전체 차단으로 바꾸지 마세요.
- 판매 준비 목록은 현재 사용 가능한 일 단위 날짜와 같은 행사/날짜의 실제 시작 시간을 갖는 sales_ready=true만 포함합니다. date_and_time 상태 자체로 판매를 허용하지 마세요.
- 관리 기록은 월 계획·후보·확인시점 미상 메모·기각 근거와 이력을 상태별로 보관합니다. effective_value/usable은 게시 승인과 다릅니다.
- 잘못된 기관/합성 인용처럼 기존 근거가 무효임이 밝혀지면 관측과 의존 평가를 기각/재계산합니다. 다른 유효 근거가 없다면 일반 조회에서도 정상 확인값을 제거하세요. 원본 이력은 남깁니다.

수기와 충돌
- 전화/문서 직접 확인은 확인 방법과 실제 confirmed_at이 필요합니다. 일반 신규 확인의 note는 선택이며 충돌 재확인에만 근거 메모를 필수로 하세요. 미상 시점은 저장하되 관리 기록으로 남기고 입력일을 확인일로 채우지 마세요.
- 수기 보호는 저장 원본을 지키는 규칙이며 게시 검사 면제가 아닙니다. acknowledge는 알림 읽음이고 충돌 해결이나 게시 재개가 아닙니다.
- 직접 재확인은 방법·실제 확인시점·근거 메모와 현재 충돌 fingerprint가 필요합니다. 확인시점은 automatic.conflict_detected_at 이후여야 합니다. 이 값은 현재 fingerprint의 최초 감지시점으로 유지하고 checked_at 갱신만으로 해결을 취소하지 마세요. fingerprint가 바뀌면 감지시점을 새로 기록하며 이전 해결 기록으로 새 충돌을 해결하지 마세요.
- 문서 확인의 nullable source_document_id로 실제 확인한 불변 버전을 연결하세요. set 요청 생략은 null이며 종이/오프라인 확인도 가능합니다. URL만 있는 기존 기록은 confirmed_at 이하 취득 버전 중 최신을 선택하세요. 선택 버전의 무효는 일반 게시도 막지만 무관한 과거 오류 버전이 새 정상 확인을 막아서는 안 됩니다. 실제 확인 이후 필요한 근거 재확인 실패는 과거값을 보존하고 현재 사용만 보류하며 새 사람 확인으로 다시 판정합니다.
- 시간만 문제면 날짜는 유지할 수 있습니다. 행사 식별/미해결 취소 주의처럼 행사 전체에 영향을 주는 문제와 필드별 보류를 구분하세요.
- 시간은 확인된 일 단위 bound_date에 연결하세요. 날짜 변경/기각 뒤 예전 시간을 새 날짜에 합치지 마세요. 장소도 확인값과 다른 최종 값으로 바꾸지 마세요.

P0 순서
1. 단일 Publication과 정상/반례 참조 검사를 먼저 연결합니다. 미해결 행사 식별, 취소 주의, confirmed_at 없는 수기 해결, 확인값과 다른 장소 출력을 차단하고 정상 날짜+시간/날짜만/정당한 재확인은 통과시킵니다.
2. 계약 모델·SQLite·설정과 live/demo 분리·단일 런처를 만듭니다. 전체 대상 유형의 공식 API 또는 공식 파일 적재 경로와 목록 완전성을 연결합니다.
3. NEIS 인증·전체 기간/페이징, 공개 검색, HTML·텍스트 PDF를 연결합니다. 날짜를 모르는 기관 탐색 → 오류 차단 → 정상 게시의 최소 종단 흐름을 실제 앱 도구로 확인합니다.
4. 수기 보호·일반/판매/관리 조회·기관 기준 확인 목록과 기관별 LangGraph의 조건부 추가 조사를 연결합니다.
5. 고정 전체 큐·누적 예산·idempotency·멈춤/재개·취소와 재시작을 연결합니다. 취소 의도는 영속화하고 재시작의 cancelling은 cancelled로 정리합니다. 취소 의도가 없으면 all_items_done에 따라 completed/paused를 구분합니다. cancelled를 paused로 되살리거나 resume하지 않습니다.
6. 한 snapshot의 집계와 HTML export, 오프라인 필터·안전한 출력·재시작 보존을 확인합니다.
7. 대표 기관 시험에서 확인된 병목에 한해 브라우저/HWP/OCR 등 도구를 확장합니다. 기본값은 비활성이며 P0 필수 경로로 먼저 넣지 않습니다.

설정·모델·외부 전송
LLM_BACKEND=ollama/openai로 백엔드를 선택하고 해당 Adapter만 초기화·검사하세요. 초기값은 Ollama입니다. OpenAI 선택에는 Ollama 실행/설치를 요구하지 않고, Ollama 선택에는 OpenAI 키를 요구하지 마세요. OpenAI 기본 모델은 config의 gpt-6.1-sol이며 quality가 비어 있으면 fast 모델을 재사용합니다. 모델 기본값은 정확성 우위나 실제 PC 성능의 증거가 아닙니다. Mac의 Ollama 앱이 서비스를 실행하면 ollama serve를 중복 실행하지 않습니다.

키 입력만으로 백엔드가 바뀌지 않습니다. LLM_BACKEND=openai 선택은 공개 문서의 필요한 텍스트 구간 전송을 허용하는 선택이며 이미지·사적 수기 메모를 포함하지 않습니다. ollama/fake profile은 외부 전송 false, openai profile만 공개 문서 텍스트 true이고 명시한 ALLOW_EXTERNAL_DOCUMENT_TEXT=false가 우선합니다. 최종 허용값과 실행환경의 승인/거절을 지키고 거절 payload는 보내지 마세요. 기존 probe의 OpenAI 원문/이미지 해석은 실행되지 않았습니다. 장애·키 누락 시 다른 백엔드나 demo/fake로 자동 전환하지 마세요. 저장 조회·수기·fixture와 독립 가능한 기능은 유지하고 실연동은 미완료로 보고하세요.

API·DB·내보내기
비밀이 아닌 전체 기본값은 config/defaults.json, 선택적 환경변수 목록은 config/env-map.json으로 관리하세요. 최종 LLM_BACKEND를 defaults/.env/프로세스 환경변수 우선순위로 먼저 결정한 뒤 defaults → 해당 llm_profiles의 전송 설정 → 비어 있지 않은 .env → 비어 있지 않은 프로세스 환경변수 순서로 병합하세요. 생략·빈 값은 이전 값을 유지하고 false·0은 보존한 뒤 허용 범위를 검사하세요. .env.example은 여섯 준비 항목만 담고 전체 env-map을 필수 입력으로 만들지 않습니다. 설정 변경은 앱 재시작 후 새 작업에 적용하세요. 기존 작업 재개는 source_config_hash와 현재 비밀이 아닌 수집·모델 설정 해시가 같을 때만 허용하고 다르면 provider 초기화·호출 전에 409 settings_changed로 거절하세요. 키·UI 포트·브라우저 열기 설정은 해시에서 제외하고 backend/model/관련 Ollama endpoint/전송 정책/게시 정책 버전/활성 규칙 ID는 포함합니다. 해시로 이전 설정을 복원한다고 가정하지 마세요. 이전 설정 복원 또는 기록을 유지한 새 작업 생성으로 안내하고 snapshot을 덮어쓰지 마세요. API 키는 환경변수/메모리에서만 다루고 defaults·일반 JSON·작업 snapshot·로그·HTML에 저장하지 마세요. 특정 키가 없으면 해당 서비스의 제한만 표시하세요. 기존 시즌은 SQLite가 관리하고 config의 시즌 기본값은 새 시즌에만 사용하세요. checks/configuration_reference.py와 checks/check_configuration.py는 사양 참조이며 실제 앱 로더와 Adapter에도 연결·검증해야 합니다.

기본 설정과 env 이름을 실제 config에 연결하고 런타임 Pydantic/OpenAPI와 제공 계약을 비교하세요. 네트워크는 Pydantic validator 밖의 서비스에서 수행합니다. 2.0/2.1/3.0 DB가 있으면 먼저 백업하고 수기·근거·기각·시점을 보존하는 migration을 작성하세요. 없는 증명을 supported로 만들지 말고 부족한 자동값을 reference_only로 둡니다. 이전/미상 정책 export는 보관하되 4.0으로 재생성하기 전 현재 일정 URL로 제공하지 마세요.

날짜/시간 확인율은 current_date_allowed/current_time_allowed를 충족하는 고유 기관으로 계산합니다. 일반 조회에만 남은 과거 값·월 계획·후보·취소/미개최는 확인 분자에서 제외합니다. 날짜만 허용된 기관은 날짜 지표에 들어갈 수 있어도 판매 준비는 false입니다. 공식 운영 종료가 확인되고 종료일이 행사일 이전/당일이면 해당 예정 행사는 제외하며 종료일 미상은 조사 대상으로 남깁니다. 분모는 시즌 대상 기관이고 0이면 비율은 null입니다. 목록 미완전 시 등록 기관 기준이라고 표시하세요.

HTML은 일반 코드와 고정 템플릿으로 생성합니다. 외부 CDN/fetch 없이 오프라인으로 열리고 자체 필터는 동작하되 불신 입력의 스크립트 실행은 막으세요. 생성시점·revision·정책·필드 확인시점/재확인 상태를 포함하고 키·원문 전문·사적 메모는 기본 제외합니다.

실행·완료 보고
python -m app 한 명령으로 지속 데이터 준비·서버·브라우저를 여는 P0 런처를 마련하세요. loopback, 중복 실행, 포트 점유와 checkpoint 종료를 처리하고 패키지 자산/사용자 데이터를 분리하세요. Windows 실행파일과 frozen MCP 모드는 P2이며 실제 Windows 검증 전 배포 완료라고 부르지 마세요.

기능 완료·자료원 실연동·전체 목록 확보를 나눠 보고하세요. 계약·반례·정상 결과, 실제 기관 날짜/시간 현재 허용 건수와 수기 필요 건수, 수기 보호/취소 복구/HTML 결과, 실제 설정·실행법·데이터/백업 경로와 남은 한계를 포함하세요. 실제 측정하지 않은 성과를 쓰지 마세요. PPT/발표 준비와 Before/After 보너스 비교 시스템은 개발 완료 조건에 넣지 않습니다.

기존 증거의 해석
기존 probe는 사람 선정 URL/사례별 개별 작업입니다. 동봉 원본 집계에서 검색 제공자는 OpenAI Responses web_search로 확인되며 Tavily 실연동 증거가 아닙니다. 도메인 필터 HTTP 400 원인은 미해결입니다. HTTP URL 10개는 기관 10곳 표본이 아니고, NEIS는 샘플/알려진 날짜 조회였습니다. 브라우저 목록 읽기를 실패 상세 URL 수집으로 확대하지 마세요. 모델 결과는 초기/재시도 일부 중복 사례이며 전체 정확도나 외부 모델 비교로 일반화하지 마세요. 실행 근거 문서의 파일·hash와 범위를 확인하세요.
