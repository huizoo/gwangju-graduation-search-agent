# 공식 자료와 외부 연결

통합 명세 4.0, 기준일 2026-10-20. 이 문서는 예정 자료원, 기존 독립 실험에서 실행한 연결, 앞으로 구현·검증할 앱 Adapter를 구분한다. 자료원 실험은 동봉한 기존 증거를 인계한 것이며, 설정 보완에서는 Ollama 실행 방식과 OpenAI 기본 모델의 공식 안내를 확인했다. 새 인증키 사용·유료 모델 요청·원문 외부 전송은 하지 않았다. 문서나 API의 존재는 최신 광주 전체 목록 확보와 일정 정확성의 증거가 아니다.

## 2 NEIS Adapter 경계

예정 기본 URL은 `https://open.neis.go.kr/hub`이고 `schoolInfo`, `SchoolSchedule`을 사용한다. 기본 인자는 `KEY`, `Type`, `pIndex`, `pSize`다. 기관·기간 조건은 서비스별 명세와 실제 응답에 맞춘다. LLM이 endpoint·기관 코드·인증 쿼리를 생성하지 않는다. 인증키는 백엔드에 보관하고 로그·원문 URL·trace에서 제거한다.

기존 실험은 인증키 없는 5행 샘플이었다. 넓은 기간을 넣어 받은 처음 5행과, 이미 알고 있던 `AA_YMD=20270120`을 넣어 받은 첨단고 졸업식 행은 전체 기간 탐색의 증거가 아니다. 해당 졸업식 레코드에는 시작 시각이 없었으므로 날짜 확인과 시간 확인을 따로 처리한다. `CalendarResult`에는 인증·발견 방식과 실제 전체 페이지 완료 여부를 표시한다.

앱에서는 인증키로 전체 페이지와 총건수를 대조하고 정상 0건·인증 실패·제한 초과·서버 오류를 구분한다. 학교 기본정보는 정규 기관 객체로 옮기고, 학사일정 행은 원문 버전·hash·JSON 경로·비밀값을 제거한 조회 조건으로 보존한다. 선택 항목 누락은 누락으로, 필수 응답 계약의 변경은 계약 오류로 기록한다. 어느 경우도 값을 만들어 채우지 않는다.

명확한 정형 레코드는 등록·시험한 매핑으로 먼저 처리한다. 매핑이 기관·시즌·졸업 행사·날짜와 시간의 의미를 확인할 수 있으면 모델 두 역할로 같은 행을 재해석할 필요가 없다. 규칙이 지원하지 않는 내용에만 후보 추출이나 추가 탐색을 요청한다. 실제 규칙 활성화 전에는 정형 API 호출 성공만으로 자동 게시를 허용하지 않는다.

## 3 유치원·어린이집·대학 목록

유치원 일반현황의 예정 API 경로는 `/api/notice/basicInfo2.do`다. `key`, `sidoCode`, `sggCode`, `pageCnt`, `currentPage`, `timing`과 `kinderCode` 등 실제 승인 명세의 항목을 확인해 Adapter를 고정한다. 공시차수·자료 기준·전체 페이지와 지역 코드/주소를 대조한다. 운영시간을 졸업식 시작 시간으로 해석하지 않는다.

어린이집은 승인된 서비스별 endpoint·시설코드·인증·페이징을 설정에 고정한다. 보육정보공개포털의 키와 공공데이터포털 서비스키가 서로 교환 가능하다고 가정하지 않는다. API가 준비되지 않았다면 실제 확보하고 범위를 확인한 공식 파일을 대안으로 사용할 수 있다. 파일도 확보하지 못하면 `목록 확보 필요`로 남긴다.

대학 자료는 대학·본분교·대학원 등 원본 행과 기관/캠퍼스의 관계를 먼저 확인한다. 대학원마다 다른 대학으로 세거나 이름만으로 캠퍼스를 합치지 않는다. 공식 식별자·주소·기관 관계로 정규화하고 불명확한 관계는 검토 대상으로 남긴다.

공식 파일은 원본·hash·출처 URL·자료 기준일·유형/구 범위를 저장하고 `RegistryImport` 계약으로 가져온다. 일부 파일·표본·검색 결과 수는 전체 기관 수가 아니다. 전체 대상 건수를 제공자가 제시하지 않으면 `expected_total=null`과 실제 범위 근거를 남긴다. 중복·지역 밖·해석 불가 행을 별도로 집계한다. 목록 완전성이 미확인인 상태의 확인율은 등록된 대상 범위의 수치로 표시한다.

## 4 검색 제공자와 날짜의 의미

앱의 검색 제공자는 `config/defaults.json`을 따른다. Tavily를 연결할 경우 서버에서 인증하고 URL 발견 뒤 document reader로 원문을 읽는다. 검색 응답의 요약이나 출처 링크 자체로 공식 원문 확인을 대체하지 않는다. 제공자별 도메인 제한 문법과 지원 여부는 실제 연결 시험으로 확인하며, 도구가 오류를 반환하면 `not_found`가 아닌 해당 오류로 기록한다.

실제 독립 실험은 **OpenAI Responses의 `gpt-4.1-mini`와 `web_search`**를 사용했다. 제공자는 `evidence/probe-summary.json`, 요청 모델은 `evidence/probe-search-request-source.txt`와 원본 소스 hash로 확인한다. 전남대 질문에 전북대 출처가 반환됐고 어린이집 검색에서는 출처를 확보하지 못했다. 도메인 필터 요청 2건의 HTTP 400은 당시 요청 설정의 관측이다. 정확한 원인 해결과 재시험은 하지 않았으므로 기능 자체가 불가능하다고 단정하거나 Tavily 문제로 해석하지 않는다. 제공자를 바꾸는 것만으로 기관 식별·날짜·시간 오류가 해결됐다고 간주하지 않는다.

검색의 게시·갱신일과 행사 개최일은 다르다. 시즌 이전에 게시된 연간 학사일정도 후보가 될 수 있다. 게시일이 최근이라는 이유로 과거 행사를 현재 일정으로 채택하지 않는다. 자료 기준일·공시차수·학년도·행사일·수집 시각·사람의 실제 확인 시각은 구분해 저장한다.

## 5 모델 연결과 원문 전송

P0는 Ollama/OpenAI 선택 Adapter를 구현하고 초기 선택인 Ollama로 실제 종단 흐름을 먼저 검증한다. `LLM_BACKEND`로 선택한 경로만 초기화·검사하고 비활성 경로의 키나 서버를 요구하지 않는다. [Ollama 공식 FAQ](https://docs.ollama.com/faq)는 Mac의 로그인 항목과 백그라운드 실행 설정을 안내한다. Ollama 앱이 서비스를 실행하면 `ollama serve`를 중복 실행할 필요가 없다. OpenAI 시작 모델은 공식 모델 문서의 [gpt-6.1-sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)이며 quality 미설정 시 같은 모델을 재사용한다. 기존 로컬 호출 성공과 모델 문서 확인은 일정 추출 정확성·어머니 PC 처리시간의 증거가 아니다. OpenAI 문서 해석은 실제 실행하지 않아 성능상 우열을 정할 수 없다. 선택 모델의 ID·지원 입력·구조화 출력·시간 제한·실제 PC 자원은 preflight와 대표 사례에서 확인한다.

외부 전송의 기본값과 ollama/fake profile은 텍스트·이미지 모두 `false`다. `LLM_BACKEND=openai` 선택은 공개 문서의 필요한 텍스트 구간을 OpenAI로 보내는 선택이며 해당 profile의 텍스트만 `true`다. 키 보유만으로는 선택이나 전송 허용을 바꾸지 않는다. 명시한 `ALLOW_EXTERNAL_DOCUMENT_TEXT=false`가 profile보다 우선하며 이미지 기본값은 모든 profile에서 false다. 사적 수기 메모·불필요한 개인정보는 제외하고 실행 환경의 별도 승인 요구도 따른다. 원격 Ollama 주소도 외부 전송 검사 대상이며 로컬 profile을 우회 수단으로 쓰지 않는다. 미설정·미허용·미지원·호출 실패를 구분하고 가능한 정형 처리·기존 조회·수기 확인은 계속한다. 다른 백엔드나 demo로 조용히 전환하지 않는다.

기존 실험의 OpenAI 문서/이미지 추출은 구체적인 전송 승인 부재로 자동 승인 검토에서 거절됐고 요청을 실행하지 않았다. 기관명·검색어를 보내는 검색 호출과 구분한다. 실제 문서 해석은 로컬 `qwen3:8b` 텍스트 6건과 `qwen3.5:2b` 이미지 2건, 지침 보완 후 같은 사례 중 4건이었다. 모든 사례의 전체 검사에는 오류가 남았지만 일부 날짜·시간은 맞았다. 8+4회는 독립 기관 12곳이나 일반 모델 정확도 측정이 아니다.

## 6 읽기 기능과 게시 권한의 경계

HTTP 대상 URL 10개 중 기대 자료 6개, HTTP 200 본문 불일치 1개, TLS/연결 실패 3개를 관측했다. 확보한 PDF 2개는 URL 10개에 이미 포함된다. 브라우저는 통합 학사일정 목록과 어린이집 공시 DOM을 읽었으며, 실패한 상세 일정 전부를 확보한 것은 아니다.

텍스트 PDF 2개, HWP5 미리보기 1개와 이미지 2개의 읽기 경로를 확인했다. HWP 성공 범위는 810자의 `PrvText`이며 전체 BodyText·HWPX·암호화 형식이 아니다. 이미지 모델 응답은 의미 검증이나 정확성 보장의 근거가 아니다. 앱 P0는 NEIS·HTML·텍스트 PDF부터 연결하고 브라우저/HWP는 대표 기관에서 확인된 병목에 따라 추가한다. 기존 전용 브라우저 도구가 앱 또는 Windows 배포에 이미 포함됐다고 가정하지 않는다.

자동 검증은 활성화된 규칙 ID·버전, 공식성 근거, 원문 버전/hash, 관측과 대상 필드의 연결을 확인한 서버 `ValueCheck`로 기록한다. 최종 일반 조회와 현재 사용 권한은 하나의 `calculate_publication` 결과를 사용한다. LLM 동의·신뢰도·스키마 통과만으로 확인값을 만들지 않는다. 정확한 계약과 판정 조건은 기술 설계·domain 계약·게시 정책을 따른다.

원문 재확인 실패는 기존 값의 오류를 증명하지 않는다. 기존에 정당하게 검증했던 값은 확인 시각과 재확인 실패 표시를 붙여 일반 조회할 수 있다. 현재 사용을 보류할지는 필드별 필수 근거의 실패와 유효한 대체 근거/사람의 재확인 여부로 결정한다. 잘못된 기관·합성 인용 등 근거 자체의 오류가 확인되면 해당 관측을 기각하고 의존하는 판정을 재계산한다. 후보·기각 기록은 관리 이력에서 보존한다.

MCP와 Pydantic은 도구 계약·타입·작성한 검증 규칙을 강제하는 수단이다. 원문의 진실·미공개 정보·수집 후 변경은 보장하지 않는다. 기존 probe가 실제 앱의 MCP/Pydantic/게시 통제까지 실행한 것으로 보고하지 않는다.

## 7 남은 실제 연결 검증

- 인증 NEIS의 광주 학교 목록·기간별 일정 전체 페이지와 날짜 미지정 탐색.
- 유치원·어린이집의 승인 API 또는 실제 공식 파일 확보와 다섯 구 범위·코드 매핑 대조.
- 대학·캠퍼스·대학원 정규화와 최신 광주 대상 목록 대조.
- 선택 검색 제공자의 기관 식별 → URL 발견 → 공식 원문 접근과 잘못된 기관/과거 자료 거절.
- 선택 P0 모델과 HTML/텍스트 PDF 경로의 실제 앱 연결, 정상 결과 게시와 오류 차단의 동시 확인.
- 원문 변경·재확인 실패·무효 근거의 재계산, 수기 보호, 취소 후 재시작과 재개.
- 배포 대상 PC의 설치·처리시간과 실제 대표 기관별 날짜/시간 현재 사용 허용 건수.

공개 일정 비율·시작 시각 공개율·광주 전체 수집률·운영 반복 안정성은 아직 알려져 있지 않다. 이 문서와 독립 probe로 그 수치를 대신하지 않는다. 실행 집계와 원본 출처의 상세 내용은 `07_execution_basis.md`에 둔다.
