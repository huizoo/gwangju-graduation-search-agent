# 실제 실행 검증 기록

통합 명세 4.0, 기준일: 2026-10-20. 기존 독립 실험을 이번 설계의 근거로 보존하는 사실 부록이다. **이 실험은 4.0 앱 구현이나 전체 Agent의 정확성을 검증한 결과가 아니다.** 이번 수정에서는 기존 로컬 증거만 읽고 대조했으며 새 수집·유료 호출·원문 외부 전송은 하지 않았다. 설계의 규칙과 완료 기준은 다른 문서가 담당하고, 여기서는 실제 수행·관측·미검증 범위를 기록한다.

## 1 목적과 증거 위치

사용자가 요청한 검증은 Supervisor와 자동 분기를 만들기 전에 검색, 원문 읽기, API 조회, 문서 해석을 개별 프로그램으로 실행해 보는 것이었다. 기존 프로젝트 코드를 변경하지 않고 별도 `graduation_probe` 폴더에 검증 코드를 만들었다. 사람이 고른 URL과 사례를 개별 명령으로 실행했으며 자동 계획·분기·재계획은 구현하지 않았다. 실패한 수집을 목업 일정으로 대체하지 않았다.

작업공간의 증거 루트는 `<PROBE_ROOT>`다. 아래 경로는 이 루트를 기준으로 한다. 이 부록은 실행 기록을 요약한 문서이며 원시 파일 전문을 포함하지 않는다. 휴대용 집계 복사본은 `evidence/probe-summary.json`, 실행 설명은 `evidence/probe-README.md`다. 취득 당시 둘 다 원본과 byte 단위로 대조해 복사했으며, Git 배포 사본의 README는 개인 경로만 비식별화했다. 취득 원본 경로의 자리표시자와 SHA-256은 `evidence/manifest.json`에 남겼다. 요청 소스의 정확한 발췌는 `evidence/probe-search-request-source.txt`다. 전체 원문·첨부파일·실험 코드는 이 ZIP에 모두 포함되지 않으며 원래 probe 루트에 있다.

기존 3.0 인계안의 `evidence/probe-findings.json`도 변경하지 않고 보존했다. 이 파일은 당시 AI가 사용자 요약으로 재구성한 자료이며 원시 실행 결과가 아니다. 그 안의 `provider_identified=false`와 `raw_artifacts_inspected_here=false`는 당시 작성 환경을 설명한다. 이번 원본 대조에서 확인한 검색 제공자·요청 모델은 원본 집계와 요청 코드에 근거해 아래와 같이 보정한다. 서로 다른 시점과 자료 종류를 하나의 실험 결과로 합산하지 않는다.

## 2 실행 환경과 실제 사용 도구

| 작업 | 실제 사용 경로 | 이 결과가 입증하지 않는 것 |
| --- | --- | --- |
| 검색 | OpenAI Responses API와 `web_search`는 집계/응답, 요청 모델 `gpt-4.1-mini`는 원본 `probe.py`의 `run_search` 호출부로 확인 | 설계에 예정된 Tavily의 연결·검색 성능 |
| HTTP 수집 | Python `httpx`, HTML 본문 추출·응답 저장 | 모든 사이트의 접근 가능성 |
| 브라우저 읽기 | 설치된 `browser-verification` 전용 런타임과 도우미 | 다른 PC의 범용 브라우저 Adapter 완성 |
| PDF | 파일 시그니처 확인, `pdftotext -layout`; 관련 페이지는 `pdftoppm` 렌더링 후 시각 확인 | 스캔 PDF OCR, 모든 표 구조의 자동 해석 |
| HWP | `olefile`로 HWP5의 `PrvText` 미리보기 읽기 | 전체 BodyText, HWPX, 암호화·이미지 중심 HWP 지원 |
| 공식 API | NEIS `schoolInfo`, `SchoolSchedule`의 인증키 없는 샘플 | 인증키를 사용한 전체 페이징·광주 전체 조회 |
| 텍스트 해석 | 로컬 Ollama `qwen3:8b` | 외부 모델이나 다른 모델의 추출 성능 |
| 이미지 해석 | 로컬 Ollama `qwen3.5:2b` | 범용 이미지·OCR 처리의 신뢰성 |

처음 제한된 실행 환경에서 발생한 연결 실패는 `artifacts/sandbox/`에 따로 보존했다. 아래 본문은 외부 접근을 허용한 실제 요청 결과를 기준으로 한다. 환경의 네트워크 제한과 개별 사이트의 TLS·연결 오류를 같은 실패로 집계하지 않는다.

문서·이미지 원문을 OpenAI API로 전송하는 추출 작업은 자동 승인 검토에서 구체적인 원문 전송 승인이 없다는 이유로 거절됐다. 해당 추출 요청은 실행하지 않았고, 문서·이미지 해석은 로컬 모델로 수행했다. 기관명과 검색어를 보내는 웹 검색 호출은 별도로 실행됐다. 이것은 이번 실행 환경에서의 제약이며 OpenAI의 문서 해석 능력이 불가능하다는 증거가 아니다.

## 3 작업별 실행 결과

| 작업과 집계 단위 | 실제 결과 | 해석 범위 |
| --- | --- | --- |
| HTTP 대상 URL 10개 | 기대 자료 확보 6, 본문 불일치 1, 연결 실패 3 | HTML 4개와 PDF 2개가 확보된 수치. PDF 다운로드는 10개에 이미 포함 |
| 브라우저 페이지 2개 | 통합 학사일정 목록, 어린이집 공시 DOM 읽기 성공 | 모든 기관의 상세 공지까지 탐색한 결과는 아님 |
| 텍스트 PDF 2개 | 텍스트 추출 성공 | 정확한 일정 추출 성공과 별개 |
| 첨부파일 3개 | HWP 1개·이미지 2개 다운로드 성공 | HTTP 10개 결과와 합산해 기관 수로 사용하지 않음 |
| HWP 미리보기 1개 | 810자 추출, 행사 일시와 하교 시각 확인 | 전체 문서 파서 아님 |
| NEIS | 학교 코드 조회, 기간의 샘플 5행, 알려진 날짜의 행사 2행 반환 | 날짜를 처음부터 발견하거나 기간 전체를 수집한 결과 아님 |
| 일반 검색 2건 | API 호출 성공. 대상 기관 불일치 1건, 출처 미확보 1건 | 정확한 공식 일정 확보 성공으로 계산하지 않음 |
| 도메인 필터 검색 2건 | HTTP 400 `invalid_request_error` | 현재 요청 설정의 실패. 정확한 원인 해결은 미수행 |
| 초기 모델 사례 8건 | 모든 사례의 전체 검사 조건에서 오류 잔존 | 일부 필드는 정확했으며 일반 정확도 측정이 아님 |
| 지침 보완 후 사례 4건 | 모든 사례의 전체 검사 조건에서 오류 잔존 | 초기 사례 중 일부를 다시 실행한 것으로 신규 기관 4곳이 아님 |

**URL 10개는 기관 10곳이 아니다.** 같은 기관의 HTML·PDF·구/신 도메인을 각각 요청했고, 모델 테스트도 같은 기관의 서로 다른 표현과 첨부파일을 포함한다. 이 실험은 표본 기관 10곳의 공식 목록 식별부터 검색·최종 일정 게시까지 수행한 종단 검증이 아니다.

HTTP 본문 불일치는 조선대의 특정 공지가 HTTP 200으로 게시물 부재 안내를 반환한 사례다. 연결 실패는 통합 학사일정 상세 페이지의 구·신 도메인에서 각각 발생한 TLS handshake 오류 2건과 어린이집 공시 HTTP 요청의 연결 초기화 1건이다. 요청 실패로 졸업식 미개최나 정보 미공개를 판정하지 않았다.

브라우저에서는 통합 학사일정의 현재 목록 주소 `https://cic.jge.go.kr/xschedule/index.php`와 어린이집 공시 화면을 읽었다. HTTP로 실패한 상세 일정의 내용을 모두 확보했다는 의미는 아니다. 브라우저 정리 기록은 `FINISHED`, 잔여 프로세스 0, `exact-close`다.

## 4 원문을 사람이 확인한 비교 기준

다음 표는 저장한 원문을 읽고 모델 출력과 비교하기 위해 정한 기준이다. **모델이 모두 정확하게 추출한 결과도, 기관에 연락해 실제 개최를 확정받은 일정표도 아니다.** 과거 자료는 형식 읽기와 목표 기간 배제 여부를 확인하기 위해 포함했다.

| 사례 ID와 원문 | 원문에서 확인한 내용 | 비교 기준의 한계 |
| --- | --- | --- |
| `jnu_calendar`: 전남대 학사일정, `https://biology.jnu.ac.kr/biology/13161/subview.do` | 목표 행사 날짜 `2027-02-26`; 해당 자료에서 시작 시간 미확인 | 여러 연도가 들어 있는 달력. 시간은 추정하지 않음 |
| `chosun_calendar_pdf`: 조선대 2026학년도 학사력 | `2027-02-25`, `2026학년도 전기 학위수여식`; 시간 미기재 | PDF 1페이지의 연·월 배치를 시각 확인 |
| `gist_notice`: GIST 공지, 문서 번호 `220364` | `2026-02-20 14:00`, 2025학년도 행사 | 이번 모델 입력의 목표 겨울 기간에 해당하지 않는 과거 행사 |
| `gwangju_notice`, `gwangju_poster`, `gwangju_rental_table`: 광주대 대학원 공지 `wr_id=396`와 연결 이미지 | 졸업 행사 `2026-02-20 10:30` | 같은 공지의 본문·포스터·표를 별도 사례로 사용 |
| `yongdu_hwp`: 용두중 공지 `number=7385`, 첨부 `file_num=10677` | `2024학년도` 안내, 행사 `2025-01-09 10:30`, 하교 예정 `11:30` | HWP 미리보기 기준. 행사와 하교 시각 구분 필요 |

| NEIS 첨단고등학교 | `AY=2026`, `AA_YMD=20270120`, `EVENT_NM=졸업식`, 3학년 대상 | 조회 조건에 날짜를 이미 넣었음. 해당 레코드 내용은 null이고 시작 시간은 확보하지 못함 |

전체 원문 URL, 최종 리디렉션 URL과 해시는 `cases.json`, `fetch_results.json`, `attachment_results.json`과 개별 결과에 남아 있다. 광주대 표에는 행사 시간 외에 `2026-02-09 09:00`부터 시작하는 학위복 대여 일정도 있어 시간 역할을 혼동할 수 있다.

## 5 검색·API의 구체적인 관측

전남대의 2027년 2월 학위수여식을 묻는 일반 검색에서 전북대의 `moak.chonbuk.ac.kr` 출처와 답변이 반환됐다. 최초 `search_results_initial.json`의 `passed`는 검색 호출과 인용 반환만 뜻했다. 이후 기관 불일치를 발견해 `search_results.json`에서는 `wrong_source`로 정정하고 최초 기록을 보존했다. 어린이집 검색은 인용 출처가 없어서 `no_source`로 기록했다. 출처 미확보가 실제 자료 부재를 뜻하지는 않는다.

검색 응답의 실제 `action.query`에는 이스케이프된 Unicode 문자열이 기록돼 있다. 원인은 이 실험에서 규명하지 않았다. 관측한 오답은 그대로 보존하되, 이 두 호출만으로 검색 서비스 전체의 성능이나 정상 한국어 검색 입력 처리 품질을 일반화하지 않는다. 도메인 일치 검사도 기관·행사·날짜·시간이 맞다는 증명은 아니다.

NEIS는 `schoolInfo`에서 첨단고등학교의 교육청 코드 `F10`, 학교 코드 `7140377`을 얻었다. `SchoolSchedule`에 `20261201`~`20270228`을 넣은 샘플은 처음 5행의 시험 일정 등을 반환했다. 이후 이미 알고 있던 `AA_YMD=20270120`으로 요청해 졸업식과 1·2학년 종업식 2행을 받았다. 인증키 없는 5행 샘플이므로 이를 기간 전체 조회나 졸업식 날짜 자동 발견으로 보고하지 않는다.

## 6 구조화 추출과 실제 오류

초기 텍스트 6건·이미지 2건에 JSON Schema 형태를 지정해 날짜, 날짜 정밀도, 행사 시작 시간, 행사 종류, 목표 학년도 해당 여부, 인용 근거를 받았다. 판정용 기대값은 모델에게 주지 않았다. 출력값을 사람이 정한 비교 기준과 대조하고 텍스트 인용문의 원문 존재 여부와 일부 필드 간 일관성을 검사했다.

이후 초기 사례 중 4건에 날짜 형식·목표 기간·시간 미기재·인용 지침을 더 명확히 하여 추가 실행했다. 목표 기간 안내는 2026년 12월~2027년 2월이었다. 이것은 개정 설계의 초기 시즌 설정 전체를 검증한 실행이 아니다.

| 사례 | 초기 실행에서 관측한 오류 | 지침 보완 후 관측 |
| --- | --- | --- |
| 전남대 달력 | 목표 `2027-02-26` 대신 `2026-02-26` 선택, 미기재 시간 `00:00` 생성 | 날짜는 맞았으나 미기재 시간 `10:00` 생성. 인용문 자체는 원문에 존재 |
| 조선대 PDF | 날짜 `2027-02-25`는 맞았으나 시간 `00:00` 생성 | 재시험하지 않음 |
| GIST 공지 | 시간 `14:00`은 맞았으나 날짜를 `2026-02`로 축소 | 날짜를 월까지만 출력, 시간 누락, 목표 기간 해당 여부 오류 |
| 용두중 HWP | 시간 `10:30`은 맞았으나 날짜 `2025-01-09`를 `2025-01`로 축소 | 재시험하지 않음 |
| 광주대 본문 | 시간 `10:30`은 맞았으나 날짜를 월까지만 출력 | 재시험하지 않음 |
| 광주대 포스터 | 날짜·시간 값은 맞았으나 날짜 정밀도를 `month`로 출력 | 재시험하지 않음 |
| 광주대 표 이미지 | 행사 대신 대여 일정 `2026-02-09 09:00` 선택 | 행사 날짜·시간은 맞았으나 행사 종류 분류 오류 |
| 어린이집 PDF | 떨어진 문구를 합쳐 원문에 그대로 존재하지 않는 인용문 생성 | 월·연도·시간 미확인은 맞았으나 합성 인용 오류 잔존 |

초기 8건과 추가 4건은 모두 각 사례에 적용한 전체 검사에서 실패했다. 검사 항목과 지침이 일부 달라 정식 전후 성능 비교가 아니며, 12개의 독립 기관 표본도 아니다. 일부 날짜·시간 필드는 맞았으므로 이를 일반 모델 정확도 0%라고 표현하지 않는다. 모델·문서·실행 횟수가 제한돼 있어 다른 모델의 성능을 추정할 근거도 아니다.

현재 텍스트 인용 검사는 공백을 정규화하여 원문에 문구가 존재하는지 확인한다. 인용문이 추출값을 의미상 뒷받침하는지까지 증명하지 않는다. 이미지 인용은 자동 원문 대조가 아닌 사람이 시각 확인해야 하는 대상으로 기록됐다. 일부 초기 기대값에는 검사가 없는 필드도 있으므로 `failures`가 모든 오류를 망라한다고 보장하지 않는다. `summary.json`의 `date_time_checks`는 일부 날짜·시간 필드만 따로 집계한 값이며 전체 검사 통과율과 같지 않다.

## 7 이번 실행에서 검증하지 않은 것

- 광주 전체 기관의 공식 목록 확보, 전체 기관 수와 누락률, 유형별 공개 일정 비율.
- 날짜를 모르는 상태에서 학교 식별·검색·원문 확인·최종 게시까지 자동으로 완료하는 전체 흐름.
- Tavily, 유치원알리미·어린이집 목록 API, 대학 목록 API의 실제 호출과 전체 페이징.
- 실제 앱의 MCP 호출, Pydantic 사용자 정의 검증기, Supervisor·LangGraph 자동 분기·재계획.
- HWP 전체 본문·HWPX·암호화 문서·스캔 PDF OCR 및 모든 JS 상세 페이지 처리.
- 모델 의미 오류를 차단하는 게시 판정기와 검증된 필드만 내보내는 최종 출력 경로.
- 변경·취소 공지 재확인, 출처 충돌 해결, 수기 보호, 큐 재개와 운영 환경의 반복 안정성.
- 전체 수집의 소요 시간·비용, 타 운영체제 배포, 외부 모델을 통한 문서 해석 성능.

## 8 개정 설계에서의 사용 원칙

이 증거는 실제 자료의 여러 수집·읽기 경로가 실행된다는 점과, 형식이 맞는 모델 출력에도 의미 오류가 남는다는 점을 뒷받침한다. MCP나 Pydantic의 사실 정확성 보장, 오류 없는 완전 위임, 전체 기관 수집 가능성을 입증하지 않는다.

다음 검증은 앱에 실제 연결한 도구와 선택한 모델로 수행해야 한다. 알려지지 않은 날짜의 발견, 기관 식별, 원문 접근, 필드별 의미 검증, 잘못된 후보의 게시 차단, 올바른 후보의 정상 출력 여부를 분리해서 기록한다. 이 문장이 해당 기능의 구현 완료를 뜻하지는 않는다.


## 9 통합 설계에 반영하는 결정과 근거

아래는 관측 결과로부터 선택한 설계다. 실험에서 이미 구현하거나 차단했다고 주장하는 항목이 아니다. 계약·API·DB·예시와 실행 가능한 명세 검사는 통합 4.0의 별도 산출물이며 실제 기관 종단 검증과 구분한다.

| 통합 결정 | 관측 또는 사용자 요구 | 남는 비용과 한계 |
| --- | --- | --- |
| 정형 매핑 우선, 필요한 경우에만 LLM 후보 추출 | NEIS는 구조화된 날짜 행을 제공했고 모델은 형식 지정 상태에서도 의미 오류를 냈음 | 실제 자료원별 등록 규칙과 정상·오류 사례 시험이 필요함 |
| 일·월·미확인 날짜를 구분하고 월 값을 후보·수기·조회에 유지 | 어린이집은 월 계획만 있고 일부 모델은 정확한 일자를 월로 축소함 | 월 계획은 일 단위 확인율·판매 준비 목록에 포함하지 않음 |
| 하나의 Publication으로 일반 조회·현재 사용·관리 기록을 구분 | 사용자는 과거 확인 기록을 보존하면서 부정확한 값을 판매 판단에 쓰지 않기를 원함 | 재확인 실패 시 맞는 일정도 현재 사용에서는 일시 보류될 수 있음 |
| 필드별 원문·규칙 버전·관측 연결을 확인하고 출력값을 직접 생성 | 미기재 시간 생성·합성 인용·대여/행사 시각 혼동을 관측함 | 인용 존재만으로 의미를 입증할 수 없고 공식 원문의 오기도 남음 |
| 유효한 대체 근거와 사람의 재확인을 고려해 재확인 실패를 판단 | 접속 실패 3건은 일정 오류의 증거가 아님 | 보조 검색 실패나 중복 근거 한 건의 실패를 기관 전체 차단으로 확대하지 않음 |
| 날짜와 시간의 독립 검증, 시간은 동일 행사·일자에 연결 | 원문에 날짜만 있는 사례와 행사 외 시각이 함께 있는 사례가 있음 | 시간만 보류하면 날짜는 제공하되 판매 준비 조건과는 구분함 |
| 실제 확인시점 없는 수기 기록은 관리에 보존하고 현재 사용에서 제외 | 실제 확인시점과 입력시점의 구분이 필요하다는 합의 | 사람이 확인한 내용의 진실까지 코드가 증명하지 못함 |
| P0는 NEIS·HTML·텍스트 PDF, 브라우저/HWP는 병목에 따라 추가 | 기존 브라우저 DOM 2건·HWP 미리보기 1건은 개별 경로 가능성만 보임 | 부분 읽기·형식 미지원·Windows 통합은 별도 검증이 필요함 |
| 모델 백엔드 하나를 실제 연결한 뒤 선택, 외부 원문 전송은 기본 비허용 | 로컬 호출은 실행됐지만 오류가 남았고 외부 추출은 실행하지 않음 | 현재 자료로 모델 성능 우열·사용자 PC 처리시간을 정할 수 없음 |

다음 실제 검증은 날짜를 모르는 기관의 발견, 관측된 의미 오류의 차단, 올바른 일정의 정상 제공을 함께 확인한다. 전부 보류한 결과는 사용자의 수집 목표 달성으로 보지 않는다. 확인된 날짜 건수·동일 일자의 시작 시간 건수·수기 확인 필요 건수를 구분하고, 과거 기록·월 값·미검증 후보는 현재 확인율에 합산하지 않는다. 실제 모집단 전체의 오류율 0%나 완전 수집을 보장하지 않는다.

사용자가 별도 준비하는 PPT·발표 증빙은 이 인계안의 개발 완료 조건이 아니다. 기존 모델의 개선 전후 실측 비교도 새 아이디어 구현의 필수 조건으로 추가하지 않는다.
