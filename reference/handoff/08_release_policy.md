# 게시 정책과 실행 참조

계약·게시 정책 버전은 4.0입니다. 게시 권한의 기준은 contracts/README.md와 동일한 단일 `calculate_publication`이며 이 문서는 적용 순서와 검증 범위를 설명합니다. 독립된 두 번째 판정기를 만들지 않습니다.

1. 서버가 원문 버전, 관측 상태, 규칙 ID/버전과 필드의 연결을 확인합니다. 모델의 확신이나 두 모델의 동의는 독립 증거가 아닙니다.
2. 실제 확인시점이 있는 유효한 수기 확인 또는 근거가 검증된 자동 평가에서 값을 생성합니다. 수기 지정 보호·현재 충돌 fingerprint·재확인 근거를 검사합니다.
3. 행사 식별/취소의 미해결 사유는 전체에 적용합니다. 시각·장소의 개별 문제는 해당 필드에 적용하고 날짜를 불필요하게 숨기지 않습니다.
4. 일 단위 날짜와 시간의 bound_date를 확인합니다. 월 단위나 다른 날짜의 시간을 최종 일정으로 결합하지 않습니다.
5. 일반 조회에는 유효한 검증 이력과 실제 확인시점을 표시합니다. 근거가 틀렸다고 판명된 값은 여기에도 정상 확인값으로 남기지 않습니다.
6. 필요한 근거 경로의 실제 재확인 실패로 현재 사용이 불가하면 해당 필드를 제한합니다. 일반 조회의 과거 값/원문은 보존하고 경고를 붙입니다. 대체 공식 근거나 독립적인 사람의 재확인이 있으면 재평가합니다.
7. 현재 허용된 날짜·시작 시각이 모두 있는 항목만 판매 준비 목록에 넣습니다. API/화면/내보내기/집계가 같은 판정 결과와 snapshot을 사용합니다.

`checks/publication_policy.py`와 `checks/check_publication.py`는 이 정책을 실행하여 확인하는 **참조 사양**입니다. 제공된 가상 문장과 원문 연결의 양성·음성 시험을 수행하며 실제 사이트 전체에서의 의미 판독이나 앱 구현 완료를 입증하지 않습니다. live 활성 규칙 목록은 비어 있고, 실제 문서 형식의 추출·정규화·인용 검증을 구현하고 대표 기관 종단 시험을 통과해야 활성화할 수 있습니다.

네 회귀 사례는 미해결 행사 식별, 미해결 취소 주의, 확인시점 없는 수기 충돌 해결, 확인값과 다른 최종 장소입니다. 정상 날짜·시간, 날짜만 있는 일정, 정당한 수기 재확인은 통과해야 하며 전부 보류하는 구현도 실패입니다. 재확인 실패의 이력 보존/현재 제한, 시간만 충돌, 날짜 변경 뒤 과거 시간 재사용, 월 정보, 해시·규칙 버전·기관 불일치도 검사합니다.

이 검사는 문서·계약·참조 판정의 정합성 확인입니다. 실제 앱에서는 날짜를 모르는 기관 탐색 → 관측 오류 차단 → 정상 게시를 추가 검증하고, 날짜/시간 게시 수와 사람 확인 필요 수를 구분해 기록해야 합니다. 오류 0%나 모든 기관의 공개 일정 확보를 보장하지 않습니다.
