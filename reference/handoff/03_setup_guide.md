# 개발 전 준비 안내 4.0

이 인계물은 명세·계약·참조 검사이며 실제 앱은 별도 구현 대상이다. 개발과 자료 정규화는 Codex가 맡고, 사용자는 이미 가진 기록과 실제 사용할 PC 정보, 필요한 경우 발급 계정을 준비한다. 실제 비밀값을 채팅·문서·인계 ZIP에 넣지 않는다.

## 1 개발에 필요한 연결

| 준비물 | 용도와 범위 |
| --- | --- |
| 선택 모델 연결 | 초기값 Ollama는 앱/서비스와 텍스트 모델이 필요. OpenAI 선택은 자신의 API 키가 필요하며 Ollama 실행은 불필요. 모델별 처리시간·추출 정확성은 확인 필요 |
| NEIS 인증키 | 학교 목록·학사일정의 전체 기간과 페이징 실연동. 인증키 없는 샘플/알려진 날짜 조회로 대체하지 않음 |
| 선택 SearchProvider의 키 | 새로운 공식 공지 URL 발견. 기본 후보 Tavily의 실제 요청은 별도 연결 검증 필요 |
| 공식 목록 파일 또는 유형별 API 계정 | 유치원·어린이집·대학 등을 포함한 전체 대상 목록. API가 늦으면 출처와 기준일이 있는 공식 파일 적재 |

조사·검증 역할은 같은 모델을 사용할 수 있다. 의미 검증이 필요한 경로의 모델 설정이 없으면 그 자동 단계는 보류하되 저장 조회·수기 입력은 사용할 수 있어야 한다. 등록된 정형 매핑으로 충분한 레코드를 해석하는 데 모델 호출을 강제하지 않는다.

검색 키가 없어도 NEIS와 이미 알고 있는 공식 URL을 읽을 수 있다. 새로운 공지를 자율적으로 찾는 범위는 제한되므로 연결 상태와 완료 보고에서 구분한다. 모델과 검색 백엔드는 서로 다른 설정이며 한쪽 성공으로 다른 쪽을 검증했다고 하지 않는다.

위 링크는 준비할 자료원의 안내 경로이며 모든 API가 현재 앱에 연결돼 있다는 뜻은 아니다. endpoint·코드·인증·이용 조건은 실제 구현 시 확인한다. 서비스별 키를 서로 바꿔 쓰지 않는다. 미확보 유형은 목록 확보 필요로 남기며 일부 수동 등록 기관으로 완료 처리하지 않는다. 신청 목적은 공개 기관정보·졸업식 일정의 실제 활용 범위로 적고 학생 명단이나 비공개 학부모 채널을 요청하지 않는다.

## 3 기존 기록과 실제 PC

어머니의 기존 메모/엑셀은 원래 형식대로 보존한다. 표본 기록에 기관명·구/주소·학년도·날짜 정밀도·시간·확인 방법과 알면 실제 확인시점을 준비하면 도움이 된다. 문서로 확인했다면 원문 링크나 실제 확인한 파일을 함께 남겨 해당 버전에 연결한다. 종이·오프라인 확인도 가능하며 일반 신규 확인의 메모는 선택이다. 연도나 확인일을 모르면 비워 둔다. 오래된 메모와 전화·문서 직접 확인을 구분한다.

P0는 단건 수기 입력과 공식 기관 목록 가져오기를 제공한다. 일정 엑셀 전체 자동 해석·사진 메모 판독·표 붙여 넣기는 확장이다. 기존 기록 전체를 미리 새 양식으로 옮길 필요는 없다. 확인일 미상 메모는 보관하지만 정상 확인값이나 판매 준비 목록으로 자동 승격하지 않는다.

실제 사용할 PC의 운영체제·버전·64비트 여부·인터넷 가능 여부를 확인한다. 개발 Mac의 모델 호출은 Windows 설치·처리시간·배포 검증이 아니다. P0는 개발자가 단일 명령 런처를 제공하고 Windows 실행파일은 실제 환경 검증을 거치는 P2 범위다.

## 4 설정과 비밀값

현재 기본 선택은 **Ollama**다. `.env.example`은 전환에 대비한 OpenAI 키 칸을 포함해 다음 여섯 항목만 담는다. 실제 앱을 개발할 작업 폴더의 `.env`에 필요한 값을 넣고, `.env.example`에는 비밀값을 넣지 않는다. 이미 작성한 `.env`의 값을 보존한다.

| `.env` 항목 | 어디서 확인하고 입력하는가 |
| --- | --- |
| `LLM_BACKEND=ollama` | 앱 내부 모델 선택. `ollama` 또는 `openai`로 변경. 개발을 수행할 Codex의 모델 설정과는 별개 |
| `OLLAMA_BASE_URL=http://127.0.0.1:11434` | 같은 PC에서 실행하는 Ollama의 로컬 서비스 주소. 기본 주소로 실행하면 유지하며 API 키가 아님 |
| `OLLAMA_TEXT_MODEL=qwen3:8b` | `ollama list`로 설치된 정확한 모델 이름 확인. 예제 이름은 기존 재현 설정이며 설치·품질 검증 완료 또는 성능 추천을 뜻하지 않음 |
| `OPENAI_API_KEY=` | OpenAI를 선택할 때만 [API keys](https://platform.openai.com/api-keys)에서 발급한 키 입력. Ollama 사용 중에는 비워도 됨 |
| `NEIS_API_KEY=` | [나이스 개발자 가이드](https://open.neis.go.kr/portal/guide/apiGuidePage.do)의 인증키 신청 절차로 발급한 키 입력 |
| `TAVILY_API_KEY=` | [Tavily 대시보드](https://app.tavily.com/)에서 확인한 API 키 입력. 키 발급은 실제 앱의 Tavily 연결 검증 완료와 별개 |

Ollama를 선택하면 서비스 실행과 텍스트 모델 설치가 필요하다. Mac도 Ollama 앱을 실행해 백그라운드 서비스가 동작하면 터미널에서 `ollama serve`를 별도로 실행할 필요가 없다. GUI 없이 CLI로 실행할 때 `ollama serve`를 사용하며 같은 포트에 두 서버를 동시에 띄우지 않는다. 로그인 시 자동 실행은 macOS의 로그인 항목·백그라운드 허용 설정을 확인한다. Ollama 환경변수를 바꾼 경우에는 Ollama 앱을 종료 후 다시 실행한다. [Ollama 공식 FAQ](https://docs.ollama.com/faq)와 [Mac 설치 안내](https://docs.ollama.com/macos)를 참고한다. 개발자가 실제 연결, 구조화 출력과 정상·오류 사례를 검증하며 인계 파일 준비만으로 설치·다운로드·실행 완료를 주장하지 않는다.

기본값은 `config/defaults.json`, 선택적으로 덮어쓸 수 있는 전체 이름/타입/경로는 `config/env-map.json`, 관리 방법은 `config/README.md`를 기준으로 한다. 실행 한도·동시 처리·재시도·문서 크기·선택 기능·tracing 등 비밀이 아닌 기본값은 `.env`에 반복하지 않는다. env-map에 이름이 있다는 이유로 사용자의 필수 입력이 되는 것은 아니다. 기존 시즌의 학년도·기간·선택 상태는 SQLite와 앱 화면에서 관리하며 config의 시즌 기본값은 새 시즌 생성에만 적용한다.

최종 `LLM_BACKEND`는 비어 있지 않은 프로세스 환경변수, `.env`, defaults 순서로 결정한다. 이후 `defaults.json → 선택한 llm_profiles의 전송 설정 → 비어 있지 않은 .env 값 → 비어 있지 않은 프로세스 환경변수` 순서로 결합한다. 생략·빈 값은 직전 값을 유지한다. 명시한 false·0은 보존하고 env-map 타입과 실제 앱의 허용 범위를 검사한다. 실행 가능한 사양 참조는 `checks/configuration_reference.py`와 `checks/check_configuration.py`이며 실제 앱 로더·SDK 연결은 개발 단계에서 구현·검증한다. 설정을 바꾸면 앱을 재시작하고 새 작업에 적용한다. 기존 작업은 비밀이 아닌 수집·모델 설정의 `source_config_hash`가 같은 경우에만 재개한다. 다르면 409 `settings_changed`로 접속 전에 중단하며 이전 설정을 복원하거나 기록을 유지한 채 새 작업을 만든다. 키 회전만으로는 불일치가 생기지 않는다.

비밀 키는 환경변수/메모리에서만 사용한다. `.env`는 Git에서 제외하고 defaults·일반 JSON 설정·작업 snapshot·로그·화면·HTML·인계 ZIP에 복사하지 않는다. 특정 키가 없으면 해당 서비스의 사용 제한만 표시하고 저장 기록 조회·수기 입력과 독립적으로 가능한 기능을 막지 않는다. live 실패를 demo나 다른 외부 서비스로 조용히 바꾸지 않는다.

OpenAI로 전환할 때는 키 칸을 채운 뒤 `LLM_BACKEND=openai`로 바꾸면 된다. OpenAI 기본 모델은 [gpt-6.1-sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)이며 비밀이 아닌 `config/defaults.json`에서 관리한다. `OPENAI_FAST_MODEL`과 `OPENAI_QUALITY_MODEL`은 선택적 재정의이고 quality가 비어 있으면 fast 모델을 재사용한다. 선택한 백엔드만 초기화·검사하므로 OpenAI 선택에는 Ollama 실행·설치를 요구하지 않는다. 키를 넣기만 해서는 백엔드가 바뀌지 않으며 키 누락·장애 시 다른 백엔드로 자동 전환하지 않는다. 현재 자료만으로 모델 간 정확성 우위를 정하지 않는다.

`LLM_BACKEND=openai` 선택은 공개 문서의 필요한 텍스트 구간을 OpenAI로 보내는 선택이다. ollama/fake profile은 외부 전송이 꺼져 있고 openai profile만 공개 문서 텍스트를 허용한다. 이미지와 사적 수기 메모는 이 선택에 포함하지 않는다. 선택적으로 `ALLOW_EXTERNAL_DOCUMENT_TEXT=false`를 추가하면 OpenAI profile보다 우선해 해당 전송을 차단한다. `ALLOW_EXTERNAL_IMAGES`는 모든 profile의 기본값이 false이며 별도 허용·지원 검증 없이는 전송하지 않는다. 공개 검색어와 원문 payload를 구분하고 실행환경의 별도 승인/거절을 따른다. 별도 승인 관리 UI는 P0 요구가 아니다. 이는 구현할 설정 계약이며 이 문서 수정 과정에서 유료 호출이나 원문 외부 전송을 실행했다는 뜻이 아니다.

유치원·어린이집 API 키는 해당 Adapter를 실제로 선택·연결할 때만 준비한다. 출처·기준일이 있는 공식 파일을 가져오는 경로도 가능하다. LangSmith/tracing과 이미지 후보는 초기 필수 준비가 아니며 기본 비활성이다. 조정이 필요하면 env-map의 해당 항목만 `.env` 또는 프로세스 환경변수에 추가한다. 명시적인 fixture 시연은 `APP_MODE=demo`, `LLM_BACKEND=fake`, `SEARCH_PROVIDER=none`을 함께 사용하고 외부 요청을 금지하며 live와 DB/캐시/HTML을 분리한다.

과거 검색 probe의 제공자는 동봉된 원본 실행 집계에서 OpenAI Responses의 web_search로 확인된다. 이를 Tavily 연결 검증으로 계산하지 않는다. 도메인 필터 400의 원인은 미해결이며 기본 비활성 상태에서 실제 요청을 고쳐 재검증한다. 외부 모델의 원문 텍스트·이미지 해석은 실행되지 않아 성능 결과가 없다.

지역코드는 사용자가 외워 입력하지 않는다. 개발자가 공식 코드표/응답과 실제 주소로 profile을 검증한다. 모델의 실제 입력/출력 상한과 구조화 응답 지원도 연결 검사에 포함한다. provider가 지원하는 Schema가 제한돼도 전체 서버 계약을 완화하지 않는다.

## 5 실행 근거와 규칙 활성화

동봉 실행 근거 문서와 `evidence/`의 원본 집계 복사본·hash를 먼저 확인한다. 이 집계는 개별 실행 결과이며 전체 Agent의 자율 수집·게시 성공이 아니다. 실제 fixture를 만들 때 저장 원문·최초 모델 출력·정정 출력과 출처 위치/hash를 연결하고 가상 fixture와 실원문 재현을 구분한다.

규칙의 초기 운영 허용 목록은 비어 있다. 정상 날짜+시간, 날짜만 확인과 실제 관측 오류를 같은 등록 규칙에서 시험한 뒤 ID·버전을 활성화한다. 모델 호출이나 JSON 출력 성공만으로 활성화하지 않는다. 참조 검사의 fixture 규칙을 운영에 그대로 켜지 않는다.

P0 reader는 HTML·텍스트 PDF다. 브라우저/HWP 앱 연결과 배포는 필수 설치 전제가 아니다. 필요한 병목이 확인되면 해당 도구를 추가하고 읽기 범위·지원 한계를 확인한다. 도구가 없어도 기존 기록 조회를 막지 않는다.

## 6 개발 완료 시 받을 결과

실제 앱 도구로 날짜를 모르는 기관을 조사한 경로, 정상/오류 원문의 필드별 판정과 최종 출력, 자료원별 전체 목록 확보 범위·기준일을 받는다. 일반 조회의 과거 확인값과 현재 판매 허용이 구분되는지, 수기 확인시점·확인한 문서 버전·최신 충돌 재확인·취소 재시작이 보존되는지도 확인한다. 같은 내용의 원문을 재확인한 것만으로 수기 충돌 해결이 취소되지 않아야 한다. 기존 2.0·2.1·3.0 DB가 있으면 먼저 백업하고 기록을 보존한 채 4.0 조건을 검증한다.

보고는 기능 완료·자료원 실연동·전체 목록 확보를 나눈다. 실행 명령, 필요한 설정, 데이터·백업·HTML 위치, 계약/반례/실제 기관 시험 결과와 남은 한계를 포함한다. PPT/발표 준비나 Before/After 비교를 개발 완료 조건에 추가하지 않는다. SQLite를 쓰므로 별도 DB 서비스·클라우드·벡터 DB·임베딩 키는 사전 준비물이 아니다.
