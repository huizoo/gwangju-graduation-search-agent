# 광주 졸업식 일정 도우미

광주 지역 **초등학교·중학교·고등학교·대학교·전문대학**의 졸업식 날짜와 인원수를 조사하고, 필요한 학교의 시간을 더 찾아보는 로컬 프로그램입니다. 직접 확인한 내용도 문장으로 기록할 수 있습니다. 자료·근거·수정 이력은 SQLite에 남고, 저장한 HTML은 프로그램 없이 조회하고 인쇄할 수 있습니다.

## 실행과 사용

이 폴더의 **[start.command](start.command)를 더블 클릭**합니다. 터미널에서는 다음과 같이 실행합니다.

```sh
cd $HOME/workspace/week15/gwangju-graduation-search-agent
.venv/bin/python -m app
```

기존 앱이 실행 중이면 **저장하고 프로그램 종료**를 누른 뒤 다시 실행해 새 코드를 적용하세요. 기존 기록은 보존하며 저장 구조를 바꾸기 전에 자동으로 백업합니다.

1. 조사 시즌을 선택합니다. `2026학년도 겨울`의 조사 기간은 2026-12-01부터 2027-03-31까지입니다.
2. **일정찾기**를 누릅니다. 등록한 전체 대상 학교의 날짜와 인원수를 조사합니다. 아래 표에서 선택한 구·검색어·날짜나 페이지는 조사 범위를 줄이지 않습니다.
3. 시간이 비어 있는 학교는 **시간 찾기**를 누릅니다. 날짜를 확인한 해당 행사를 조사합니다. 기본 일정찾기 중 같은 원문에 본식 시각이 명시돼 있으면 함께 기록합니다.
4. 직접 전화하거나 안내문을 확인했다면 **직접 확인한 내용**에 적습니다.

   > 건국초 졸업식은 1월 6일 오전 10시래. 방금 학교에 전화해서 확인했어. 기록해줘.

   위 문장은 사용 예시이며 실제 건국초 시작 시각을 뜻하지 않습니다. 기존 행사를 보완하고 애매한 기관·날짜·시간·확인시점이나 충돌하는 부분만 짧게 묻습니다.
5. **HTML 열기**로 확인하거나 **HTML 저장**으로 `graduation-schedule-2026.html`을 저장합니다. **인쇄**는 현재 검색·구·날짜 조건에 맞는 전체 행을 인쇄합니다.
6. **저장하고 프로그램 종료**를 누릅니다. 기록은 남고 진행 중인 조사는 멈춥니다.

## 일정표 읽기

표는 **날짜 | 학교명 | 시간 | 졸업인원수 | 장소** 순서입니다. 학교명은 확인된 공식 홈페이지에 연결합니다. 장소는 확인한 학교·캠퍼스 주소이며 행사장 추정값이 아닙니다.

학교명 검색·구·날짜를 함께 적용하고 화면에서 20행씩 볼 수 있습니다. 여러 날 열리는 실제 졸업식은 각 날짜로 검색됩니다. 같은 날짜는 같은 차분한 배경색으로 표시하며, 인쇄에서는 날짜 사이의 선으로 구분합니다. 인쇄물에는 표만 나오고 조사 버튼이 있던 시간 칸은 비워집니다.

확인하지 못했거나 현재 사용이 보류된 값은 **공란**입니다. 시간이나 인원이 없더라도 정상 날짜는 남습니다. 확인된 취소·미실시는 짧게 표시하고 과거 날짜·시간을 정상 일정으로 내보내지 않습니다.

초등학교는 해당 학년도 6학년, 중학교·고등학교는 3학년 재학생 수를 인원으로 사용할 수 있습니다. 대학은 학교·캠퍼스의 대표 졸업식에 대응하는 공개 졸업인원만 사용합니다. 인원의 종류·기준 학년도·출처는 내부에 보관합니다.

저장 HTML의 검색·필터·페이지 이동·인쇄는 파일 안에서 작동하므로 앱이나 인터넷이 필요하지 않습니다. 학교 홈페이지를 열 때에는 인터넷이 필요합니다. HTML은 저장 당시의 사본이므로 새 정보가 필요하면 앱에서 다시 조사하고 저장하세요.

## 학교 목록과 확인한 결과

**기록 관리 → 학교 목록 새로 가져오기**에서 NEIS와 공식 대학 목록을 조회합니다. 이번 실제 조회에서는 대상 학교 **339개**를 확보했습니다. 명부 확보와 각 학교 일정 확인은 별개입니다.

현재 시즌 건국초등학교는 날짜를 미리 주지 않은 실제 조회에서 **2027-01-06, 졸업인원수 188명**을 확인했습니다. 인원은 2026학년도 6학년 재학생 수입니다. 정형 자료로 날짜와 인원이 충족돼 모델 호출과 별도 시간 검색 없이 완료했습니다. 시작 시각은 공란입니다.

광주대학교는 실제 선택 모델이 공식 학사일정에서 **2027-02-19**를 제안하고 공통 검증을 거쳐 표에 게시했습니다. 해당 작업은 예산 한도에서 멈췄고 시간·인원은 공란입니다. 이 결과와 건국초 자료를 담은 [저장 HTML](output/graduation-schedule-2026.html)을 바로 열어볼 수 있습니다.

실제 자료원·선택 모델·브라우저의 완료 여부와 한계는 [최신 검증 기록](docs/RESEARCH_V2_VALIDATION.md)에 구분해 남깁니다. 확인한 사례를 모든 학교의 최신 일정 확보로 확대하지 않습니다.

## 기록과 설정

| 위치 | 내용 |
| --- | --- |
| `data/live/graduation.sqlite3` | 학교·행사·원문·수기·인원·경로·조사 실행 이력 |
| `data/live/backups/` | 수동 및 저장 구조·규칙 변경 전 자동 백업 |
| `data/live/exports/` | 앱에서 생성한 HTML 버전 |
| `.env` | 기존 백엔드 선택·키·PC 연결 정보. Git과 출력에서 제외 |
| `config/defaults.json` | 비밀이 아닌 기본 설정 |
| `runtime/improvements-20261021/` | 실제 사용자 데이터와 분리한 검증 자료 |
| `reference/handoff/` | 보존한 인계 원본 |

기존 `LLM_BACKEND`에 따라 Ollama 또는 OpenAI만 초기화합니다. 선택한 백엔드에 문제가 생겨도 다른 백엔드로 바꾸지 않습니다. 기존 설정 병합·사적 정보 전송 금지·작업 재개 시 설정 보호 규칙을 유지합니다. 직접 기록하는 문장은 로컬에서 처리합니다.

새 조사는 준비한 NEIS·검색 연결과 선택 모델을 사용합니다. 학교알리미 API 키는 기존 `.env`의 `SCHOOLINFO_API_KEY`로 받습니다. 학교알리미 조회에 필요한 소재 구 코드(`sggCode`)는 공식 학교 식별·주소와 대조하여 코드로 처리하므로 어머니가 입력하지 않습니다. 키 없는 공식 공개 표 경로도 지원하며, 접근이나 식별 검사가 실패하면 인원을 추정하지 않습니다. 저장 조회·직접 기록·HTML 저장에는 외부 키가 필요하지 않습니다.
