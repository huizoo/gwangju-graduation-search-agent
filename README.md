# 광주 졸업식 일정 도우미

광주 지역 **초등학교·중학교·고등학교·대학교·전문대학**의 졸업식 날짜와 인원수를 조사하고, 필요한 학교의 시간을 더 찾아보는 로컬 프로그램입니다. 직접 확인한 내용도 문장으로 기록할 수 있습니다. 자료·근거·수정 이력은 SQLite에 남고, 저장한 HTML은 프로그램 없이 조회하고 인쇄할 수 있습니다.

## 실행과 사용

이 폴더의 **[start.command](start.command)를 더블 클릭**합니다. 터미널에서는 다음과 같이 실행합니다.

```sh
cd $HOME/workspace/week15/gwangju-graduation-search-agent
.venv/bin/python -m app
```

기존 앱이 실행 중이면 기존 화면의 **저장하고 프로그램 종료**를 누른 뒤 다시 실행해 새 코드를 적용하세요. 새 화면에서는 버튼 이름이 **프로그램 종료**입니다. 기존 기록은 보존하며 저장 구조를 바꾸기 전에 자동으로 백업합니다.

1. 처음 찾을 기간이면 **새 시즌 조사**를 누르고 졸업식의 시작 날짜·끝 날짜를 선택한 뒤 **조사 시작**을 누릅니다. 양끝 날짜를 포함하며 6개월 미만이어야 합니다. 학년도는 입력하지 않습니다.
2. 이미 저장한 기간을 다시 확인하려면 **저장된 시즌**에서 기간을 골라 **이 시즌 다시 조사**를 누릅니다. 같은 시즌 ID·기간·수기 기록을 유지합니다. 다른 기간은 새 시즌으로 조사합니다.
3. 기본 조사는 등록한 전체 대상 학교의 날짜와 인원수를 찾습니다. 아래 표의 구·검색어·하루 날짜·페이지는 조사 범위를 줄이지 않습니다.
4. 시간이 비어 있는 학교는 **시간 찾기**를 누릅니다. 해당 시간 칸에서 진행 상태를 볼 수 있고, 새로고침 후에도 복원됩니다. 다른 학교의 비활성 버튼은 그 학교를 조사 중이라는 뜻이 아닙니다. 기본 조사 중 같은 원문에 실제 본식 시각이 명시돼 있으면 함께 기록합니다.
5. 직접 전화하거나 안내문을 확인했다면 **직접 확인한 내용**에 적습니다.

   > 건국초 졸업식은 1월 6일 오전 10시래. 방금 학교에 전화해서 확인했어. 기록해줘.

   위 문장은 사용 예시이며 실제 건국초 시작 시각을 뜻하지 않습니다. 기존 행사를 보완하고 애매한 기관·날짜·시간·확인시점이나 충돌하는 부분만 짧게 묻습니다.
6. 기록은 자동 저장되며, 앱이 실행 중이면 기간별 HTML도 자동 갱신됩니다. **일정표 열기**로 확인하거나 **파일 내려받기**로 다른 곳에 복사합니다. **인쇄**는 현재 검색·구·하루 날짜 조건에 맞는 전체 행을 인쇄합니다.
7. **프로그램 종료**를 누릅니다. 진행 중인 조사를 멈추고 HTML 갱신을 마무리합니다. 아직 입력창에만 있는 문장은 먼저 기록하거나 지워 주세요. 브라우저 창만 닫으면 프로그램은 계속 실행될 수 있습니다.

선택한 기간은 찾을 졸업식의 **실제 행사 날짜 범위**입니다. 프로그램 실행 기간이나 표의 하루 날짜 필터와 다릅니다. 과거·현재·미래 기간에 같은 조사 기능을 사용합니다. 기간이 연도·학년도 경계를 지나면 필요한 자료 학년도를 나눠 조회합니다. 대학의 학년도와 전기·후기는 날짜만으로 정하지 않고 원문에서 확인합니다.

## 일정표 읽기

표는 **날짜 | 학교명 | 시간 | 졸업인원수 | 장소** 순서입니다. 학교명은 확인된 공식 홈페이지에 연결합니다. 장소는 확인한 학교·캠퍼스 주소이며 행사장 추정값이 아닙니다.

학교명 검색·구·하루 날짜를 함께 적용하고 화면에서 20행씩 볼 수 있습니다. 여러 날 열리는 실제 졸업식은 시즌 범위에 포함된 각 날짜로 검색됩니다. 필터 결과에서 같은 날짜는 같은 색이고 바로 다음 날짜 그룹은 다른 색입니다. 같은 날짜가 다음 페이지로 이어져도 색을 유지합니다. 필터를 바꾸면 색이 다시 배정될 수 있습니다. 인쇄물에는 표만 나오며 날짜 사이 경계선을 유지하고, 조사 버튼·진행·결과 안내가 있던 시간 칸은 비웁니다.

시간 조사 중에는 해당 칸에 작은 진행 표시와 `찾는 중…`이 나옵니다. 중간 시간이 저장되더라도 실제 작업이 끝날 때까지 진행 표시를 유지합니다. 완료 후 확인 시간을 표시하며, 미발견·자료 접근 실패·오류·중지·취소도 같은 위치에서 구분해 알립니다. `이번 조사에서 시간을 찾지 못했어요.`는 시간이 미공개라는 단정이 아닙니다.

확인하지 못했거나 현재 사용이 보류된 값은 **공란**입니다. 시간이나 인원이 없더라도 정상 날짜는 남습니다. 확인된 취소·미실시는 짧게 표시하고 과거 날짜·시간을 정상 일정으로 내보내지 않습니다.

초등학교는 해당 학년도 6학년, 중학교·고등학교는 3학년 재학생 수를 인원으로 사용할 수 있습니다. 대학은 학교·캠퍼스의 대표 졸업식에 대응하는 공개 졸업인원만 사용합니다. 인원의 종류·기준 학년도·출처는 내부에 보관합니다.

저장 HTML의 검색·필터·페이지 이동·인쇄는 파일 안에서 작동하므로 앱이나 인터넷이 필요하지 않습니다. 학교 홈페이지를 열 때에는 인터넷이 필요합니다. `data/live/exports/graduation-schedule-시작일-종료일.html`은 앱이 자동 갱신하는 최신 파일입니다. 이미 다른 곳으로 내려받은 복사본과 열어 둔 HTML 화면은 저절로 바뀌지 않습니다. 새 파일을 다시 열거나 내려받아 주세요. 파일 저장에 실패하면 DB 기록과 마지막 정상 HTML을 보존하고 앱에 알립니다.

## 학교 목록과 확인한 결과

접힌 **관리 → 학교 목록 갱신**에서 NEIS와 공식 대학 목록을 조회합니다. 명부 확보와 각 학교 일정 확인은 별개입니다. **기록 백업**은 전체 DB의 보관용 복사본이며 HTML 일정표와 다릅니다.

시즌의 전체 조사 전·진행·일부 미완료·종료 여부는 앱에서 짧게 안내합니다. 전체 조사를 마쳐도 모든 학교의 날짜·시간·인원이 확인됐다는 뜻은 아닙니다.

이전에 사용자 DB에 들어간 GIST 단건 공지 검증은 개발 검증 기록으로 분리합니다. 원문·추출값·검증 이력과 변경 전 DB는 별도 보관하고, 검증용 시즌과 일정값은 일반 조회·HTML·조사 실적에서 제외합니다. 실제 과거 기간을 조사하려면 **새 시즌 조사**로 해당 기간을 선택하세요. GIST도 일반 조사에서 다시 확인한 근거가 있어야 일정값이 표시됩니다.

이번 기간 기반 조사 검증에서는 첨단고등학교의 **2026-01-21 졸업식과 355명**을 실제 API와 작업 관리자를 통해 확인했습니다. 인원은 행사에 대응하는 **2025학년도 3학년 재학생 수**이며 모델 호출은 0회였습니다. [과거 기간의 실제 수집 예시](output/graduation-schedule-2025-12-01-2026-03-15.html)는 사용자 DB와 분리한 검증 자료로 만들었습니다.

같은 최종 앱으로 미래 기간도 조사해 건국초등학교의 **2027-01-06·2026학년도 6학년 188명**을 다시 확인했습니다. 두 학교 모두 학년도를 강제하지 않은 NEIS 날짜 조회와 확인된 행사 학년도 인원 조회를 사용했고, 각각 HTTP 3회로 완료했습니다. 시작 시각은 공란입니다.

이전 2.0 검증에서는 공식 대상 **339개**를 확보했습니다. 건국초등학교는 날짜를 미리 주지 않은 실제 조회에서 **2027-01-06·188명**을 확인했으며, 인원은 2026학년도 6학년 재학생 수입니다. 정형 자료로 날짜·인원이 충족돼 모델 호출 없이 완료했고 시작 시각은 공란이었습니다. 광주대학교는 실제 선택 모델이 공식 학사일정에서 **2027-02-19**를 제안하고 공통 검증을 거쳐 게시했습니다. 해당 작업은 예산 한도에서 멈췄고 시간·인원은 공란이었습니다.

건국초의 이번 확인값과 광주대의 이전 확인값은 [기존 기간의 새 형식 HTML](output/graduation-schedule-2026-12-01-2027-03-31.html)에서 볼 수 있습니다. 원래의 [2.0 저장 HTML](output/graduation-schedule-2026.html)과 [이전 검증 기록](docs/RESEARCH_V2_VALIDATION.md)도 보존합니다. 전체 명부를 새로 전수 조사한 성과로 계산하지 않습니다.

실제 API·선택 모델 검증과 합성 자료를 사용한 브라우저 검증의 범위는 [최신 검증 기록](docs/PERIOD_V3_VALIDATION.md)에 나눠 남깁니다. 확인한 사례를 모든 학교의 최신 일정 확보로 확대하지 않습니다.

## 기록과 설정

| 위치 | 내용 |
| --- | --- |
| `data/live/graduation.sqlite3` | 학교·행사·원문·수기·인원·경로·조사 실행 이력 |
| `data/live/backups/` | 수동 및 저장 구조·규칙 변경 전 자동 백업 |
| `data/live/archives/` | 운영 자료에서 분리한 개발 검증 원본과 보관 정보 |
| `data/live/exports/` | 자동 갱신하는 기간별 HTML과 이전 불변 버전 |
| `.env` | 기존 백엔드 선택·키·PC 연결 정보. Git과 출력에서 제외 |
| `config/defaults.json` | 비밀이 아닌 기본 설정 |
| `runtime/` | 사용자 데이터와 분리한 실제 수집·합성 UI 검사 및 실패 기록 |
| `reference/handoff/` | 보존한 인계 원본 |

기존 `LLM_BACKEND`에 따라 Ollama 또는 OpenAI만 초기화합니다. 선택한 백엔드에 문제가 생겨도 다른 백엔드로 바꾸지 않습니다. 기존 설정 병합·사적 정보 전송 금지·작업 재개 시 설정 보호 규칙을 유지합니다. 직접 기록하는 문장은 로컬에서 처리합니다.

새 조사는 준비한 NEIS·검색 연결과 선택 모델을 사용합니다. 학교알리미 API 키는 기존 `.env`의 `SCHOOLINFO_API_KEY`로 받습니다. 학교알리미 조회에 필요한 소재 구 코드(`sggCode`)는 공식 학교 식별·주소와 대조하여 코드로 처리하므로 어머니가 입력하지 않습니다. 키 없는 공식 공개 표 경로도 지원하며, 접근이나 식별 검사가 실패하면 인원을 추정하지 않습니다. 저장 조회·직접 기록·HTML 저장에는 외부 키가 필요하지 않습니다.
