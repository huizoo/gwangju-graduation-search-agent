# 검사 실행

자동 검사는 오류가 다시 생기는 것을 막기 위한 개발 도구다. 프로그램 실행에는 필요하지 않다. 실행 결과·스크린샷·수집 원문은 `runtime/`에만 남기고 Git에 추가하지 않는다.

## 계약·저장·정확성 회귀검사

```sh
.venv/bin/python -m pytest -q
```

시즌 범위, 자료 학년도, 본식·부대 행사·다른 기관 구분, 취소, 날짜 충돌, 직접 기록, 중복 방지, 중단·재개, 백업·초기화, 설정·비밀 보호를 검사한다. 고정 예제와 모의 외부 응답은 실제 사이트의 현재 사실을 입증하지 않는다.

`test_agent_recovery.py`는 실제 조사 루프·MCP 경계에서 중복 요청 미전송, 미방문 공식 경로 복구, 제한된 형식 수정과 예산·취소 전파를 검사한다. `test_model_decision_recovery.py`는 상태별 생성 선택지, 모델 응답의 단계별 오류 진단과 민감 문자열 배제를 검사한다. 형식 검사를 통과한 응답도 사실 검증은 별도로 통과해야 하며, 오류를 덜 기록하거나 일찍 종료한 것만으로 수집 성공을 판단하지 않는다. 실제 검증에서는 이전 실패 사례와 정상 API 경로를 새 DB에서 다시 조사하고 최종 허용 값·종료 사유·복구 이력·HTML·재시작 보존을 함께 확인한다.

## 일시 장애와 선택적 추적

```sh
.venv/bin/python -m pytest tests/test_retry.py tests/test_tracing.py -q
```

`test_retry.py`는 `429`·`500`·`502`·`503`·`504`와 일시 연결 오류의 제한 재시도, 영구 오류·잘못된 모델 JSON의 비재시도, `Retry-After`, 취소·시간 예산을 검사한다. 실제 계량기를 사용해 재시도마다 호출 예산을 예약하고 응답 유실 시 토큰 예약을 보수적으로 유지하는지도 확인한다.

`test_budget_diagnostics.py`는 24,000·48,000 예산에서 실제 모델 전송 직전의 예약 허용·거절, 기관·구간·전체 한도 상세, 사용량 미상 예약분, 재시작·재개 시 이력과 고정 한도 보존을 임시 DB로 검사한다. 기본값을 늘려도 기존 경계 검사를 약화하지 않는다. 실제 수집 검증은 새 DB에서 학교 식별 정보만 준비하고 같은 기간·모델·나머지 한도로 재실행한다. 토큰 한도 통과, 다른 한도 종료, 모델·자료원 오류, 실제 일정 확보를 각각 기록한다.

`test_tracing.py`는 기본 꺼짐·키 누락 시 SDK와 외부 요청이 없는지, 작업 → 학교 → 모델 결정·도구의 부모 관계가 유지되는지 검사한다. 원문·프롬프트·수기·키·환경·예외 원문 배제, 마지막 모델 응답에서 확인한 토큰만 표시하는 경계, 256개 대기열의 포화 처리, SDK 실패 격리와 종료 대기 상한도 검사한다. 실제 SDK 직렬화는 모의 전송기로 확인하며 계정·실제 네트워크는 사용하지 않는다. 이 검사를 위해 실제 `.env`에 추적 설정을 추가할 필요는 없다.

## 실제 브라우저

적용되는 `browser-verification` 지침의 전용 런타임을 먼저 확인한다. 사용자 브라우저나 프로필을 사용하지 않는다.

```sh
.venv/bin/python scripts/verify_browser.py all
```

`periods`, `checkpoint`, `feedback`, `first_use`, `download`를 개별 실행할 수도 있다. 각 검사는 새 DB와 자신이 소유한 서버만 사용하며, 브라우저 종료·잔여 프로세스 없음까지 확인한 뒤 다음 검사로 넘어간다.

합성 학교는 페이지 경계·부분 정보·진행 상태·실패를 재현하기 위한 입력이다. 외부 API나 모델의 정확성 성과로 계산하지 않는다. 파일 URL 열기가 전용 도구에서 차단되면 그 제한을 기록하고, 같은 다운로드 바이트의 오프라인 동작 검사를 따로 보고한다.

## 실행·저장 수명

```sh
.venv/bin/python scripts/verify_lifecycle.py
```

실제 `start.command`를 새 검사 폴더로 실행해 중복 실행, 포트 충돌, 직접 기록, 백업, 재시작 보존, 정상 종료를 확인한다. 사용자 브라우저와 외부 조사는 실행하지 않는다.

## 실제 자료와 데이터 보호

실제 API·선택 모델 검증은 별도 `runtime/` DB에서 수행한다. 학교 식별 이외의 날짜·시간·인원 정답을 미리 넣지 않는다. 정상 일정 확보, 미발견, 접속 실패, 모델 실패를 구분하고 DB 저장·HTML·재시작 결과를 함께 확인한다. 한 학교 성공을 전체 학교 조사 성공으로 확대하지 않는다.

`scripts/check_historical_publication.py`는 고정된 과거 공지의 읽기·검증 경로만 확인한다. 새로운 일정 탐색 성과로 계산하지 않는다.

```sh
python3 scripts/check_publication_safety.py --tracked
python3 scripts/check_publication_safety.py --history HEAD
```

공개 검사는 실제 index·커밋 이력과 비밀·검토 자료 목록을 확인한다. 탐지되지 않았다는 사실만으로 임의의 수집 자료 공개를 승인하지 않는다.
